# ADR - 012 앱 로컬 서버 · 라이브 스토어 · AI 활동 패널

## 상태

채택 (2026-09-29, 4단계 구현). 계약은 orchestrator 가 고정한 것을 그대로 구현했다. 수신부: `euta-app/src/main/local-server.ts` · `live-store.ts` · `live-reducer.ts` · `hook-store.ts`.

## 맥락

- MCP 서버(ADR-008 §5)는 `EUTA_APP_EVENTS_URL` 로 core 이벤트 배치를 POST 한다 — at-most-once, 재시도 없음, 2초 타임아웃, 한 서버 안에서는 순서 보장, 여러 runId 가 섞일 수 있음.
- euta 플러그인(ADR-009)은 Claude Code hook 입력 JSON 을 `EUTA_APP_URL/hooks/claude` 로 보낸다. `SessionEnd` 외에는 **async** hook 이라 도착 순서가 뒤바뀔 수 있고, 전달기 마감은 약 1초다. 전달 이벤트: SessionStart · UserPromptSubmit · PreToolUse · PostToolUse · PostToolUseFailure · Notification · SubagentStart · SubagentStop · Stop · StopFailure · SessionEnd.
- Claude Code 문서(hooks, HTTP 응답 처리): non-2xx·타임아웃·연결 실패는 **비차단 오류**, 2xx + 빈 본문은 결정 없음, 2xx + JSON 본문만 결정으로 해석된다.
- 앱에서 직접 시작한 실행도 같은 화면에 그려야 한다(ARCH: 앱 라이브 뷰는 이벤트 버스를 구독).

## 결정

### 1. 로컬 서버

- `node:http`, **`127.0.0.1` · 포트 0(임의)** 바인딩, 앱 실행마다 `randomBytes(32)` hex 토큰. 토큰은 pty env(ADR-011)로만 나가고 렌더러에는 보내지 않는다.
- 요청 검사 순서와 응답:

| 검사 | 실패 시 |
|---|---|
| 원격 주소가 loopback(`127.0.0.1` · `::1` · `::ffff:127.0.0.1`) | 403 |
| `Host` 헤더가 `127.0.0.1` · `localhost` · `[::1]` (DNS rebinding 방지) | 403 |
| `Authorization: Bearer <token>` (timingSafeEqual) | 401 |
| 경로 `/events` · `/hooks/claude` | 404 |
| 메서드 `POST` | 405 (`Allow: POST`) |
| `Content-Type: application/json` | 415 |
| 본문 ≤ 4 MiB (Content-Length 선검사 + 스트림 누적) | 413 |
| JSON 파싱 / 형태 | 400 |

- **CORS 헤더를 보내지 않는다**(OPTIONS 도 405). 요청 타임아웃 10초, 헤더 50개 제한.
- `POST /events`: 봉투 `{ source: string, protocol: 1, pid?, sentAt?, events: [] }` 검증 → **먼저 204** → 스토어 반영.
- `POST /hooks/claude`: 객체이면 **먼저 204(빈 본문)** → 기록. 어떤 경우에도 JSON 본문을 돌려주지 않으므로 앱이 Claude 의 결정에 영향을 줄 수 없다. 4 MiB 초과 413 도 Claude 에게는 비차단 오류일 뿐이다.

### 2. 라이브 스토어 (실행 뷰)

- 순수 리듀서 `applyEvent(state, event)` 가 이벤트를 **seq 기준 멱등**으로 적용해 `RunView`(상태 · 요약 · 스텝 목록 · 최신 스크린샷 · 지표 · expect · 콘솔 오류 · 네트워크 실패 · `eventCount`/`maxSeq`)를 만든다. 세 출처가 같은 리듀서를 쓴다: 앱 실행(`EventBus.onAny({replay:true})`), MCP 전달(`/events`), `steps.jsonl` 재생(History Open · 복구).
- **순서 뒤바뀜·중복**: seq 중복은 무시. 스텝은 `stepId` 로 upsert 하고 `index` 로 정렬. `step.finished` 가 먼저 와도 뒤늦은 `step.started` 가 상태를 `running` 으로 되돌리지 않는다. 최신 스크린샷은 가장 큰 seq 의 `artifact.saved(screenshot)`. `run.finished` 때 아직 `running` 인 스텝은 `skipped` 로 닫는다.
- **누락 복구**: MCP 실행에서 `seen < maxSeq`(빈 seq)이거나 `run.finished` 를 받으면 500ms 디바운스 후 `runDir/steps.jsonl`(같은 스키마, ADR-008) 을 읽어 병합한다. 복구되면 화면에 "recovered from steps.jsonl".
- **runDir 신뢰**: 앱 실행은 core `RunHandle.runDir` 만 쓴다. 전달된 이벤트의 `run.started.runDir` 은 **절대 경로이고 폴더 이름이 runId 와 같을 때만** 받는다(엔진 배치 `<runsRoot>/<runId>`). 그 밖이면 runDir 없음(스크린샷·복구 안 함).
- **아티팩트 읽기**: 렌더러는 `artifactImage(runId, relPath)` 만 부를 수 있다. main 은 스토어의 runDir 기준으로 `realpath` 한 파일이 runDir 안(심볼릭 링크 탈출 차단)이고 확장자가 png/jpg/jpeg/webp, 15 MiB 이하일 때만 data URL 로 돌려준다.
- 상한: 실행 100개(끝난 것부터 제거), 목록류 300개. 렌더러 푸시는 100ms 스로틀.
- secrets: core 와 MCP SecretGuard 가 이미 마스킹한 이벤트만 들어온다. 앱은 값을 추가로 다루지 않는다. Playwright 오류의 ANSI 색 코드는 제거해 표시한다.

### 3. AI 활동 스토어 (hook)

- `session_id` 별 세션(최대 20) · 세션당 항목 500개. 저장하지 않는다(메모리만).
- **짝짓기**: PreToolUse/PostToolUse/PostToolUseFailure(와 PermissionRequest/Denied)는 `session_id + tool_use_id` 로 한 항목에 합친다(먼저 온 쪽이 만들고, 늦은 Pre 는 끝난 호출을 다시 열지 않음). SubagentStart/SubagentStop 은 `session_id + agent_id`. 서브에이전트 안의 도구 호출은 `agent_id` 를 표시.
- 분류: prompt(UserPromptSubmit) · tool · subagent · stop(Stop, StopFailure=failed) · notification · session(SessionStart/End → 세션 ended 표시) · other.
- **euta 도구 강조**: `mcp__euta__*`(`claude mcp add euta`) 와 `mcp__plugin_<plugin>_euta__*`(플러그인 설치 시 `mcp__plugin_euta_euta__*`).
- 크기: 요약 300자, 입력·응답 상세 4,000자, 그 안의 긴 문자열(스크린샷 base64 등)은 200자로 줄인다.

## 이유

- 먼저 204 를 보내고 처리하면 hook 전달기(1초)·MCP 전달기(2초) 마감을 넘지 않고, 앱 처리 오류가 Claude 나 MCP 서버로 번지지 않는다.
- seq 멱등 리듀서 하나로 세 출처를 합치면 "라이브 = 재생 = 복구" 가 같은 코드라 결과가 어긋나지 않는다(ADR-007 의 "steps.jsonl 로 같은 타임라인 재생" 원칙).
- 토큰 + loopback 주소 + Host 검사 + CORS 무응답의 겹 방어로, 브라우저 페이지(Playwright 가 연 대상 사이트 포함)가 localhost 엔드포인트를 두드려도 통과하지 못한다.
- runDir 이름 검사는 토큰을 가진 프로세스라도 앱이 임의 폴더의 이미지를 읽게 만들 수 없게 하는 값싼 장치다.

## 고려한 대안

| 대안 | 제외 이유 |
|---|---|
| WebSocket/SSE 로 MCP 서버와 양방향 | ADR-008 이 단방향 POST 로 고정. 앱이 서버를 몰라도 붙을 수 있어 단순 |
| 413 대신 초과 본문을 버리고 204 | 문서상 non-2xx 도 비차단이라 차이가 없고, 한도 초과를 숨기지 않는 편이 진단에 낫다 |
| 렌더러에 원시 이벤트를 보내고 렌더러에서 리듀스 | 복구(파일 읽기)가 main 에 있어야 하므로 리듀서를 main 에 두고 뷰만 보냄 |
| hook 항목을 도착 순서대로 따로 표시 | async hook 에서 Post 가 Pre 보다 먼저 오면 짝이 안 맞아 보임 |
| hook 기록을 디스크에 저장 | 프롬프트·도구 입력에 민감 정보가 있을 수 있고 1차 범위는 실시간 표시 |

## 결과

- 테스트(vitest): 401(토큰 없음·오답) · 204 + 빈 본문 · CORS 헤더 없음 · 비 loopback 원격 주소 403(연결 소켓의 remoteAddress 를 바꿔 실제 서버 경로로 확인) · Host 403 · 405/415/400/404 · 413(Content-Length·chunked) · 이벤트 반영 · 순서 뒤바뀜·중복 · steps.jsonl 복구 · 잘못된 이벤트/runDir 거부 · hook 분류·짝짓기(Post 먼저)·서브에이전트·StopFailure · euta 도구 패턴.
- E2E: 실제 앱에 잘못된 토큰 401, 합성 배치 두 개를 **역순**으로 POST → Live 에 MCP 실행 passed · 스텝 2개 · 스크린샷(runDir 에서 읽음), hook 6개 POST(각 204·빈 본문) → AI 패널에 프롬프트·euta 도구(done) 강조·도구 2개.
- 남은 일: MCP 서버가 앱과 다른 runs 폴더를 쓰면 History 에는 안 보인다(pty 로 띄운 CLI 는 `EUTA_RUNS_DIR` 로 맞춰짐, 수동 등록 시 안내문대로 `-e EUTA_RUNS_DIR`). Codex hook 은 미대응.
