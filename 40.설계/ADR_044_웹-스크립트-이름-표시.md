# ADR - 044 웹 스크립트 이름 표시

## 상태

채택 (2026-11-05). 코드: `euta-cloud` (`packages/server/src/services/script-name.ts`, `packages/web/src/project/script-name.tsx` 외).

## 맥락

- 웹은 스크립트를 어디서나 경로(파일명)로만 보여 주고, 예약 대상과 테스트 세트 항목은 파일명 드롭다운으로 골랐다. UI 그라운드룰("이름으로 보여 주고 이름으로 고르게")과 어긋났다.
- 사용자 결정(2026-11-05): 이름 굵게 + 경로 작게(웹 전체), 이름이 없으면 "(이름 없음)", 고르기 = 검색 + 체크, 새 스크립트 = 이름 입력 → 경로 자동 제안.
- 서버는 스크립트 이름을 따로 저장하지 않는다. 이름은 YAML 본문의 `name:` 에만 있다.

## 결정

### 이름 = 그때그때 본문에서 읽음 (저장 안 함)

- `scriptNameOf(source, contentHash)`: `@euta/core` `parseYaml` 로 `name` 을 읽어 앞뒤 공백을 자른다. 문자열이 아니거나, 비었거나, 파싱되지 않으면 `null`. **내용 해시를 키로 캐시**(최대 5,000개, 오래된 것부터 버림) — 이름은 본문으로 정해지므로 같은 해시는 한 번만 파싱한다.
- 응답에 `name: string | null` 을 더함: `ScriptDto`(현재 버전), `RunDto.script`(**그 실행이 고정한 버전**), `ScheduleDto.target.script`(현재 버전). 테스트 세트 리포트도 같은 함수를 쓴다. 같은 DTO 를 쓰는 MCP `list_schedules` · 실행 응답에도 같이 실린다. MCP `list_scripts` 는 응답을 따로 만들어 이름이 없다(이번 범위 밖).
- **DB 칸을 두지 않은 이유**: ① 실행은 고정한 버전의 이름을 보여야 한다 — `scripts.name` 칸은 최신 이름만 가져 옛 실행을 틀리게 보여 준다. ② 필요한 본문(현재 버전 행, 실행의 `script_source`)은 이미 각 조회에 있다. ③ 합쳐지지 않은 `feat/app-release` 가 마이그레이션 `0005` 를 쓰고 있어 번호가 부딪힌다. 기존 행 채우기(backfill)도 필요 없다.
- DSL 은 `name` 이 필수라, 이름 없는 스크립트는 검증 없이 저장되는 외부 편집(`origin: external`)으로만 생긴다.

### 웹

- 공용 `ScriptName`(이름 굵게 + 경로 고정폭 작게, `stacked` 면 경로를 아래 줄) — 스크립트 탭 목록, 실행 이력 · 현황(`RunTarget`), 실행 상세 제목, 예약 목록, 테스트 세트 항목 · 편집, 테스트 세트 리포트. 스크립트 탭 검색은 이름 · 경로 둘 다.
- 공용 `ScriptPicker`(검색 + 체크, 체크한 것이 체크 순서대로 위로 · 순번): 테스트 세트는 여러 개를 체크 → "체크한 N개 넣기"(체크 순서대로 끝에 붙음, 같은 스크립트를 다시 넣을 수 있음). 예약은 `single` — 하나만, 다른 것을 체크하면 바뀐다. **예약의 스크립트 대상은 더 이상 첫 스크립트를 미리 고르지 않는다**(체크해야 저장 가능). 예약의 테스트 세트 대상은 이름 드롭다운 그대로.
- 구성원 초대의 선택기(ADR-035)는 그 화면 안에 묶여 있어 재사용하지 않고, 같은 모양으로 스크립트용을 만들었다.

### 새 스크립트 경로 제안

- 앱 TC 변환의 파일 이름 규칙(`tcSlug`, ADR-039)과 같다: NFC · 소문자, 영문 소문자 · 숫자 · 한글만 남기고 나머지는 `-`, 앞뒤 `-` 제거, 40자 → `.yaml`. 비면 `new-script.yaml`, 같은 경로가 있으면 `-2`, `-3` … 스크립트가 앱과 클라우드를 오가므로 규칙을 하나로 맞췄다. 엔진 `slugify`(영문만 남김)는 한글 이름이면 기본값으로 떨어져 쓰지 않았다.
- 경로 칸은 사람이 고치기 전까지 이름을 따라간다. 입력한 이름은 `?new=1&name=…` 로 폼 편집기에 넘겨 템플릿의 `name` 이 된다.

## 대안

- **`scripts` 또는 `script_versions` 에 `name` 칸**: 위 ①~③ 때문에 택하지 않음. 목록이 수천 개로 커져 파싱이 문제가 되면 `script_versions.name`(버전별이라 ①을 지킴)으로 옮긴다.
- **목록에 이름 칸 · 경로 칸 따로**(앱 방식): 경로가 길면 표가 넓어진다. 사용자가 한 칸(이름 + 경로 작게)을 골랐다.

## 검증

- 서버 `test/script-name.test.ts`: 목록 이름 · 이름 없음 `null` · 실행은 고정 버전 이름 유지(저장 뒤에도) · 예약은 현재 이름 · 공백 자르기/문자열 아님/파싱 실패. MCP `list_schedules` 기대값 갱신. 서버 340개 통과.
- 웹 E2E `project-run.spec.ts`: 새 스크립트 이름 → 경로 `로그인-점검.yaml` 제안 · 상세 제목 = 입력한 이름, 목록 행에 이름(링크) + 경로, 예약 스크립트 대상 검색 + 체크(미리 고르지 않음), 테스트 세트 체크 순서 1 · 2 → 넣기. 캡처 `scripts-1-new` · `scripts-2-list` · `scripts-3-suite-pick`. 웹 E2E 22개 통과.
- 범위 밖: 앱 스크립트 목록(사용자가 웹만 선택), 작업 로그 문장(서버가 만든 기록 문장에 경로가 그대로 들어감).
