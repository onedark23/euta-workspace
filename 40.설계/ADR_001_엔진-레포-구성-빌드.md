# ADR - 001 엔진 레포 구성·빌드·연결 전략

## 상태

채택 (2026-09-29, 1단계 구현)

## 맥락

- `euta-engine` 한 레포에 GUI 없는 패키지(core · cli · 이후 mcp-server)를 묶기로 했다(PLAN).
- 같은 core 를 CLI · MCP 서버(2단계) · Electron 앱(4단계, 별도 레포)이 불러 쓴다. 앱·플러그인 레포가 엔진을 어떻게 참조할지 정해야 한다.
- 런타임은 TypeScript(Node). 로컬 Node 22.18 · pnpm 9.

## 결정

- **pnpm workspace** — `packages/core`(`@euta/core`), `packages/cli`(`@euta/cli`, bin `euta`). cli 는 `workspace:*` 로 core 를 참조한다.
- **ESM + TypeScript strict**(`module/moduleResolution: NodeNext`, `noUncheckedIndexedAccess`, `verbatimModuleSyntax`). 공통 설정은 `tsconfig.base.json`.
- **빌드는 `tsc` 만** 쓴다(번들러 없음). 패키지마다 `tsconfig.build.json → dist/`, 타입 선언 포함. core 빌드 뒤 `scripts/emit-schema.mjs` 가 `schema/euta-script.schema.json` 을 만든다(커밋 대상 — 편집기·AI 가 경로로 참조).
- **테스트는 vitest 4**(루트 설정 하나, `packages/*/test/**/*.test.ts`, `pool: forks`). `pnpm test` = `pnpm -r build && vitest run` — CLI 테스트가 빌드된 `dist` 를 실행하기 때문.
- **엔진 요구 Node ≥ 22.13** (`node:sqlite` 가 플래그 없이 동작하는 최소 버전, ADR-003).
- **다른 레포와의 연결**
  - 개발 중: `euta-app` · `euta-claude-plugin` 은 상대 경로 의존 `"@euta/core": "link:../euta-engine/packages/core"` 로 붙인다(엔진을 먼저 `pnpm -r build`). 소스가 아니라 `dist` 를 소비하므로 앱 쪽 빌드 설정이 엔진 내부 구조를 몰라도 된다.
  - 배포: 결정 보류 — 후보는 `pnpm pack` tarball 을 앱 빌드에 포함, 또는 사내 레지스트리 publish. 앱 배포 형태 ADR 에서 정한다.
  - Electron 패키징 주의: `playwright` 는 브라우저 바이너리·드라이버를 런타임에 찾으므로 번들하지 말고 external + asar unpack 대상으로 둔다(4단계에서 검증).

## 이유

- 항상 함께 바뀌는 core·cli·mcp 를 한 워크스페이스에 두면 버전 맞추기 부담이 없다.
- tsc 만 쓰면 `dist` 구조가 소스와 1:1 이라 디버깅·Electron 내장이 단순하다. 라이브러리이므로 번들 최적화 이득이 작다.
- `link:` 는 앱 레포에서 엔진 변경을 즉시 반영하면서도 레포를 분리해 둘 수 있다.

## 고려한 대안

| 대안 | 제외 이유 |
|---|---|
| tsup/esbuild 번들 | 라이브러리에 이득이 작고, playwright 같은 동적 로딩 의존을 external 처리해야 해 설정만 늘어남 |
| TS project references(`tsc -b`) | 패키지 2개에서는 이점이 작다. 패키지가 늘면 재검토 |
| npm/yarn workspaces | pnpm 이 설치돼 있고 엄격한 의존 격리로 유령 의존을 막음 |
| 앱이 엔진 소스를 git submodule 로 포함 | 레포 분리 이점 상실, 빌드 설정 중복 |
| jest | ESM·TS 설정 부담. vitest 는 설정 없이 TS·ESM 실행 |

## 결과

- 루트 명령: `pnpm build` · `pnpm typecheck` · `pnpm test` · `pnpm fixture`(예제용 픽스처 사이트).
- MCP 서버(2단계)는 `packages/mcp-server` 로 같은 워크스페이스에 추가한다.
- 앱·플러그인 레포는 엔진 빌드 산출물(`dist`)에 의존하므로, 엔진 공개 API 는 `packages/core/src/index.ts` 한 곳에서만 내보낸다.
