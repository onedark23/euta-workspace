# SPEC - 스크립트 작성 (시연 녹화 + 설명 → AI 정리)

> 상태: **구현 완료** (2026-10-02 — 엔진 `@euta/core` 녹화기·초안 변환, 앱 녹화 패널·녹화 저장소·`get_recording`. 구현 세부는 각 절의 "구현 세부" 와 [ADR-017](ADR_017_시연-녹화기-구현.md)). 실사용 확인 대기. 결정 정본은 [PLAN 결정 사항](../20.프로젝트관리/PLAN_end-user-테스트툴-종합계획.md#결정-사항) "스크립트 작성 방식".
> 선행: [SPEC_프로젝트-관리](SPEC_프로젝트-관리.md)(프로젝트·환경·vault·라이브러리) · [SPEC_test-script-dsl](SPEC_test-script-dsl.md)(출력 형식) · [ADR-015](ADR_015_앱-AI-채팅-Agent-SDK.md)(AI 채팅).

## 목적

- 사람이 YAML 을 직접 쓰지 않는다. **업무를 아는 사람이 실제 사이트를 시연하고 설명**하면, **AI 가 튼튼한 테스트 스크립트로 정리**하고 한 번 돌려 확인한다.
- 녹화만으로는 "무엇이 맞는 결과인가"(검증)가 빠지므로, **설명 메모**와 **체크포인트**로 사람이 기대 결과를 남긴다.
- 설명은 **텍스트만** 받는다(음성은 범위 밖 — 사용자 결정).

## 전체 흐름

```
① 시연 녹화    앱이 띄운 브라우저(headed)에서 사용자가 사이트를 평소처럼 사용
   + 설명 메모   녹화 패널에 텍스트로 "여기서 로그인", "합계가 1,200원이어야 함"
   + 체크포인트  [확인] 모드 → 화면 요소 클릭 = "이게 보여야 함 / 이 값이어야 함"
        ↓  (녹화 저장: 프로젝트 recordings/)
② 초안 변환    녹화 → 기계적 변환으로 YAML 초안 (AI 없이도 동작)
        ↓
③ AI 정리      초안 + 녹화 원본 + 메모 → AI 가 다듬은 스크립트를 라이브러리에 저장
        ↓
④ 자동 확인    AI 가 선택 환경으로 실행 → 실패하면 고쳐서 재실행(최대 3회) → 결과 보고
        ↓
⑤ 대화로 수정  "이 단계는 빼줘", "결제 실패 경우도 만들어줘"
```

- **보조 입구 — 말로 시키기**: 시연 없이 AI 채팅에 목표만 말하면 AI 가 탐색 세션(headed)으로 사이트를 직접 돌아보고 ③~⑤ 를 거친다(기존 탐색 도구 사용). 이번 단계는 시스템 지침과 화면 진입점만 정리한다.

## 녹화 (① — 엔진)

- 엔진 core 에 **녹화기** 를 둔다(앱·향후 CLI 공용). 프로젝트 환경의 주소·브라우저 기본값으로 headed 브라우저를 띄우고, 페이지에 수집 스크립트를 주입해 사용자 동작을 이벤트로 받는다.
- 수집 동작: 페이지 이동(goto·링크 이동 구분), 클릭·더블클릭, 입력(입력란 단위로 합침 — 키마다 남기지 않음), 선택(select), 체크/해제, 키 입력(Enter·Tab·Escape·단축키), 파일 업로드(파일 이름만), 다운로드(자동 감지), 스크롤은 의미 있을 때만(요소가 보이게 된 경우).
- **대상 기록**: 사람이 보는 기준을 우선한다 — role+이름 → 라벨 → placeholder → testId → 텍스트 → CSS. 후보 여러 개를 남기고, 녹화 시점에 페이지에서 **유일하게 잡히는 첫 후보**를 대표로 정한다.
- **비밀값**: `type=password` 입력란과 `autocomplete` 가 자격증명 성격인 입력란은 **페이지 안 수집 단계에서 값을 버리고** "secret 필요" 표시만 남긴다. 그 밖의 입력란도 패널에서 "민감" 으로 표시할 수 있다(표시하면 값 삭제). 민감 값은 녹화 파일·스크린샷·로그 어디에도 남지 않는다(스크린샷은 해당 입력란 가림).
- 단계별 작은 스크린샷(가림 적용)을 남긴다 — AI 와 사람이 흐름을 이해하는 용도.
- 범위: 한 탭(같은 탭 이동 포함). 팝업·새 탭·iframe 내부는 "녹화 안 됨" 으로 이벤트에 표시만 한다.

### 녹화 — 구현 세부 (2026-10-02, 구현하며 정함 · [ADR-017](ADR_017_시연-녹화기-구현.md))

- 대상 후보의 유일성은 **페이지 안에서** 센다(Playwright 기본 의미: 공백 정규화·대소문자 무시 부분 일치). 부분 일치로 여러 개지만 정확 일치로 하나면 `exact: true` 를 붙인다. CSS 경로(`#id` 또는 `tag:nth-of-type` 사슬)가 마지막 후보이며 항상 유일하다. 후보마다 녹화 시점 일치 개수를 남긴다.
- 입력란 단위 합치기: 같은 입력란의 연속 입력은 한 `fill` 이벤트(마지막 값). 바뀐 것이 없는 반복(포커스가 빠질 때의 change)은 이벤트를 건드리지 않는다. 더블클릭은 바로 앞 같은 요소의 클릭 2개를 대신한다.
- 체크박스·라디오·select·파일은 `change` 로 기록하고 그 요소(와 연결된 label)의 클릭은 남기지 않는다. 키보드로 눌린 클릭(Enter/Space)은 키 입력만 남긴다. 복사·붙여넣기·실행 취소 단축키(a·c·v·x·z·y 조합)는 재생하면 값이 바뀌므로 남기지 않는다.
- 페이지 이동 구분: 녹화기 시작 이동 = `start`, 동작(클릭·키·선택…) 뒤 2.5초 안의 이동 = `action`(링크·제출·스크립트 이동, 초안에서 생략), 그 밖 = `direct`(주소창·새로고침·뒤로). 일시정지 중 주소가 바뀌었으면 재개할 때 `direct` 이동을 하나 남긴다.
- 다운로드는 파일 이름만 남기고 받은 파일은 지운다. 스크롤은 0.5초 묶어서 남긴다.
- 스크린샷: 동작 0.4초 뒤 한 장(`scale: css`), 비밀번호·자격증명 autocomplete·민감 표시 입력란은 가린다(Playwright mask). **민감 표시를 하면** 그 입력란의 값을 지우고, 그 입력란을 처음 입력한 동작부터 다음 페이지 이동 전까지(같은 문서) 찍힌 스크린샷을 지운다(이미 값이 찍혔을 수 있음). 표시 전에 찍기 시작한 스크린샷은 버린다. 같은 입력란의 다른 입력도 함께 민감 처리한다.
- `recording.json` 은 녹화를 끝낼 때 한 번 쓴다(임시 파일 → rename). 녹화 중 값은 메모리에만 있다. 브라우저 창을 닫으면 녹화가 끝난다.
- 이벤트 필드 추가(SPEC 형식의 확장): `nav`(start·direct·action), `field`(태그·type·name·id·autocomplete·라벨·다시 찾을 선택자 — 값 없음), `interactive`·`textEntry`(클릭), `key`·`values`·`files`·`download`·`scroll`, `reason`(녹화 안 됨: popup·iframe), `el`·`doc`(문서 안 요소 키). 메모는 `{ afterSeq, at, text }`.

## 녹화 패널 (① — 앱)

- 진입: 스크립트 탭 **"시연으로 만들기"**, AI 탭 **"시연으로 만들기"** 버튼. 시작 전에 환경·시작 경로·녹화 이름을 고른다.
- 패널(앱 창 옆 또는 위): 실시간 동작 목록 · 메모 입력란(Enter = 현재 위치에 메모 추가) · **[확인] 체크포인트** · 일시정지/재개 · 마지막 동작 취소 · 종료.
- **체크포인트 모드**: 켜면 브라우저에 강조 표시가 뜨고, 다음 클릭은 **실행되지 않고** 그 요소를 검증 대상으로 잡는다. 종류를 고른다:
  - 보임 · 숨김 · 텍스트 같음(지금 텍스트를 기대값으로) · 텍스트 포함 · 현재 주소 · 개수
  - "현재 주소" 는 요소가 필요 없어 고르는 즉시 지금 주소로 기록한다(클릭 대기 없음). "개수" 는 클릭한 요소가 속한 반복 항목(표의 행, 같은 태그 형제)의 역할(또는 태그+클래스)로 세어 지금 개수를 기대값으로 둔다.
  - 메모로 기대값을 바꿀 수 있다(예: "1,200원").
- 각 동작 줄에서: 민감 표시, 삭제, 메모 붙이기.

### 녹화 패널 — 구현 세부 (2026-10-02)

- 패널은 프로젝트 화면 오른쪽에 붙는다(앱 창 안, 녹화 브라우저는 별도 창). 한 번에 녹화 1개(앱 전체). 녹화 중에는 그 프로젝트를 지울 수 없다.
- 시작 대화상자: 환경(기본 = 프로젝트 기본 환경) · 시작 경로(환경 주소 기준, 전체 URL 도 가능) · 이름(비우면 `시연 <날짜 시각>`). 브라우저 = 프로젝트 기본 엔진·디바이스, 항상 headed.
- 줄 동작: 민감(입력 줄만, 되돌리기 없음 — 값이 이미 지워짐) · 메모 · 삭제. 체크포인트 줄(텍스트·개수)은 "기대값 바꾸기" 로 기대값을 직접 고칠 수 있다(메모로 적어도 AI 가 반영). "마지막 동작 취소" 는 마지막 이벤트를 지운다(시작 이동 제외) — 브라우저 상태는 되돌리지 않는다.
- 종료 후 결과 영역: 확인 실행 환경 선택(등록 필요 secret 계산 기준) · 초안 요약 · "AI 없이 저장" · "AI로 정리"(덧붙일 말 입력란). 저장된 녹화는 스크립트 탭 아래 "시연 녹화" 목록에서 초안 저장·AI로 정리·이름 변경·삭제. 종료 후에도 "민감" 표시는 저장된 녹화에 적용된다(값·해당 스크린샷 삭제).

## 녹화 저장

```
projects/<projectId>/recordings/<recordingId>/
  recording.json     { id, name, envId, startUrl, startedAt, finishedAt,
                       events: [{ seq, at, kind, url, target:{ chosen, candidates[] },
                                  value?, sensitive?, secretHint?, note?, checkpoint?,
                                  shot? }], notes: [{ afterSeq, text }] }
  shots/<seq>.png    가림 적용 스크린샷
```

- 녹화는 프로젝트 데이터라 재시작 후에도 남는다. 목록·이름 변경·삭제·다시 변환을 지원한다. 열려 있는 녹화 패널의 녹화를 목록에서 삭제하면 패널도 닫힌다.
- 작업 로그: `recording.started` · `recording.finished` · `recording.converted`.
- 구현 세부: 녹화 id 12자 소문자 영숫자. `recording.json` 에 `version: 1`, `baseUrl`, `browser`, `euta`(엔진 버전)를 함께 둔다. `recording.converted` 는 "AI 없이 저장"(스크립트 경로·등록 필요 secret)과 "AI로 정리" 요청(채팅 id) 두 경우에 남긴다. 저장 경로는 녹화 이름 슬러그(`<slug>.yaml`, 겹치면 `-2`).

## 초안 변환 (② — 엔진, 결정적)

- 녹화 → DSL 스크립트(`version: 1`, `target.baseUrl: ${env.BASE_URL}`, 경로는 상대 `goto`).
- 매핑: 이동→`goto`(첫 이동 + 주소창 직접 이동만, 링크 클릭 뒤 이동은 생략) · 클릭→`click` · 입력→`fill` · 선택→`select` · 체크→`check/uncheck` · 키→`press` · 업로드→`upload`(파일 경로는 `files/<이름>` 자리표시) · 다운로드→`expectDownload`(파일 이름 패턴·형식) · 체크포인트→`expect` · 메모→가장 가까운 스텝 `name`.
- 민감 입력 → `fill: { value: "${secrets.<NAME>}" }`. `<NAME>` 은 라벨에서 제안(예: `PASSWORD`, `USER_EMAIL`) — **환경에 같은 뜻의 이름이 이미 있으면 그 이름을 쓴다**(제안 `PASSWORD` → 환경의 `USER_PASSWORD`: 정확히 같음 → `*_<핵심>`/`<핵심>_*` → `<핵심>` 포함 순). 환경 vault 에 그 이름이 없으면 초안 상단 주석과 변환 결과에 "등록 필요 secret" 목록으로 알린다.
- 같은 입력란 연속 입력 합치기, 의미 없는 클릭(빈 영역) 제거.
  - 구현 세부: "빈 영역" = 대화형 요소(button·a·input·label·role·onclick·tabindex 등)도 `cursor: pointer` 도 아닌 곳의 클릭. 입력란 클릭 바로 뒤에 같은 입력란의 `fill`/`press` 가 오면 그 클릭은 뺀다(둘 다 스스로 포커스). 다운로드는 바로 앞 클릭·키 스텝을 `trigger` 로 감싸고 이름은 `*.<확장자>`, `type` 은 확장자. 스크롤은 뒤에 동작이 없거나 체크포인트만 있고 맨 아래에 닿았을 때만 `scroll: { to: bottom }`. 메모는 시간상 가장 가까운 스텝(같으면 뒤 스텝) `name`, 줄 메모가 앞에 온다(여럿이면 ` / ` 로 잇는다). 시작 이동은 사용자가 고른 시작 경로로 `goto` 한다(리다이렉트 결과 주소가 아님).
- 초안만으로도 스크립트 라이브러리에 저장할 수 있다("AI 없이 저장").

## AI 정리 (③④⑤ — 앱)

- "AI로 정리" 를 누르면 그 프로젝트에 새 AI 채팅을 열고, 녹화를 붙여 요청을 보낸다(사용자가 메시지를 덧붙일 수 있음).
- AI 도구 추가: `get_recording(recordingId)` — 이벤트·메모·체크포인트·초안 YAML·등록 필요 secret 이름(값 없음), 요청 시 스크린샷. 결과는 기존 마스킹을 거친다.
- 정리 지침(시스템 프롬프트에 포함):
  - 메모·체크포인트를 `expect` 로 옮기고, 화면 전환 뒤에는 대기·확인을 넣는다. 응답 시간·Web Vitals 측정은 주요 화면에 `measure` 로 넣는다.
  - 대상은 사람이 보는 기준으로 유지하고 불안정한 CSS 는 피한다.
  - 비밀값은 `${secrets.*}` 참조만. 값을 묻거나 만들지 않는다.
  - 결과를 `save_script` 로 라이브러리에 저장 → `validate_script` → `run_script`(선택 환경) → 실패하면 원인 분석 후 수정·재실행(최대 3회) → 통과/실패와 바꾼 점을 보고.
- 사람은 결과를 보고 대화로 수정을 요청한다. YAML 을 직접 고칠 필요가 없다.
- 구현 세부: "AI로 정리" 는 녹화의 환경(또는 결과 영역에서 고른 환경)으로 새 채팅을 만들고 `시연 녹화 "<이름>" … recordingId: <id> …` + 덧붙인 말을 보낸다. `get_recording { recordingId, screenshots?: [seq] (최대 6) }` 결과: 이벤트(상대 주소, 대상 후보·일치 수, 값·체크포인트·메모 — 요소 키·재탐색 선택자 제외), 메모, 초안 YAML(두 번째 텍스트 블록), `secretsNeeded`·`missingSecrets`(이름만), `notRecorded`, 스크린샷 있는 seq 목록. 텍스트는 도구 가드의 secret 마스킹을 거친다.

## 보조 입구 — 말로 시키기

- AI 탭 입력창 위에 "말로 시키기" 안내 예시를 둔다(예: "로그인해서 보고서를 PDF로 내보내기 테스트 만들어줘").
- 지침: 탐색 세션은 headed, 사용자가 화면을 보며 끼어들 수 있게 단계마다 짧게 보고, 끝나면 `session_export` → ③④ 와 같은 확인 실행.
- 구현: 예시 3개(누르면 입력창에 채움) + "시연으로 보여주기 →" 링크. 지침은 시스템 프롬프트 "When the user only describes a goal (말로 시키기)" 절.

## 완료 기준 (검증)

- 엔진 단위: 대상 후보 생성·유일성 선택, 입력 합치기, 민감 값 미수집(페이지 수집 단계에서 값 없음), 초안 변환 매핑 전부, 등록 필요 secret 목록.
- 엔진 E2E(픽스처 사이트): 테스트가 "사람" 역할로 녹화 중인 브라우저를 조작(로그인·위젯·다운로드·체크포인트) → 녹화 파일 → 초안 변환 → **초안 스크립트가 같은 환경에서 통과** → 녹화 폴더 전체에 비밀번호 평문 0건.
- 앱 단위: 녹화 저장소(재시작 후 유지, 삭제), `get_recording` 도구(마스킹), 작업 로그 기록.
- 앱 E2E(개발·패키징본): 스크립트 탭 "시연으로 만들기" → (테스트가 녹화 브라우저 조작 + 메모·체크포인트 입력) → 종료 → "AI 없이 저장" 으로 라이브러리에 추가 → 실행 통과 → "AI로 정리"(가짜 에이전트가 `get_recording`·`save_script`·`run_script` 호출) → 채팅·라이브러리·History 반영.
- 실제 모델 호출 없음(실사용 확인은 사용자).
- 결과(2026-10-02): 엔진 153 통과(녹화 단위 8 · 페이지 수집 스크립트 5 · 녹화 E2E 5 추가), 앱 단위 92 통과(녹화 7 추가), 앱 E2E 2개(기존 + 녹화) 개발 빌드·패키징본 모두 통과. 앱 E2E 는 E2E 전용 `__eutaTest.recorderPage()` 로 녹화 브라우저를 조작한다([ADR-017](ADR_017_시연-녹화기-구현.md)).
