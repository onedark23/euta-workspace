# ADR - 042 앱 배포 업데이트 앱 구현

## 상태

채택 (2026-10-30, 단계 17 앱 구현). 코드: `euta-app` 브랜치 `feat/app-release`. **릴리스 산출물 4종 실제 빌드는 보류** — 작업 중 이 맥의 디스크가 가득 차(여유 ≈ 5GB) Docker 가 멈췄다. 맥 빌드 첫 시도는 스테이징까지 통과하고 electron-builder 단계에서 `ENOSPC` 로 멈췄다.

## 맥락

- [SPEC_앱-배포-업데이트](SPEC_앱-배포-업데이트.md) 는 네 빌드(맥 arm64 · x64, 윈도 x64, 리눅스 x64)를 이 맥에서 만들고, 서명 여부에 따라 앱이 뒤에서 받아 설치하거나(electron-updater) 알림 + 내려받기만 하며, 클라우드 `426 APP_TOO_OLD` 에 클라우드 프로젝트만 잠그도록 정했다.
- 정하지 않은 세부: 윈도 NSIS 를 무엇으로 만들지(Wine), 리눅스 node-pty 를 어떻게 컴파일할지, 맥 두 arch 의 `latest-mac.yml` 을 어떻게 하나로 만들지, 업데이터 배선, 의존성 범위 표기와 SDK ↔ CLI 짝 맞추기, "끝나면 업데이트" 의 뜻.
- 계약: `~/.cache/euta-wt/API_CONTRACT.md` (18:25 클라우드 확정 — 파일 이름 규칙, 단일 Range, 426 본문, 관리자 목록 경로).

## 결정

### 빌드 (`scripts/package.mjs`)

- `pnpm package`(개인, ADR-014)와 `pnpm release [--mac] [--win] [--linux] [--skip-build]` 를 한 스크립트로. **대상 OS 마다 스테이징 하나**(`release/stage-<os>`) — 번들 Claude Code CLI 가 플랫폼 패키지이고 리눅스만 컴파일이 필요해서다. 엔진 tarball 은 한 번만 만든다.
- 스테이징 `npm install --omit=dev --os=<os> --cpu=<arch> [--libc=glibc]` — npm 이 대상 플랫폼의 optional 의존성(SDK 의 `claude-agent-sdk-<os>-<arch>`)을 고른다. 스테이징 `package.json` 의 의존성은 앱 레포에 **설치된 정확한 버전**(범위가 아니라)이므로 릴리스 = 테스트한 것.
- **맥 두 arch 는 electron-builder 한 번**(`--mac --arm64 --x64`): `latest-mac.yml` 하나에 두 zip 이 적힌다(electron-updater 가 이름의 `arm64` 로 고름). 스테이징에 다른 arch 의 CLI 패키지를 `npm pack` tarball 로 풀어 넣고, `files` 의 `!node_modules/@anthropic-ai/claude-agent-sdk-!(darwin-${arch})/**`(electron-builder 가 arch 마다 `${arch}` 를 펼침)로 arch 마다 자기 CLI 만 담는다. node-pty · robotjs prebuild 도 같은 방식으로 대상 것만.
- 서명: 기본 ad-hoc — electron-builder `afterPack` 훅(`scripts/adhoc-sign.cjs`)이 `codesign --deep -s -` 해서 dmg · zip 이 서명된 앱을 담는다. `EUTA_MAC_SIGN=developer-id` 면 electron-builder 서명 + hardened runtime(`build/entitlements.mac.plist`) + `APPLE_API_KEY`/`APPLE_ID` 있으면 공증, 번들 CLI 는 `signIgnore`(Anthropic 서명 유지). **Developer ID 경로는 계정이 없어 미검증**.
- 빌드 결과 검사: main import 가드(개인 · 릴리스 모두), 앱 안 CLI sha256 = npm 원본(수정 금지 정책), 다른 플랫폼 CLI 없음, CLI 패키지 버전 = SDK 버전, `latest*.yml` 에 arch 별 파일.
- 업데이트 정보: `publish: generic https://<사내 euta 서버>/updates/<채널>/`, `detectUpdateChannel: false`(채널은 URL 에 — 파일 이름은 `latest*.yml` 그대로), `releaseInfo.releaseNotes` = RELEASES.md 그 버전 절, `artifactName = euta-${version}-${os}-${arch}.${ext}`(계약 파일 이름 규칙). NSIS 는 사용자 설치(`oneClick`, `perMachine: false`).
- **윈도 NSIS: 호스트, Wine 없음**. electron-builder 26 은 macOS 10.15+ 에서 언인스톨러를 `UninstallerReader`(JS)로 뽑고 실행 파일 리소스를 `resedit`(JS)로 고친다 — 호스트 Wine 도, Docker 도 필요 없다. 첫 실제 빌드에서 확인하고, 안 되면 `electronuserland/builder:wine` 컨테이너로 바꾼다.
- **리눅스 node-pty: Docker 에서 스테이징 `npm install`**(`electronuserland/builder:wine`, `--platform linux/amd64`, `npm_config_runtime=electron` · `npm_config_target=<Electron 버전>` · `npm_config_disturl=https://electronjs.org/headers`) → node-pty 의 install 스크립트가 linux prebuild 가 없어 node-gyp 로 Electron 헤더에 맞춰 `build/Release/pty.node` 를 만든다(N-API, 로더가 `build/Release` 를 먼저 봄). robotjs 는 linux-x64 prebuild. 그 뒤 electron-builder(AppImage)는 호스트에서(맥에서 AppImage 를 못 만들면 그 단계도 같은 컨테이너로 옮긴다 — 미확인). npm 캐시는 `~/.cache/euta-release/npm-linux`.
- 맥 한 번 빌드의 extglob · `${arch}` 패턴, afterPack ad-hoc 서명으로 바꾼 개인 `pnpm package` 도 **디스크 부족으로 아직 끝까지 돌리지 못했다** — 빌드 후 검사(arch 별 CLI 하나 · yml 에 두 arch · codesign verify)가 첫 성공 빌드에서 이를 확인한다.

### 업데이터 (`src/main/updater.ts` · `update-backend.ts` · `src/shared/app-version.ts`)

- 순수 규칙: `channelOf`(prerelease 이름), `compareVersions`(SemVer 2.0 우선순위, 숫자 식별자는 숫자로), `updateMode({platform, packaged, macSignature, appImage})` → `auto | manual | off`, `pickInstaller`(Apple 칩은 x64 dmg 로 대체 가능).
- 서명 판정은 런타임 `codesign` 이 아니라 **빌드가 적은 `eutaBuild.macSignature`** 를 읽는다 — 테스트 가능하고 프로세스를 띄우지 않는다.
- `AppUpdater`: 30초 뒤 · 6시간마다(타이머 `unref`) · [업데이트 확인]. `auto` 는 electron-updater 를 작은 백엔드 인터페이스(check · download · install) 뒤에 두고 `autoDownload=false` 로 확인 → 내려받기 → "준비됨". `allowPrerelease`, `autoInstallOnAppQuit`(끌 때 설치), `useMultipleRangeRequest: false`(서버가 단일 Range 만 — 계약). `manual` 은 electron-updater 를 쓰지 않고 `GET /api/app/releases` 로 새 버전과 내 dmg 주소. 실패는 `lastCheck: error` 로만(준비된 업데이트는 유지).
- 재시작: `restart(force)` — 진행 중 작업(`ProjectService.busyWork()`: 클라우드 아닌 실행 중 run · 녹화 · 응답 중 AI 채팅)이 있으면 그 목록을 돌려주고 화면이 묻는다. **"끝나면 업데이트" = 작업이 0 이 되면(3초 폴링) 알림을 다시 띄울 뿐 저절로 다시 시작하지 않는다** — "자동 재시작 금지" 와 사용자의 선택을 둘 다 지키는 해석. 끌 때는 설치된다.
- 업데이트 서버 기본 주소는 사내 euta 서버(환경 `EUTA_UPDATE_SERVER` 로 바꿀 수 있음 — E2E · 개발 서버 시험용). 클라우드 로그인 서버 주소와 따로 둔다(SPEC).
- E2E: `EUTA_E2E=1` + `EUTA_E2E_UPDATE_MODE=auto|manual` 일 때만 패키징 안 된 앱에서 경로를 강제한다. `auto` 는 electron-updater 가 가짜 피드의 `latest*.yml` 을 **실제로** 읽고(`forceDevUpdateConfig`), 내려받기 · 설치만 기록으로 대신한다(서명 없는 개발 앱은 설치할 수 없음).

### 426 (`src/main/cloud/*`)

- `CloudClient` 생성자에 앱 버전 → 모든 요청 · SSE 연결에 `X-Euta-App-Version`. 오류 본문은 `{ code, minVersion }` · `{ error: {…} }` 둘 다 읽는다.
- 연결 상태에 `app_too_old` 추가. `markOffline` 한 곳에서 426 을 판별해 요청 · 피드 · 보내기 · 알림 스트림 어디서 받아도 같은 잠금. 오프라인과 달리 **재시도 루프 없음**, 보내기 대기분은 `queued` 그대로(거절로 바꾸지 않음). `ProjectCloudView.appTooOld` → "업데이트 필요" 화면 + [업데이트].

### 의존성 범위

- `package.json` 의 정확한 고정을 모두 `^` 로(`pnpm install` 후 lockfile 은 `specifier` 줄만 바뀜 — 해석 버전 그대로). 새 의존성 `electron-updater ^6.8.11`.

## 이유

- OS 별 스테이징 + 설치된 버전 고정은 ADR-014 의 "pnpm 트리와 분리" 를 그대로 늘린 것이고, 교차 플랫폼 optional 의존성을 npm 이 정확히 고른다.
- 맥 한 번 빌드는 `latest-mac.yml` 병합 코드를 없앤다(electron-builder 가 스스로 합침).
- Wine 없이 되는 길이 있는데 Wine(호스트 설치 또는 수 GB 이미지)을 쓸 이유가 없다.
- 리눅스만 Docker 에서 `npm install` 하면 에뮬레이션(amd64)이 느린 구간을 컴파일에만 쓴다.

## 고려한 대안

- **맥 arch 별 따로 빌드 + yml 병합** — 병합 코드와 순서 의존이 생김. 제외.
- **윈도를 `electronuserland/builder:wine` 에서** — 동작은 확실하지만 이미지가 크고(Docker 디스크 압박), 호스트 경로가 되면 불필요. 대체 경로로 둠.
- **리눅스 전체(electron-builder 포함)를 컨테이너에서** — 가능하지만 느리고 호스트 electron-builder 와 경로를 맞춰야 함. 컴파일만 컨테이너.
- **런타임에 `codesign -dv` 로 서명 판정** — 프로세스 실행 · 파싱이 필요하고 테스트가 어렵다. 빌드 기록으로.
- **"끝나면 업데이트" = 끝나면 자동 재시작** — 사용자가 다른 일을 하던 중에 앱이 꺼질 수 있어 "자동 재시작 금지" 와 맞지 않음. 제외.
- **`semver` 패키지** — 비교 하나에 의존성을 더할 필요 없음(30줄).
