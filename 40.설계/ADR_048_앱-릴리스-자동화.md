# ADR - 048 앱 릴리스 자동화

## 상태

진행 중 (2026-11-10). 설계 확정(사용자 결정 2026-11-10 — "둘 다 자동"), 구현 · 단위 · E2E 완료, 실제 Actions 실행 · 배포 전.

## 맥락

- 첫 릴리스 `0.1.0-alpha.1`(2026-11-09)은 손이 세 번 갔다: 개발 맥에서 4종 빌드(디스크 · Docker 필요) → `release:github` → 관리자 토큰으로 `release:upload`(사내 미러).
- 맥 앱은 macOS 에서만 빌드된다 — 서버 이미지처럼 사내 클러스터(Linux) 빌드 Job 으로는 만들 수 없다.
- GitHub 쪽 자동화는 사내 서버에 닿지 못한다(서버는 허용한 IP 만 받는다). 반대로 사내 클러스터 pod 는 GitHub 에 나갈 수 있다(2026-11-06 확인).

## 결정

1. **빌드 · 공개 게시 = GitHub Actions**(앱 레포 `.github/workflows/release.yml`). 트리거 = 태그 `app-v*` push(+ 수동 실행, 입력 `engine_ref`).
   - macOS 러너(`macos-14`, Apple 칩): `pnpm release --mac --win` — 맥 arm64 · x64 와 Windows x64(이 맥에서처럼 Wine 없이 교차 빌드, 2026-11-09 확인).
   - Ubuntu 러너: `pnpm release --linux` — 그 자리에서 node-pty 를 Electron 헤더로 컴파일(맥에서는 Docker 안에서 하던 일). 빌드 스크립트의 "릴리스는 macOS 에서만" 검사를 "리눅스 호스트는 `--linux` 만" 으로 넓힌다.
   - 엔진은 앱 옆 `euta-engine/` 에 `onedark23/euta-engine`(기본 `main`)을 받는다 — 로컬과 같은 `link:../euta-engine` 배치.
   - 게시 작업: 세 빌드의 산출물을 `release/<버전>/{mac,win,linux}/` 로 모아 `release:github --publish`(GitHub CLI, 작업 토큰 `contents: write`). 공개 레포라 macOS 러너도 비용 없음.
   - 빌드 전 확인: 태그 = `app-v<package.json version>`, `RELEASES.md` 에 그 절이 있음.
2. **사내 미러 = 서버가 GitHub 에서 가져온다**(클라우드 서버 기능, 끄고 켤 수 있음). `APP_MIRROR_GITHUB=<owner/repo>` 면 시작 1분 뒤 · `APP_MIRROR_INTERVAL`(기본 10분)마다:
   - 최신 태그: `https://github.com/<repo>/releases/latest` 의 넘겨 주기(302 `Location: …/releases/tag/<태그>`)로 읽는다 — GitHub API(비로그인 IP 당 시간당 60회)를 쓰지 않는다. 받는 동안 "latest" 가 바뀌어도 섞이지 않게 이후 파일은 모두 `releases/download/<태그>/<이름>` 에서 받는다.
   - `latest-mac.yml` · `latest.yml` · `latest-linux.yml`(404 = 그 플랫폼 없음)의 버전이 서버에 없으면 초안을 만들고, yml 의 `files`(sha512 를 yml 값과 비교) · 각 파일의 `.blockmap`(없으면 건너뜀) · yml 자체를 기존 저장 경로(`saveReleaseFile`, 이름 규칙 · 1GiB)로 넣은 뒤 게시한다. 노트 = yml `releaseNotes`.
   - 실패하면 초안을 지우고 기록(시각 · 결과 · 메시지)을 남긴다 — 다음 주기에 다시. 한 번에 하나만 돈다(진행 중이면 [지금 가져오기] 는 그 결과를 기다림).
   - 관리자 API `POST /api/admin/app-releases/mirror`(지금 가져오기) · 상태는 `GET /api/admin/app-releases` 응답의 `mirror` 에 둔다. 웹 "릴리스 관리" 에 마지막 가져오기와 [지금 가져오기] 버튼.
   - 관리자 토큰이 사람 손을 거치지 않는다(서버가 자기 DB 에 넣음). 업로드 Ingress 도 쓰지 않는다(서버가 나가서 받음).
3. **예비 경로 유지** — 이 맥의 `pnpm release` · `release:github` · `release:upload` 는 그대로 둔다(Actions 장애 · 사내 먼저 배포).

## 구현 메모 (2026-11-10)

- 클라우드(`services/app-mirror.ts`): 설정 `APP_MIRROR_GITHUB`(owner/repo 형식이 아니면 시작 거절) · `APP_MIRROR_INTERVAL`(단위 필수 `30s`·`10m`·`1h`, 최소 1분) · 테스트용 `APP_MIRROR_BASE_URL`. 상태 `{ repo, running, lastRun: { at, result: published | already | none | error, version?, message? } }`, 끄면 `POST …/mirror` 는 409 `MIRROR_OFF`.
- **더 낮은 버전은 게시하지 않는다** — GitHub 최신이 그 채널의 게시본보다 낮으면(손으로 더 새 버전을 먼저 올린 경우 등) `already`. 게시는 `latest*.yml` 을 가장 최근 게시본으로 바꾸므로 낮은 버전이 덮어쓰면 업데이트가 뒤로 간다.
- **중단된 가져오기 정리** — 서버가 가져오는 도중 꺼지면(pod 교체) 미러가 만든 초안(`created_by` NULL)이 남는다. 45분(파일당 제한 30분 + 여유)이 지난 그런 초안은 다음 실행이 지우고 다시 가져온다. 관리자가 올린 초안(`created_by` 있음)은 건드리지 않는다. 다른 서버 인스턴스가 같은 버전을 먼저 만들면(`VERSION_EXISTS`) `already`.
- 요청 시간 제한: 넘겨 주기 · yml 30초, blockmap 2분, 파일 30분. yml 은 받은 그대로 저장, yml 항목에 sha512 가 없으면 실패. 노트 = 첫 `releaseNotes`(앱과 같은 글 규칙, 2만 자).
- 파일 내려받기는 GitHub 이 `release-assets.githubusercontent.com`(2026-11-10 확인) 으로 넘겨 주므로 pod 가 그곳에도 나갈 수 있어야 한다.
- 웹 "릴리스 관리": 미러가 켜져 있으면 안내 문구가 "GitHub 에서 자동으로 가져와 게시" 로 바뀌고, 마지막 가져오기 줄 + [지금 가져오기], 진행 중이면 3초마다 다시 읽는다.
- 앱(`.github/workflows/release.yml`): check(태그 = 버전 · 노트 절) → build(macOS `--mac --win` · Ubuntu `--linux`, 엔진은 `--ignore-scripts` 로 설치 — 네이티브는 robotjs 하나, 릴리스 스테이지가 prebuild 로 해결) → publish(`release:github --publish`, 태그 push 또는 수동 실행의 `publish`). 빌드 스크립트: 리눅스 호스트는 `--linux` 만, node-pty 를 Electron 헤더로 그 자리에서 컴파일.

## 대안

- **빌드만 자동, 미러는 관리자 버튼**: 사람이 한 번 더 눌러야 한다. 버튼은 자동 주기와 함께 둔다.
- **GitHub Actions 가 사내 서버로 올리기**: 사내 서버가 GitHub 러너 IP 를 받지 않는다(사내망 전용). 허용 목록을 넓히는 것은 보안 원칙과 맞지 않는다.
- **사내에 macOS 빌드 머신**: 장비 · 운영 부담. 공개 레포의 macOS 러너로 충분.
- **electron-builder `--publish always`(github)**: 플랫폼마다 따로 올려 같은 릴리스에 경합하고, 우리 파일 이름 규칙 · 노트 처리(`release:github`)와 겹친다.

## 검증

- 서버 단위: 미러 — 새 버전 가져와 게시(파일 · blockmap · yml, sha512 확인) · 이미 있는 버전은 건너뜀 · sha512 다르면 실패하고 초안 없음 · 한 플랫폼 yml 없음은 건너뜀 · 버전 어긋남 · 파일 404 · 낮은 버전 · 동시 실행 하나 · 중단된 초안 정리(관리자 초안은 그대로) · 설정 비면 꺼짐 · 관리자만 [지금 가져오기].
- 웹 E2E: 릴리스 관리의 마지막 가져오기 · [지금 가져오기](가짜 GitHub), 화면 캡처.
- 실제: 다음 버전(`0.1.0-alpha.2`) 태그 push → Actions 3빌드 · 게시 → 사내 서버가 10분 안에 게시 → 설치된 alpha.1 이 사내 미러에서 업데이트를 알아챔.
