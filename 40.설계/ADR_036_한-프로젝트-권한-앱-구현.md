# ADR - 036 한 프로젝트 + 권한 앱 구현

## 상태

채택 (2026-10-23). 단계 15 의 **앱 쪽** 구현. 브랜치 `feat/one-project-perms`(euta-app) — 커밋 f520c65(기능) · 8db6d22(E2E·화면 다듬기). 서버 API 는 ADR-035 / 작업 폴더 `API_CONTRACT.md` 를 그대로 따른다.

## 맥락

- 올리기가 복사였기 때문에 사이드바에 로컬 프로젝트와 클라우드 작업 사본이 따로 보였다. 단계 15 는 올리기를 **전환**으로 바꾸고(SPEC), 이미 갈라진 프로젝트는 **대상이 고정된 합치기**로 하나로 만든다.
- 앱 id 규칙(작업 사본 id = 클라우드 UUID 에서 `-` 를 뺀 값, vault 키도 그 id — ADR-025)은 바꾸지 않는다. 로컬 프로젝트 id 는 임의 값이라 "같은 id 로 제자리 전환" 은 불가능하다.
- 엔진의 `runs/index.sqlite` 는 실행 폴더·스크립트 경로를 **절대 경로**로 저장한다. 폴더만 옮기면 History 가 끊긴다.
- 역할에 실행자가 생겼다. 기존 화면은 `readOnly`(= `script.edit` 없음) 하나로 편집·실행 버튼을 함께 숨기고 있었다.

## 결정

### 올리기 = 전환 (`CloudService.upload`)

- 서버 단계(네트워크): `POST /api/projects` 에 `origin: app` + `originLocalId` = 로컬 프로젝트 id → 환경은 **이름으로 재사용**, 스크립트는 같은 경로의 서버 해시가 같으면 건너뜀(아니면 그 버전을 기준으로 PUT), 테스트 세트는 이름으로 재사용. 서버가 같은 `originLocalId` 를 멱등으로 받아 주므로(`resumed: true`) **"이어서 하기" 에 앱 쪽 표시를 따로 두지 않는다** — 다시 누르면 같은 요청이 같은 프로젝트로 이어진다.
- 로컬 단계(동기 — IPC 가 끼어들 수 없음): 감시·AI 채팅을 먼저 놓고(`ProjectService.release`), 작업 사본을 받은 뒤(`openRemote`), `local-move.ts` 가 `runs`(색인 경로 바꿈) · `suite-runs`(프로젝트·세트·환경 id 바꿈) · `baselines/<환경 id>`(클라우드 환경 id 로 이름 바꿈) · `chats` · `recordings` · `activity` · `script-history` · `designs` · `design-reviews` · `scripts` 를 작업 사본 폴더로 **옮긴다**(같은 볼륨 rename). 이 PC 테스트 계정 값은 **복호화 없이 암호문째** 새 키로 옮긴다(`Vault.moveEnv` — 값을 돌려주는 메서드는 여전히 없음). 마지막에 `ProjectService.converted` 가 고정·최근 순서 자리를 넘기고 로컬 항목을 지운 뒤 한 번만 `projectsChanged`.
- 실패: 서버 단계·`openRemote` 에서 실패하면 로컬 프로젝트는 그대로(감시 다시 붙임). 확인 대화상자(올라가는 것 / 이 PC 에 옮겨지는 것 + 실행 수)는 서버 호출 없이 `convertPreview` 로 만든다.
- 이미 `uploadedTo` 가 있는 프로젝트는 올리기를 막고 합치기로 안내한다.

### 합치기 (`mergeStatus` · `mergePlan` · `mergeApply`)

- 대상 = `uploadedTo.projectId` 고정. 버튼은 `merge/check` 가 통과할 때만 보이고, 거절이면 이유를 한국어로 배너에 적는다 — `ORIGIN_MISMATCH`(`web_origin` → "웹에서 만든 … 받아서 쓰세요", `local_id_mismatch` · `link_mismatch`), `FORBIDDEN not_owner`, 404.
- 비교는 경로 기준 내용 해시: 로컬에만 → 올림 · 같음 → 그대로 · 서버에만 → 그대로 · 다름 → **로컬 / 서버 / 둘 다**(둘 다 = 로컬 것을 `이름-로컬.yaml` 새 스크립트로). 단계 문장 비교(서버 → 로컬)를 같은 diff 로 보인다. 테스트 세트는 같은 이름이고 목록이 다를 때만 로컬 / 서버. 다 고르기 전에는 [합치기] 가 꺼져 있고, 고를 것이 없으면 "내용이 같아 고를 것이 없습니다".
- 적용 순서: 검사 → 올림(스크립트·환경·세트) → `POST merge`(요약 숫자) → 로컬 감시 놓기 → 작업 사본 전체 다시 받기 → 로컬 단계(위와 같은 이동, **실행 색인은 ATTACH 로 행을 합침**, 스크립트 폴더는 옮기지 않음, vault 값은 대상에 없는 이름만).
- 작업 사본에 보내기 대기분이 있으면 합치기를 막는다(순서가 꼬이지 않게).

### 역할별 화면 — `can` 으로

- `ProjectCloudView` 에 `canRun`(`run.execute`) · `canUpload`(`run.upload`) · `canRequestAccess`(`access.request`) 를 더하고 `readOnly` 는 "`script.edit` 없음" 그대로. 서버가 `can` 을 안 주면(옛 서버) 역할 표로 대신한다(`allows()`).
- 머리: `readOnly && canRun` → **실행 전용**, `readOnly && !canRun` → **보기 전용**, `canRequestAccess` 면 [권한 요청](또는 "권한 요청 중"), [역할 새로고침]. 실행 버튼(스크립트 행 · 상세 · 실행 탭 · 테스트 세트)은 `canRun` 으로, 편집 버튼은 `readOnly` 로 숨긴다. 보기 역할의 실행 탭은 실행 버튼 대신 안내 문장.
- 역할 변화 반영: 프로젝트를 열 때와 다시 연결될 때 `GET project` 를 먼저 다시 읽고(`openFollow`), 피드의 `member.*` · `access.*` · `project.*` 는 스냅샷을 다시 읽는다. 앱 알림 `access.approved/rejected` 도 그 작업 사본을 다시 읽는다. 역할이 바뀌면 "내 역할이 바뀌었습니다: 보기 → 실행자" 알림 띠.
- 구성원(소유자): 네 역할 고르기, 열린 권한 요청 목록 + [승인](역할 바꿔 승인 가능) · [거절]. `access.requested` 알림이 오면 목록을 다시 읽고 띠로 알린다.

### 접근 권한 없음

- 404(피드 연결 · 스냅샷) 또는 `event: access_lost` → `state.json.accessLost = { at }`. 잠긴 작업 사본은 피드·보내기를 하지 않고, 화면은 잠금 카드([다시 확인] · [이 PC 에서 지우기]) + **[실행 이력](이 PC 기록만) · [실시간](재생)** 두 탭만. 사이드바는 자물쇠 아이콘. 다음 `GET project` 200 이면 풀린다. 서버가 404 를 "삭제" 와 구분하지 않으므로(계약) 문구도 셋을 함께 적는다.

### [클라우드에서 받기]

- `GET /api/projects/receivable` 의 `mine` / `org` 를 두 표로(이름 · 만든 사람 · 출처 · 내 역할 · 최근 실행), 이름·만든 사람 검색. [받기](주 동작) / 이미 받았으면 [열기] / 요청할 수 있으면 [권한 요청] / 요청 중 배지. 옛 서버(404)는 `GET /api/projects?scope=all` 을 역할로 나눈다. 사이드바 항목 이름 "클라우드 프로젝트 찾기" → "클라우드에서 받기".

### 테스트

- `e2e/fake-cloud.ts` — 계약 모양만 흉내 내는 메모리 가짜 서버(HTTP, 장치 로그인·SSE 포함). 단위(`test/unit/cloud-one-project.test.ts`, 5건)와 앱 E2E(`e2e/one-project.spec.ts`, 계정 A·B)가 같이 쓴다. 실서버 E2E(`cloud.spec.ts` · `cloud-runs.spec.ts`)는 전환 흐름에 맞게 고쳐 실서버(클라우드 워크트리 빌드)에서도 통과.

## 이유

- 전환을 "새 id 로 옮기고 같은 자리에 둔다" 로 한 것: 앱 id = 클라우드 id 규칙(vault 키·알림·작업 사본 경로)이 이미 여러 곳에 묶여 있어, 로컬 id 를 유지하는 쪽이 훨씬 넓게 바뀐다. 사용자에게 보이는 것(사이드바 한 항목·같은 순서·고정·History)은 같다.
- 암호문 이동: 값을 복호화해 다시 쓰는 경로를 만들지 않는다(보안 규칙 — 값은 실행 조립 때만 복호화).
- 로컬 단계를 동기로: 렌더러의 목록 요청은 IPC(매크로태스크)라 동기 블록 사이에 끼지 못한다 → 두 항목이 보이는 순간이 없다.

## 고려한 대안

- 로컬 id 를 유지한 채 `cloud` 연결만 붙이기 — 작업 사본 폴더·vault 키·알림 id 변환이 모두 두 갈래가 되어 버림.
- 실행 결과를 복사(cp) — 큰 영상·trace 를 두 벌 두게 되어 버림. 같은 볼륨 rename 이 원자적이다.
- 엔진에 색인 재구성 기능 추가 — 엔진을 고치지 않는 범위라 앱에서 `node:sqlite` 로 경로만 바꾼다.
- 합치기에 서버 일괄 API — ADR-035 와 같은 이유로 기존 API 재사용.
