# SPEC - 클라우드 실행·예약

> 상태: **확정** (2026-10-20, C0). 제안값은 2026-10-20 사용자 확인으로 모두 채택. 구현 단계: C1(러너·실행 — **구현 완료** 2026-10-20) · C3(예약·알림·위임 — **서버 구현 완료** 2026-10-21, 앱 쪽 대기) · C4(웹 화면 — **구현 완료** 2026-10-21, [ADR-029](ADR_029_클라우드-웹-화면-구현.md)).
> 구조·흐름은 [ARCH_euta-cloud 실행 위임·러너](ARCH_euta-cloud.md#실행-위임--러너). 계정·프로젝트는 [SPEC_클라우드-계정-프로젝트](SPEC_클라우드-계정-프로젝트.md).

## 목적

- 클라우드 공유 프로젝트의 스크립트·스위트를 **사람이 PC 를 켜 두지 않아도** 클라우드 러너가 실행한다 — 즉시(웹·앱·MCP) 또는 예약.
- 실행 결과는 엔진 결과 폴더 형식 그대로 보관하고, 진행 상황을 실시간으로 보여 주며, 실패하면 알린다.

## 실행 요청

| 항목 | 규칙 |
|---|---|
| 대상 | 스크립트 1개 또는 스위트 1개 |
| 환경 | 필수(기본 환경이 있으면 기본값) |
| 덮어쓰기 | `vars` 키·값(선택) |
| 시간 제한 | 프로젝트 기본값(6시간) → 예약·요청에서 덮어쓰기. **상한 24시간** |
| 녹화 | 클라우드 기본 `video`·`trace` = `on-failure`. 스크립트 `record` 에 명시한 값이 우선 |
| 요청 주체 | 편집자 이상 — 웹 · 로컬 앱(실행 위임) · MCP(쓰기 권한 토큰) · 예약 |
| 스크립트 버전 | 요청 시점의 현재 버전으로 **고정**(버전 id·내용 해시를 실행에 기록). 이후 저장은 이 실행에 영향 없음 |

### 사전 검사 (서버 정본)

요청을 등록하기 전에 모두 통과해야 한다. 앱·웹은 같은 검사를 미리 돌려 버튼 옆에 사유를 보여 준다.

| 검사 | 실패 응답 |
|---|---|
| 스크립트 검증 오류 없음 | 422 — 검증 오류 목록 |
| `input: os` 스텝 없음(스텝·그룹·`defaults.input`·`expectDownload.trigger`) | 422 — "클라우드에서는 OS 입력을 쓸 수 없음" |
| 환경 주소가 공개 주소(사설 IP·사내 주소로 풀리지 않음) | 422 — "클라우드에서 접속할 수 없는 주소" |
| 스크립트의 `${secrets.*}` 이름이 모두 환경 테스트 계정에 있음 | 422 — 없는 이름 목록 |
| `${secrets.*}` 는 입력 스텝(`fill`·`type`) 값에만 쓰임 | 422 — 위반 스텝 목록 |
| 프로젝트가 휴지통에 있지 않음 | 404 |

- 사전 검사 때 스크립트가 쓰는 테스트 계정 이름 집합을 뽑아 실행에 저장한다(동시 실행 규칙에 사용).
- 서버는 엔진 `cloudPrecheck(source, { vars, env })`(`@euta/core/precheck`)로 검사한다. `env` 는 서버 환경변수가 아니라 **실행 환경의 값**(`BASE_URL` = 환경 주소 + 환경 변수 + 요청 덮어쓰기)을 넘긴다.

## 실행 상태

```
대기 ──▶ 실행 중 ──▶ 통과 | 실패 | 오류 | 시간 초과 | 중단 | 취소
  │                       (재실행 옵션으로 두 번째 시도가 통과하면 "통과 · 불안정")
  ├──▶ 취소 (대기 중 취소)
건너뜀 (예약 회차를 등록하지 않은 기록)
```

| 상태 | 뜻 |
|---|---|
| 통과 · 실패 · 오류 | 엔진 실행 상태 `passed` · `failed` · `error` 그대로 |
| 시간 초과 | 시간 제한을 넘겨 강제 종료 |
| 중단 | 러너가 죽어 임대가 만료됨, 또는 결과 업로드가 끝내 실패 |
| 취소 | 사람이 취소 |
| 건너뜀 | 예약 회차가 놓쳤거나 겹쳤거나 하루 실행 상한에 걸려 실행하지 않음 — 사유 기록(겹침 · 놓침 · 상한) |

### 취소

- 편집자 이상. 대기 중이면 즉시 "취소". 실행 중이면 러너에 취소 신호 → 엔진 하위 프로세스 종료 → 그때까지의 결과를 올리고 "취소".

## 동시 실행

- **같은 테스트 계정은 한 번에 1개** — 키 = (환경, 테스트 계정 이름). 실행 중인 실행과 계정이 겹치는 대기 실행은 기다린다. 테스트 계정을 안 쓰는 스크립트는 제약 없음.
- 러너당 동시 실행 상한은 러너 설정값(기본 4, dev 2). 전체 상한 = 러너 수 × 상한.
- 대기 순서는 등록 순. 예약 실행과 사람 요청 사이 우선순위는 두지 않는다(1차).

## 하루 실행 상한

> PLAN 결정 "실사용 부작용"(2026-10-21) — 대상 서비스에 실제 데이터·비용·게시가 생기므로 예약·반복 요청이 이를 키우지 않게 막는다.

| 항목 | 규칙 |
|---|---|
| 값 | 프로젝트 설정 `하루 실행 상한` — 기본 **50**, 1~10,000. 편집자 이상 |
| 하루 | Asia/Seoul 달력 날짜(00:00 기준) |
| 세는 것 | 그날 등록된 **스크립트 실행 수** — 사람 요청(웹·앱) · MCP · 예약 · 재실행. 스위트는 스크립트 수만큼 |
| 세지 않는 것 | 로컬 실행 올리기 · 건너뜀 기록 |
| 넘으면 | 예약 회차 → "건너뜀(상한)". 사람·MCP 요청 → 422 `DAILY_RUN_CAP_REACHED`(details: 상한 · 사용 · 날짜). 재실행 → 하지 않고 첫 시도 결과로 알림 |
| 보기 | 프로젝트 응답에 상한과 오늘 사용량 |

## 러너 프로토콜 (내부)

> 클러스터 안 전용 경로(`/internal/*`). 러너 인증 = 러너 토큰(k8s Secret). 외부 ingress 로 내보내지 않는다.

| 단계 | 요청 | 내용 |
|---|---|---|
| 1. 임대 | `POST /internal/runner/claim` | 러너 id·여유 슬롯 → 실행 1건(스크립트 원문·환경 주소·변수·허용 도메인·브라우저·시간 제한·녹화 값) + 임대 만료 시각. 없으면 204 |
| 2. 계정 | `POST /internal/runs/:id/credentials` | 이 실행에 필요한 테스트 계정 값. **실행당 1번만**, 이후 같은 요청은 거절 |
| 3. 진행 | `POST /internal/runs/:id/events` | 엔진 이벤트 묶음(1초 또는 50건) + 임대 연장. 응답에 취소 신호 |
| 4. 업로드 | `PUT /internal/runs/:id/result` | 결과 폴더 tar 스트림(경로 탈출 항목 거절) |
| 5. 종료 | `POST /internal/runs/:id/finish` | 최종 상태·요약. 업로드 완료 뒤에만 받는다 |

- 러너는 엔진을 `euta run <임시 폴더의 스크립트> --runs-dir <임시> --secrets <임시 파일> --cloud --allowed-domains <환경 허용 도메인>` 하위 프로세스로 실행한다(`--cloud` = `input: os` 거절 · 녹화 기본 `on-failure` · secrets 사용 위치 제한, [ADR-024](ADR_024_엔진-클라우드-보완.md)). 허용 도메인 목록은 항상 넘긴다(없으면 어떤 호스트에서도 secrets 입력 안 함). 임시 secrets 파일은 권한 0600, 엔진 시작 직후 삭제. 실행이 끝나면 임시 폴더 전체를 지운다.
- 임대 연장 주기 30초, 만료 2분. 만료된 실행은 서버가 "중단" 처리.
- 실행 위치: 러너 설정값(예: "사내 dev 클러스터")을 실행에 기록한다. 시각 비교 기준 이미지는 `baselines/<환경>/<실행 위치>/` 를 쓴다.

## 예약

| 필드 | 규칙 |
|---|---|
| 이름 | 1~80자 |
| 대상 · 환경 | 스크립트 또는 스위트 · 환경. 웹에서 스크립트는 이름 · 경로 검색 + 체크로 하나를 고른다(미리 골라 두지 않음) — [계정 SPEC "스크립트 표시"](SPEC_클라우드-계정-프로젝트.md) |
| 주기 | 프리셋 — 매시간(분 지정) · 매일 HH:MM · 평일 HH:MM · 매주 요일 HH:MM · 직접 입력(cron 5필드). 시간대 Asia/Seoul. **최소 간격 10분** |
| 시간 제한 | 실행 요청과 같은 규칙 |
| 실패 시 재실행 | 끔(기본) / 1회 |
| 상태 | 켜짐 · 꺼짐. 프로젝트가 휴지통에 가면 자동 꺼짐 |
| 권한 | 편집자 이상. 만든 사람이 프로젝트에서 빠져도 예약은 계속(행위자 "예약 — 만든 사람") |

- 다음 실행 시각을 목록에 보여 준다. 최근 3회 실행 시간 평균이 주기보다 길면 경고.
- 회차 처리: 시각이 되면 실행 등록. **이전 회차가 아직 실행 중**이면 "건너뜀(겹침)". **서버가 멈춰 놓친 회차**는 몰아 등록하지 않고 "건너뜀(놓침)" 1건만 남기고 다음 시각으로. [하루 실행 상한](#하루-실행-상한)에 걸리면 "건너뜀(상한)".

| 내용 | 프로젝트 · 대상 · 환경 · 상태 · 실패 단계(단계 문장) · 소요 시간 · 웹 실행 화면 링크. **테스트 계정 값·스크린샷·HAR 은 싣지 않는다** |
| 형식 | **Teams 워크플로(Workflows) webhook + Adaptive Card 1.4** — Office 365 커넥터 webhook 은 2026-05 폐지(Change Log 2026-10-21). 전송 실패는 5회까지 재시도(30초 · 2분 · 10분 · 30분 간격, `Retry-After` 우선), 전송 상태 기록 |

| 대상 | 규칙 |
|---|---|
| 요약 · 단계 · 지표 · expect 결과 · 색인(DB) | 1년 |
| 결과 파일(스크린샷 · 실패 영상 · trace · HAR · console · artifacts · report.html) | 30일, 그리고 **전체 12Gi 상한** — 넘으면 오래된 실행부터 삭제. 삭제된 실행은 "파일 만료" 표시 |
| 시각 비교 기준 이미지 | 정리 대상 아님. 기준을 지우면 다음 실행이 새로 만든다 |

## 실행 화면 (웹, C4)

- 실행 목록: 상태 · 대상 · 환경 · 출처(웹·앱·AI·예약·로컬 올림) · 요청자 · 시작 · 소요 시간 · 실행 위치. 필터.
- 실행 상세(`/projects/:id/runs/:runId` — Teams 카드·앱 알림 링크): 진행 중이면 현재 단계 · 경과 시간(실시간), 단계 타임라인(단계 문장) · 스크린샷 · 지표 · 콘솔·네트워크 실패 · report.html 열기 · 파일 내려받기 · 취소 · 같은 설정으로 다시 실행.
- **수동 확인 필요**(DSL `manual` 단계, [ADR-037](ADR_037_DSL-수동-단계-상태-검사.md)): 러너 이벤트·로컬 올리기의 단계 `manual: { instruction, reason? }` 표시를 실행 행 단계에 그대로 저장한다(실행 상태·`summary` 는 그대로). 실행 상세(진행 중 포함)의 도달한 수동 단계는 보라색 "수동 확인 필요" 배지 + 확인할 내용 · 이유, 앞 단계 실패로 도달 못 한 것은 건너뜀 모양 + 내용. 단계 요약 줄에 `수동 확인 필요 N`(모든 `manual` 단계 — report.html 과 같은 셈, 0 이면 없음). 테스트 세트 리포트는 요약 카드 "수동 확인 필요 N" · 스크립트별 표의 개수 배지 · "수동 확인 필요" 표(스크립트 · 단계 · 확인할 내용 · 이유, 도달 못 한 것은 "실행 안 됨") — `suite-report` 응답 `manual` 목록. 스크립트 상세의 최근 실행 겹쳐 보기도 같은 배지.
- **테스트 세트(부모) 실행의 실행 상세 = 테스트 세트 리포트 화면**(단계 14, [SPEC_프로젝트-관리 테스트 세트 리포트](SPEC_프로젝트-관리.md#테스트-세트-리포트-2026-10-23) · [ADR-032](ADR_032_테스트-세트-리포트-Live-구현.md)): 요약(통과 수/전체 · 실패·오류 · 실행 안 함) · 지난 실행 대비(같은 세트 · 같은 환경의 직전 끝난 실행 — 새로 실패 · 회복 · 계속 실패 · 그대로 통과와 해당 스크립트, 지난 실행 링크) · 스크립트별 표(순번 · 이름 + 작은 경로 · 상태 · 소요 · 항상 실행 · 열기) · 실패 스크립트마다 실패 단계 문장 · 오류 · 그 단계 스크린샷. 자료는 `GET /api/projects/:id/runs/:runId/suite-report`(보기 권한, 세트 실행이 아니면 422). Teams "실행 보기"와 앱 [리포트] 가 이 화면으로 온다.
- 실행 요청(스크립트 상세 · 스위트): 환경 · 변수 덮어쓰기 · 시간 제한 + 사전 검사 사유를 실행 버튼 앞에. 예약 화면: 목록(다음 실행 · 최근 결과 · 소요 시간 경고) · 만들기/고치기 · 켜기/끄기 · 삭제.

### 2026-10-21 — C3 서버 구현 반영 (예약 · 재실행 · 알림 · 앱 알림 · 로컬 올리기 · 하루 실행 상한)
- **Teams 방식 확인 결과**(공식 문서, 2026-10-21): Office 365 커넥터(기존 "Incoming Webhook")는 연장 끝에 **2026-05-18~22 롤아웃으로 동작 중지**(devblogs.microsoft.com "Retirement of Office 365 connectors within Microsoft Teams", 2026-04-14 갱신). 대체 = Teams **워크플로**(Power Automate) — 채널 > 워크플로 > "Send webhook alerts to a channel" 템플릿(또는 "When a Teams webhook request is received" 트리거)에서 webhook 주소를 복사해 프로젝트 설정에 넣는다(learn.microsoft.com Teams platform "Create incoming webhooks"). 본문 = `{"type":"message","attachments":[{"contentType":"application/vnd.microsoft.card.adaptive","contentUrl":null,"content":<Adaptive Card>}]}`(learn.microsoft.com/connectors/teams 트리거 설명). 카드 버전 1.4(Teams 지원 범위 안에서 여유). 응답은 202 등 2xx = "워크플로가 받음"이지 채널 게시 완료가 아니다 — 게시 실패(28KB 초과 등)는 워크플로 실행 기록에만 남는다. 게시 동작 한도 25회/5분(연결당) → 서버가 프로젝트당 5분 20건을 넘기면 1분씩 미룬다. 주소에 SAS `sig` 가 들어 있어 비밀값으로 다룬다(로그에는 호스트만). 주소 호스트는 바뀔 수 있어(`logic.azure.com` → `*.powerplatform.com` 이전, 2025-11-30) 검사하지 않는다(https 만).
- 전송: 실행 종료 트랜잭션에서 알림 행(outbox)을 쓰고 커밋 뒤 보낸다(`NOTIFY` + 15초 주기, 서버 여러 대여도 `SKIP LOCKED` 로 1번). 2xx → 보냄. 408·429·5xx·네트워크 오류 → 재시도(위 간격, `Retry-After` 가 더 길면 그 값, 최대 1시간). 그 밖의 4xx → 실패. 웹훅 주소가 없으면 Teams 행을 만들지 않는다(앱 알림은 그대로).
- 알림 판정: 대상 = 예약 실행(최상위 실행. 스위트는 부모 1건). 연속 판정 키 = (스크립트 또는 스위트, 환경)의 **직전 예약 실행 결과**(통과·실패류만 보고, 건너뜀·취소·중단과 재실행된 첫 시도는 건너뛴다). 실패류 + 직전 실패류 → 보내지 않음, 통과 + 직전 실패류 → 회복. 그 밖의 통과 → `passed` 토글, 불안정 → `flaky` 토글, 건너뜀 → `skipped`, 중단 → `aborted`. 프로젝트 필드 `notify`(기본 모두 끔, `PATCH /api/projects/:id`). 재실행이 걸린 첫 시도는 판정하지 않고 재실행 결과로 판정(실패 → 회복 쌍이 생기지 않게).
- 카드 내용: 제목 `[euta] <실패|회복|통과|통과 · 불안정|건너뜀|중단> — <대상>` + 프로젝트 · 대상 · 환경 · 상태(건너뜀은 사유) · 실패 단계(첫 실패 단계의 단계 문장, 스위트는 `<스크립트> — <단계>`) · 소요 시간 · 예약 이름 · 재실행 회차 + "실행 보기" 링크(`<BASE_URL>/projects/:id/runs/:runId`, 웹 C4 경로). 오류 메시지·변수·테스트 계정 값·스크린샷·HAR 은 싣지 않는다.
- 재실행: 실패·오류·시간 초과로 끝난 예약 실행(첫 시도)이고 예약의 "실패 시 재실행"이 켜져 있으면 같은 고정 버전·환경·설정으로 1번 다시 등록(`attempt: 2`, `retryOfRunId`). 스위트는 스위트 전체를 다시. 재실행이 통과하면 그 실행이 `passed` + `flaky: true`. 중단·취소는 재실행하지 않는다. 실행 응답에 `attempt` · `retryOfRunId` · (상세) `retryRunId`.
- 예약 API: 본문 `{ name, scriptId | suiteId, environmentId?, cadence, timeLimitSec?, retryOnFailure?, enabled? }`. `cadence` = `{kind:'hourly',minute}` · `{kind:'daily',time:'HH:MM'}` · `{kind:'weekdays',time}` · `{kind:'weekly',dayOfWeek:0-6,time}` · `{kind:'cron',expression}` → 서버가 5필드 cron 으로 바꿔 저장. cron 은 숫자·`*`·범위·목록·간격과 월/요일 영문 약어만(초 필드·`H`·`L`·`W`·`#`·`?` 거절). 최소 간격 10분은 분·시 필드와 "연속으로 허용되는 날"을 계산해 정확히 판정(422). 환경 기본값 = 스위트 기본 → 프로젝트 기본(저장 때 정함). 응답에 `nextRunAt` · `intervalMin` · `lastRun` · `durationWarning`(최근 3회 평균 소요 > 최소 간격). 시간 제한 `null` = 회차 때의 프로젝트 기본값.
- 예약 회차: 지연 허용 5분 — 회차 시각보다 5분 넘게 늦게 처리되면 놓침. 놓친 회차가 여럿이어도 "건너뜀(놓침)" 1건(첫 놓친 시각), 마지막 회차가 5분 안이면 그 회차는 실행. 다시 켜거나 주기를 바꾸면 그 시각부터 다시 계산(꺼져 있던 동안은 놓침이 아님). 회차 때 사전 검사가 실패하면(스크립트·환경 삭제, 계정 누락 등) 실행하지 않고 `error` 실행 1건에 사유를 남긴다(알림 대상). 휴지통 → 예약 자동 꺼짐(`disabledReason: project_trashed`), **복원해도 다시 켜지 않는다**. 실행 행에 `scheduleId` · `scheduledFor` · `skipReason`(`overlap`·`missed`·`daily-cap`).
- 행위자: 예약 실행·재실행의 행위자 = "예약 — <만든 사람 이름>"(만들 때 이름을 저장해 탈퇴·제외 뒤에도 유지), 요청자 id = 만든 사람(계정 삭제 시 비움).
- 앱 알림 `GET /api/me/events`(SSE, 로그인·토큰): 내가 구성원(소유자·편집자)인 프로젝트의 예약 실행 알림(위 판정과 같은 종류, Teams 주소 유무와 무관) + 내가 요청한 클라우드 실행(웹·앱·MCP)의 종료(`run.finished`, 상태 무관). `event: notification`, data = `{ id, kind, at, projectId, runId, data: { projectName, target, environment, status, flaky, source, scheduleName?, failedStep?, durationMs, url } }`. 이어 받기 `Last-Event-ID` / `?lastEventId=`, 보관 7일(피드와 같음) 지난 위치면 `resync`. 로컬 올리기는 알림 없음.
- 로컬 실행 올리기 `POST /api/projects/:id/runs/upload?scriptPath=<클라우드 경로>&environmentId=<선택>&environmentName=<선택>`: 본문 = 엔진 실행 폴더 **내용**의 tar(맨 위에 `run.json`). 편집자 이상(`run.upload`). 러너 업로드와 같은 tar 검사·크기 상한(`RESULT_MAX_RUN`) → 422 `TAR_REJECTED`/413. `run.json` 없음·종료 상태 아님 → 422 `RUN_JSON_MISSING`/`RUN_JSON_INVALID`(저장한 파일 모두 삭제). run.json 의 상태·요약·단계·expect·소요 시간·시작/종료, `metrics.json` 지표로 **끝난 실행 1건**(출처 `local_upload`, 실행 위치 "PC — <이름>", 결과 파일 있음). 원문 해시(`scriptHash`)와 같은 클라우드 버전이 있으면 그 버전(가장 최근), 없으면 `localModified: true`. 작업 로그 `run.uploaded` + 피드. 하루 실행 상한·알림 대상 아님.
- 장치: 스크립트가 `browser.device` 를 정하지 않으면 프로젝트 기본 장치를 러너가 `--device` 로 넘긴다(엔진 `euta run --device`, ADR-024). C1 의 "장치 기본값은 넘기지 않는다" 를 대체.
- 하루 실행 상한: 위 [하루 실행 상한](#하루-실행-상한) 절 신설. 프로젝트 행 잠금 아래에서 세고 등록해 동시 요청도 상한을 넘지 않는다.
- 운영 메모: PoC 는 관리자 승인 모드(SMTP 미설정, PLAN 결정 "메일 발송")로 돈다 — 예약·알림 동작과 무관(알림은 메일을 쓰지 않음).


### 2026-10-20 — C1 실행·러너 구현 반영 (구현 세부 · 빈칸 채움)
- 실행 요청 본문: `{ scriptId | scriptPath | suiteId (하나만), environmentId?, vars?, timeLimitSec?, source? }`. 환경 기본값 = 스위트 기본 환경 → 프로젝트 기본 환경. 출처: 세션 요청은 `web`(기본)·`app`, 개인 토큰 요청은 항상 `ai_mcp`. `schedule`·`local_upload` 는 서버만 붙인다(C2·C3).
- 시간 제한: 초 단위, **최소 60초**·최대 24시간. 프로젝트 기본값은 새 프로젝트 필드 `runTimeLimitSec`(기본 21600, `PATCH /api/projects/:id` — 프로젝트 설정 편집 권한). 스위트는 **스크립트마다** 같은 제한을 적용한다.
- 녹화 값: 실행에 기록하는 값 = 스크립트 `record.video`·`trace`, 없으면 `on-failure`(엔진 `--cloud` 와 같은 규칙). 브라우저: 스크립트가 `browser.engine` 을 정하지 않으면 프로젝트 기본 엔진을 `--browser` 로 넘긴다. **장치(device) 기본값은 넘기지 않는다**(`euta run` 에 장치 옵션이 없음 — 남은 일).
- 사전 검사: 한 번에 모든 문제를 모은다. `POST …/runs` 는 422, `error.code` = 첫 문제의 코드(순서 `ENVIRONMENT_REQUIRED` → `SCRIPT_INVALID` → `OS_INPUT_NOT_ALLOWED` → `SECRET_PLACEMENT` → `CREDENTIALS_MISSING` → `TARGET_NOT_PUBLIC`), `error.details` = 전체 목록(`{ code, message, script?, issues?, names? }`). `ENVIRONMENT_REQUIRED`(환경 미지정·기본 환경 없음) 추가. `POST …/runs/precheck` 는 200 `{ ok, problems, environment, credentialNames, scripts }` — 등록하지 않음. 권한은 둘 다 실행 권한(편집자 이상). 스크립트 현재 버전이 검증 오류(출처 "앱 바깥 변경")면 `SCRIPT_INVALID`. 공개 주소 검사는 저장 때 값이 아니라 **요청 시점에 다시** DNS 로 확인.
- **개발 전용 `ALLOW_PRIVATE_TARGETS=true`**: 공개 주소 검사를 끈다(테스트·로컬에서 엔진 픽스처 사이트 `127.0.0.1`·`host.docker.internal` 대상). 기본 꺼짐, 배포 환경 금지. 서버가 켜져 있으면 시작 로그에 경고.
- 실행 상태: 문서의 "대기 → 실행 중" 사이에 내부 상태 `leased`(러너가 임대, 엔진 시작 전)를 둔다. 취소는 `queued` 면 200(즉시 `cancelled`), `leased·running` 이면 202(`stopRequested: cancel`, 러너가 그때까지 결과를 올린 뒤 `cancelled`). 끝난 실행 취소는 409 `RUN_FINISHED`.
- 스위트(화면 용어 테스트 세트): 부모 실행 1건 + 자식 스크립트 실행(순서대로, 실패해도 다음). 취소는 "항상 실행" 자식을 빼고 멈춘다(그 자식은 차례에 실행·실행 중이면 끝까지). 부모 상태 = 스위트 취소면 `cancelled`, 모두 통과면 `passed`, 아니면 `failed`. 목록 API 는 최상위 실행만, 상세에 `children`.
- 결과 보관: 결과 파일 30일 + 12Gi(오래 끝난 실행부터) → `resultFiles: expired`. DB 실행 기록(요약·단계·지표·expect)은 종료 1년 뒤 삭제.
- API: `GET …/runs` 필터 `status · target(스크립트 id·경로·스위트 id) · env(id·이름) · source · before(실행 id 커서) · limit`. `GET …/runs/:runId/files` → `{ resultFiles, files: [{ path, size }] }`. `GET …/runs/:runId/report` 는 `…/files/report.html` 로 302(리포트의 상대 링크가 동작하도록). 파일은 `nosniff`·CSP, 리포트 외 HTML 은 내려받기(`attachment`).
- 러너 프로토콜: 내부 API 는 **별도 포트**(`INTERNAL_PORT`, 기본 8081 — 클러스터 안 서비스만, ingress 에 두지 않음) + 러너 토큰(`RUNNER_TOKEN`, 없으면 모두 401). 경로는 표와 같고 추가로 `GET/PUT /internal/runs/:id/baselines`(기준 이미지 동기화, ADR-021) · `GET /internal/runs/:id/designs`(프로젝트 디자인 tar → 엔진 `--designs-dir`, C8 — [SPEC_디자인-검수](SPEC_디자인-검수.md#클라우드-c8)). 임대는 긴 폴링(`waitMs` ≤ 25초, `NOTIFY` 로 깨움). 응답에 스크립트 원문·환경(주소·변수·허용 도메인)·`vars`·브라우저·시간 제한·녹화 값·계정 이름·하트비트 주기.
- **임대 연장 주기 30초 → 하트비트 5초**(만료 2분은 그대로): 취소·시간 초과 신호가 이 응답으로 가므로 대기 스텝 중에도 수 초 안에 멈추도록.
- 시간 초과: 러너가 자기 타이머로, 서버도 정리 작업(15초 주기)으로 확인해 정지 요청 → 러너가 SIGTERM → 10초 뒤 SIGKILL(프로세스 그룹). 러너가 5분 더 응답하지 않으면 서버가 `timeout` 으로 닫는다.
- 테스트 계정 평문의 유일한 경로: `POST /internal/runs/:id/credentials`(내부 포트·러너 토큰·임대 보유 러너·실행당 1번) → 러너 임시 파일(0600, 엔진이 실행 폴더를 만드는 즉시 삭제). 이 응답은 로그에 남지 않는다. 그 밖의 DB·서버/러너 로그·결과 파일·공개 API 응답에는 평문 0건(테스트).
- 엔진 하위 프로세스 환경: `BASE_URL` + 환경 변수 + 실행에 필요한 최소 값(`PATH`·`HOME`·`TMPDIR`·`LANG`·`PLAYWRIGHT_BROWSERS_PATH`)만. 러너 자신의 환경(토큰·서버 주소)은 넘기지 않는다. 환경 변수 중 예약된 이름(`PATH`·`HOME`·`NODE_*`·`LD_*`·`PLAYWRIGHT_*`·`EUTA_*` 등)은 넘기지 않고 러너 로그에 이름만 경고.
- 휴지통 프로젝트의 대기 실행은 임대하지 않고 둔다(복원하면 진행). 대기 중 환경이 지워진 실행은 임대 때 `error`.
