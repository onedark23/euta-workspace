# SPEC - 스크립트 보기 · 편집 (앱 안)

> 상태: **구현 완료** (2026-10-02, 단계 10 — 엔진 단위·앱 단위·앱 E2E 개발·패키징본 통과, 구현 방식은 [ADR-018](ADR_018_스크립트-편집기-이력-구현.md)). 실사용 확인 대기. 결정 정본은 [PLAN 결정 사항](../20.프로젝트관리/PLAN_end-user-테스트툴-종합계획.md#결정-사항) "스크립트 보기·편집", "스크립트 저장·이력".
> 선행: [SPEC_test-script-dsl](SPEC_test-script-dsl.md)(형식) · [SPEC_프로젝트-관리](SPEC_프로젝트-관리.md)(라이브러리·작업 로그) · [SPEC_스크립트-작성-시연녹화](SPEC_스크립트-작성-시연녹화.md)(AI 정리).

## 목적

- 만들어진 스크립트를 **YAML 을 몰라도** 앱 안에서 읽고, 고치고, 되돌릴 수 있게 한다.
- 제공하는 것(사용자 결정): **읽기 쉬운 단계 보기** · **단계 단위 편집** · **AI 에게 수정 요청**. 저장은 **저장 버튼 + 변경 이력**.
- 범위 밖: 앱 안 YAML 텍스트 편집기(사용자 결정으로 제외 — 필요하면 기존 "기본 편집기로 열기"), 라이브 사이트에서 요소 골라 대상 지정(후속).

## 화면 — 스크립트 상세

스크립트 탭 목록에서 스크립트를 누르면 상세 화면이 열린다.

```
로그인 후 보고서 내보내기                         scripts/login-report.yaml
최근 실행: ✔ passed · dev · 10/02 18:20            [실행 ▾환경] [검증] [편집] [AI에게 수정 요청] [이력] [⋯ 기본 편집기로 열기]

 1  🌐 /login 으로 이동                                   ✔ 0.4s  🖼
 2  ⌨  '이메일' 입력란에 🔒USER_EMAIL 입력                 ✔
 3  ⌨  '비밀번호' 입력란에 🔒USER_PASSWORD 입력            ✔
 4  🖱  '로그인' 버튼 클릭                                 ✔
 5  ✅ 확인: 주소에 /dashboard 포함                       ✔
 6  📏 측정: Web Vitals · 스크린샷                         ✔
 7  📥 '내보내기' 클릭 → PDF 다운로드 확인                  ✖ 파일 없음   🖼
     └ 이름 *.pdf · 1kb 이상 · "월간 보고서" 포함
```

- **단계 문장**: 동작별 한국어 문장 규칙으로 보여 준다. 스텝 `name` 이 있으면 굵은 제목으로 위에, 문장은 아래에.
  - 대상: role+이름 → "'로그인' 버튼" · 라벨 → "'이메일' 입력란" · placeholder → "'검색' 칸" · 텍스트 → "'내보내기' 텍스트" · testId → "[submit-btn]" · CSS → "요소 `#email`" (불안정 표시 ⚠). `nth` 는 "n번째".
  - 값: `${secrets.X}` → 🔒X · `${vars.X}` → {X} · `${env.X}` → [X].
  - 공통 옵션은 작은 배지: 선택 단계 · 대기 시간 · OS 입력 · 화면 안정 조건 · 스크린샷 · 가림.
  - `group` 은 접고 펼 수 있는 묶음. `expect` 조건 여러 개는 줄마다.
- **최근 실행 결과 겹쳐 보기**: 이 스크립트의 가장 최근 실행(프로젝트 `runs/`)에서 단계별 상태·시간·오류·스크린샷을 붙인다.
  - 실행 당시 스크립트와 **지금 내용이 같을 때만** 겹친다(실행 기록에 스크립트 내용 해시를 남긴다). 다르면 "수정 이후 아직 실행하지 않음" 표시와 함께 결과를 흐리게 보여 준다.
  - 실패 단계는 오류 문장을 펼쳐 보이고, 스크린샷은 눌러 크게 본다. "Live 에서 보기" 링크.
- 상단 경고: 검증 오류, 선택한 환경에 없는 secret 이름(이름만), 불안정한 대상(CSS) 개수.

## 단계 단위 편집

- **[편집]** 을 누르면 같은 화면이 편집 모드가 된다(단계 카드마다 편집 손잡이).
- 동작:
  - 단계 누르면 **동작별 폼**: 대상 고르기(종류 선택 + 값, 예: 종류 "버튼" + 이름 "로그인"), 입력값(일반 값 / secret 이름 선택 / 변수), 확인 조건(종류별 입력), 측정 항목 체크, 공통 옵션(선택 단계·대기 시간·OS 입력 등), 스텝 이름.
  - **단계 추가**: 분류 메뉴(이동 · 클릭 · 입력 · 선택/체크 · 키 · 확인 · 측정 · 대기 · 다운로드 확인 · 시각 비교 · 묶음)에서 고르면 그 위치에 빈 폼.
  - 삭제 · 복제 · **순서 변경**(끌어서 옮기기 + 위/아래 버튼) · 묶음으로 넣기/빼기.
  - 스크립트 머리 정보: 이름, 설명, 기본값(대기 시간·화면 안정 조건·입력 방식), 녹화 설정, 변수(`vars`). 브라우저 설정.
    - 녹화 설정: `video` · `trace` · `dom`(단계별 화면 구조 — 선택자 점검용) 은 **켬 / 실패 시만 / 끔** 선택, `har` · `console` 은 켬/끔, 스크린샷은 단계마다 / 실패 시만 / 안 찍음. 값을 지정하지 않으면 엔진 기본값(모두 켬, 클라우드 실행은 video·trace·dom 실패 시만)을 따른다.
- 편집하는 동안 **실시간 검증**(기존 스키마 + 참조 검사). 오류는 해당 단계 카드와 상단에 표시.
- secret 은 **이름만** 고른다(환경에 등록된 이름 목록 + 새 이름 입력). 값은 이 화면에서 다루지 않는다(프로젝트 설정에서).
- 직렬화: 바뀐 부분만 다시 쓰고, 나머지는 원래 순서·주석을 가능한 한 보존한다.

## 저장과 변경 이력

- **[저장]** 은 검증을 통과할 때만 활성. 저장하면 파일을 원자적으로 교체하고 **직전 내용을 이력에 보관**한다.
- 저장하지 않고 화면을 떠나거나 프로젝트를 바꾸면 "저장하지 않은 변경" 확인.
- 편집 중 파일이 바깥에서 바뀌면(외부 편집기·AI) 알림 → "다시 불러오기"(내 변경 버림) 또는 "내 것으로 저장"(바깥 변경은 이력에 남음).
- **이력 대상**: 앱 편집기 저장(user) · AI `save_script`(ai) · 녹화 "AI 없이 저장"(recording) · 바깥에서 바뀐 것 감지(external) · 되돌리기(restore) · 이름 변경 · 삭제.
- **저장 구조**:
  ```
  projects/<projectId>/script-history/<scriptKey>/
    index.json                [{ version, at, actor, kind, path, hash, summary }]
    <version>.yaml            그 시점의 전체 내용 (원본 그대로)
  ```
  - `scriptKey` 는 스크립트마다 고정된 id — 이름을 바꿔도 이력이 이어진다. 스크립트당 최근 100개 보관.
  - 삭제한 스크립트는 마지막 내용이 이력에 남아, 스크립트 탭 "삭제된 스크립트" 에서 복원할 수 있다.
- **이력 화면**: 버전 목록(시각 · 누가 · 요약 "단계 2개 추가, 1개 변경") → 선택하면 **단계 문장 단위 비교**(추가 초록 · 삭제 빨강 · 변경 전후) → **이 버전으로 되돌리기**(현재 내용도 이력에 남긴 뒤 교체).
- 작업 로그: `script.changed`(행위자·요약) · `script.restored` · 기존 `script.renamed/deleted`.

## AI 에게 수정 요청

- 상세 화면 **[AI에게 수정 요청]** 과 각 단계의 **"이 단계에 대해 AI에게"** — 입력창에 요청을 쓰면(예: "이 단계 다음에 합계 1,200원 확인 추가해줘") 그 프로젝트 AI 채팅을 새로 열고 요청을 보낸다.
  - AI 에게 함께 주는 것: 스크립트 경로, (단계 요청이면) 단계 번호·문장, 현재 선택 환경.
  - 지침: `read_file` 로 읽고 → 고친 뒤 `save_script` 로 저장(이력 actor = ai) → `validate_script` → 필요하면 `run_script` 로 확인 → 바꾼 점을 단계 문장으로 보고.
- AI 가 저장하면 열려 있는 상세 화면이 갱신되고 "AI 가 수정함 — 변경 보기" 배너(이력 비교로 연결). 편집 중이었다면 위 "바깥에서 바뀜" 규칙을 따른다.

## 공통 모듈

- **단계 문장 생성기**는 엔진 core 에 둔다(`describeStep` 류, 한국어) — 앱 상세·이력 비교가 쓰고, 이후 리포트·MCP 결과에도 쓸 수 있게.
- 실행 기록에 스크립트 내용 해시를 남긴다(엔진 실행 옵션 `meta` 또는 run.json 필드 — 구현 시 ADR).

## 구현 세부 (구현 중 확정 — 제품 결정 변경 없음)

- **이력 버전 = 그 시점의 내용 스냅샷**: 쓰기마다 "쓴 뒤 내용"을 행위자와 함께 새 버전으로 남긴다. 쓰기 직전 디스크 내용이 마지막 버전과 다르면(앱이 모르는 사이 바뀜) 먼저 `external` 버전으로 남긴 뒤 쓴다 — 이렇게 "직전 내용"은 항상 이력에 있다. 상세 화면을 열 때도 같은 확인을 한다(앱이 꺼져 있는 동안 바뀐 것까지 잡힘).
- **저장 구조 보강**: `script-history/keys.json` 이 경로 → `scriptKey` 지도와 삭제된 스크립트 목록을 가진다. `<scriptKey>/index.json` 은 위 배열 그대로.
- **행위자**: `user`(앱 편집기·생성·가져오기·이름 변경·삭제) · `ai`(AI `save_script`, AI 대화 중 감지된 바깥 변경) · `recording`(녹화 "AI 없이 저장") · `external`(바깥에서 바뀐 것) · `restore`(되돌리기·삭제 복원). 버전마다 종류(`baseline` 처음 기록 · `create` · `save` · `external` · `restore` · `rename` · `delete` · `undelete`)도 남긴다.
- **바깥 이름 변경**: 감시자가 본 "없어진 파일 + 새 파일"의 내용 해시가 같으면 이름 변경으로 보고 이력을 잇는다. 아니면 삭제 + 새 스크립트.
- **실행 기록 해시**: 엔진이 실행한 원문 그대로의 sha256 을 `run.json` 최상위 `scriptHash` 로 남긴다(앱 `meta` 가 아니라 엔진 필드 — 실제로 실행한 내용과 같아야 하므로). 해시가 없는 예전 실행은 "다름" 으로 본다.
- **저장 가능 조건**: 구조 검증 + `vars` 참조 오류가 없을 것. 선택한 환경에 없는 secret 이름은 **경고**(저장 막지 않음 — 새 이름을 먼저 쓰고 나중에 등록할 수 있게).
- **비교의 "변경"**: 연속한 삭제·추가 안에서 같은 동작·같은 깊이의 단계끼리만 "변경(전→후)" 으로 짝짓는다. 다른 동작이면 삭제 + 추가로 보인다.
- **직렬화**: 바뀌지 않은 키·단계는 원문 바이트 그대로, 바뀐 단계는 그 단계만 다시 쓴다(위쪽 주석 줄은 유지). 흐름 스타일 `steps: [...]` 같은 드문 배치는 주석은 지키되 서식이 정리될 수 있다.
- **묶음 넣기/빼기**: 넣기 = 바로 위 단계가 묶음이면 그 끝으로, 아니면 새 묶음("새 묶음")으로 감싼다. 빼기 = 묶음 바로 아래로. 끌어서 옮기기는 같은 목록 안에서(묶음 넘나들기는 넣기/빼기).
- **검증 문장**: 시간·크기 형식 오류는 한국어로("시간 형식이 아닙니다 (예: 500, 2s, 1m)"). 오류는 상단에 "n번 단계: …" 로, 카드에 필드별로.
- **최근 실행 찾기**: 같은 파일 경로의 최신 실행. 이름을 바꾸기 전 실행은 겹치지 않는다. 상세 화면의 [실행] 은 그 자리에서 실행하고 끝나면 겹치기를 새로 그린다.
- **저장하지 않은 변경 확인**: 목록으로 돌아가기 · 다른 스크립트 열기 · 프로젝트 바꾸기 · 앱 설정/새 프로젝트로 가기. 탭 전환은 화면이 그대로 유지되므로 묻지 않는다.

## 완료 기준 (검증)

- 엔진 단위: 단계 문장 생성(모든 동작·대상 종류·값 표기·공통 옵션·묶음·여러 조건), 실행 기록의 스크립트 해시.
- 앱 단위: 편집 모델(추가·삭제·복제·순서 변경·묶음 넣기/빼기·머리 정보) → 직렬화 결과가 스키마 통과 + 바뀌지 않은 부분의 주석·순서 보존, 이력(저장·외부 변경 감지·AI 저장·녹화 저장·되돌리기·이름 변경 후 이어짐·삭제 후 복원·100개 보관), 단계 비교 요약, 최근 실행 겹치기(해시 같음/다름).
- 앱 E2E(개발·패키징본): 스크립트 상세(단계 문장·최근 실행 겹치기·스크린샷) → 편집(값 변경·단계 추가·순서 변경·삭제) → 검증 오류 시 저장 불가 → 저장 → 실행 통과 → 이력 비교 → 되돌리기 → "AI에게 수정 요청"(가짜 에이전트가 `read_file`·`save_script`) → 배너·이력 actor ai → 외부 변경 감지 알림 → 앱 재시작 후 이력 유지.
- 실제 모델 호출 없음.
