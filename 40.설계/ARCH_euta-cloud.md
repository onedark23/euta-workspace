# ARCH - euta cloud 아키텍처

> 상태: **작성 중 (C0)** — 절마다 하나씩 채운다. `작성 예정` 절은 열린 결정이 정해지면 채운다.
> 확정 결정은 [PLAN_euta-cloud 결정 사항](../20.프로젝트관리/PLAN_euta-cloud.md#결정-사항) 이 정본. 이 문서는 그 결정을 구성 요소·데이터·흐름으로 풀어낸다. 구현 세부는 `40.설계/ADR_*` 로 기록한다.
> 로컬 앱·엔진 구조: [ARCH_end-user-테스트툴](ARCH_end-user-테스트툴.md)

## 한눈에 보기

```
 구성원 PC                                   euta cloud (euta-cloud 레포)
 ┌──────────────────────────┐               ┌──────────────────────────────────────────────┐
 │ euta-app (로컬 앱)        │  HTTPS API    │ 서버                                          │
 │  로컬 전용 프로젝트        │◀────────────▶│  인증(인가 서버) · 프로젝트·구성원·권한         │
 │  클라우드 프로젝트 작업 사본│  실시간 수신  │  스크립트·버전 · 환경·테스트 계정(암호화)       │
 │  엔진 내장(로컬 실행)      │               │  실행 요청·예약 · 실행 색인 · 작업 로그         │
 └──────────────────────────┘               │  원격 MCP (HTTP) — 공용 도구 핸들러             │
 ┌──────────────────────────┐               └───────┬───────────────────────┬──────────────┘
 │ 브라우저 (웹)              │◀──── HTTPS ─────────┘                       │ 실행 지시
 │  현황·이력·리포트·폼 편집   │                                             ▼
 └──────────────────────────┘               ┌──────────────────────────────────────────────┐
 ┌──────────────────────────┐               │ 러너 — euta-engine headless (Playwright 컨테이너) │
 │ 본인 Claude (구독)         │── MCP ──▶ 서버 │  공개 URL 로만 대상 접속 → 결과 폴더            │
 │  claude.ai · Desktop · Code│               └───────────────────────┬──────────────────────┘
 └──────────────────────────┘                                       ▼
                                             저장: DB(메타·색인·버전·대기열) · 결과 파일(서버 PVC)
```

- 서버 안에는 AI 가 없다. AI 는 구성원 각자의 Claude 가 원격 MCP 로 서버 도구를 쓰는 형태로만 붙는다.
- 러너는 대상 서비스에 사용자와 같은 길(공개 URL · 브라우저)로만 접근한다.

## 레포와 책임

| 레포 | 책임 |
|---|---|
| `euta-cloud` (신규) | 서버(API·인증·스케줄러·원격 MCP) · 웹 · 러너. pnpm 워크스페이스 `shared` · `server`(Fastify, 웹 정적 파일 동봉) · `runner` · `web`(React+Vite) — [ADR-019](ADR_019_클라우드-레포-구성-서버-스택.md) |
| `euta-engine` | 변경 최소 — 클라우드 실행 옵션(`input: os` 거절·녹화 기본값), DSL 보완 2건(`record` 실패 시 보관 · `wait` 새로고침 대기, [엔진 보완](#엔진-보완-dsl-spec-갱신-후-구현)), 결과 업로드용 경로 정리, MCP 서버 HTTP transport. `euta-cloud` 는 엔진을 `link:` 의존으로 import |
| `euta-app` | 프로젝트 저장소가 "로컬 / 클라우드" 두 종류가 됨 — 클라우드 연결·로그인, 작업 사본, 충돌 처리, 실행 위임 UI ([동기화](#동기화)) |

- 의존 방향: `cloud → engine`, `app → engine`, `app → cloud(API)`. 엔진은 여전히 아무것도 모른다.

## 인증·권한

### 로그인

- **회사 Microsoft 계정(Entra ID) 로그인** (PLAN 결정 "로그인" 2026-10-30, 사내 도구에서 흔한 방식). 회사 테넌트 OIDC — 처음 로그인이 곧 가입이고 바로 사용. 회사 테넌트 계정이면서 허용 도메인(`ALLOWED_EMAIL_DOMAINS`, 필수 설정 — 사내 배포는 회사 도메인)인 메일만 받는다.
- 이메일·비밀번호는 **기존 이메일 회원 로그인**으로만 남는다(새 가입 닫힘). 같은 메일의 기존 계정은 Microsoft 로그인 때 그 계정에 연결된다 — 메일 미인증 계정이면 그때 비밀번호를 지운다(관리자 제외).
- Entra 설정(테넌트·클라이언트)이 없으면 이전 방식(이메일 가입 + 관리자 승인)으로 동작한다 — 앱 등록 전 dev · 로컬 개발·테스트용.
- **euta cloud 가 OAuth 인가 서버**다. 웹·로컬 앱·MCP 커넥터는 모두 euta cloud 가 발급한 토큰을 쓴다.

```
[사람 확인]  Microsoft(Entra ID, 회사 테넌트) — 주     ·  이메일·비밀번호 — 기존 회원만
      │  "이 사람이 누구인가" 만 확인 (교체 지점)
      ▼
[euta cloud 인가 서버]  토큰 발급·갱신·폐기 — 이 아래는 로그인 방법이 바뀌어도 그대로
      ├─ 웹: 로그인 후 세션
      ├─ 로컬 앱: 장치 인가(RFC 8628) — 앱이 코드 요청 → 브라우저에서 승인(이때 Microsoft 로그인) → 앱이 토큰 수신
      └─ MCP: 계정별 개인 토큰(웹에서 발급, scope read / write) — Bearer 헤더
```

- 교체 지점은 "사람 확인" 하나로 좁힌다. 사용자 개체는 이메일을 기준으로 외부 계정(Entra)과 연결한다.
- 비밀번호는 해시만 저장한다. 인증 계층은 Better Auth — [ADR-023](ADR_023_클라우드-인증-구현.md), Microsoft 로그인 구현 세부 [ADR-043](ADR_043_Microsoft-로그인-구현.md). 프로젝트 역할 판정은 서버 자체 권한 모듈.

### 권한

- **조직**: 가입한 회사 도메인 사용자는 모두 같은 조직 구성원. 관리자(서버 설정 `ADMIN_EMAILS`) — 가입 승인(이메일 가입 모드일 때만) · 구성원 비활성화 · **소유자가 모두 비활성인 프로젝트의 새 소유자 지정**. 관리자라도 프로젝트 내용을 보거나 고치는 특권은 없다(공개 범위·역할을 그대로 따름).
- **프로젝트 공개 범위**(프로젝트마다, 소유자가 정함): **조직 공개**(기본 — 조직 구성원은 초대 없이 "보기", 받기 목록에 나옴) / **구성원만**(초대받은 사람만 보고 받음, 그 밖에는 목록·직접 주소 모두 404).
- **프로젝트 출생 기록**(서버가 만들 때 남기고 바꿀 수 없음): 출처 `web`(웹 "새 프로젝트") / `app`(앱 "클라우드로 올리기" — 로컬 프로젝트 id) · 만든 계정 · 시각. 옛 프로젝트는 `unknown`. 앱의 "합치기"는 **출처 `app` + 로컬 id 일치 + 요청자가 소유자** 일 때만 서버가 받는다(`unknown` 은 소유자 + 앱의 로컬 연결 기록 id 일치 시 1회 허용 후 기록 채움). 웹 출생 프로젝트는 받기만.

|---|---|---|---|---|
| 현황·이력·리포트 보기 · 받기(작업 사본) | ✅ | ✅ | ✅ | ✅ |
| 실행 · 테스트 세트 실행 · 실행 취소 | ✅ | ✅ | ✅ | ❌ |
| 로컬 실행 올리기 | ✅ | ✅ | ✅ | ❌ |
| 예약 만들기·고치기·켜고 끄기 | ✅ | ✅ | ❌ | ❌ |
| 스크립트 · 테스트 세트 · 환경(주소·변수·허용 도메인) 편집 | ✅ | ✅ | ❌ | ❌ |
| 테스트 계정 입력 (값은 아무도 다시 못 봄 — 실행자는 실행 때 쓰기만) | ✅ | ✅ | ❌ | ❌ |
| 프로젝트 설정 (기본 정보·알림·테스트 규칙·하루 상한·기본 환경) | ✅ | ✅ | ❌ | ❌ |
| 구성원 초대 · 역할 변경 · 내보내기 · 권한 요청 승인/거절 | ✅ | ❌ | ❌ | ❌ |
| 공개 범위 변경 · 소유권 이전 · 삭제·복원 · 합치기 | ✅ | ❌ | ❌ | ❌ |
| 권한 요청 · 나가기 | — | ✅ | ✅ | ✅ (조직 공개 프로젝트) |

- 소유자는 최소 1명(마지막 소유자는 내보내기·낮추기·나가기 불가 — 먼저 이전).
- 보기 역할은 실행할 수 없다 — 실행은 실제 부작용(업로드·크레딧·게시)이 있다. 실행자는 부작용이 있는 실행은 하되 스크립트·계정·설정은 못 바꾼다.
- 권한 판정은 서버 한 곳에서 한다. 웹·로컬 앱·MCP 모두 같은 판정을 거친다.
- **MCP 는 토큰 주인의 역할을 그대로 따른다.** 토큰 scope(`read`/`write`)와 프로젝트 역할 중 좁은 쪽 — 실행자 + `write` 토큰 = 실행 도구까지, 저장 도구는 거절.
- 권한 변경(초대·역할 변경·내보내기·요청·승인·거절·나가기·이전·공개 범위·관리자 지정)은 프로젝트 작업 로그에 행위자와 함께 남는다.

## 동기화

클라우드 공유 프로젝트는 **클라우드가 정본, 로컬 앱은 작업 사본**이다. 로컬 전용 프로젝트는 지금과 같다(동기화 없음).

### 무엇을 어디서 바꾸나

| 대상 | 온라인 | 오프라인 |
|---|---|---|
| 스크립트 편집 | 저장 즉시 서버로 | 로컬에 "보내기 대기" 로 쌓고, 재연결 시 순서대로 전송 |
| 로컬 실행 | 가능 · 골라서 올리기 | 가능 · 올리기는 재연결 후 |
| 환경 · 테스트 계정 · 스위트 · 예약 · 구성원 | 서버에 바로 반영 | 불가 (읽기만) |

### 저장과 충돌

- 스크립트 저장 요청에는 **기준 버전**(내가 편집을 시작한 버전)을 함께 보낸다.
- 서버의 현재 버전이 기준 버전과 같으면 새 버전으로 저장한다.
- 다르면(그사이 다른 사람이 저장) **충돌** — 저장하지 않고 앱이 지금의 단계 문장 비교 화면을 띄운다. 사용자는 셋 중 하나를 고른다.
  1. 내 것으로 새 버전 (서버 최신 위에 덮기, 이전 버전은 이력에 남음)
  2. 서버 것 받기 (내 변경 버림)
  3. 내 것을 사본 스크립트로 저장
- 잠금은 두지 않는다. 오프라인 대기분도 재연결 시 같은 규칙으로 처리한다.
- 외부 편집기로 고친 변경은 지금처럼 감지해 로컬 저장과 같은 흐름을 탄다.
- 로컬 앱의 스크립트 쓰기 한 경로(`writeScript` — 충돌 검사·버전 기록·작업 로그)를 클라우드 프로젝트에선 서버 저장으로 연결한다 (ARCH 로컬 "앱 구성").

### 변경 받기

- 프로젝트를 열고 있는 동안 서버 변경을 **실시간으로 받는다** — 다른 사람의 저장 · 실행 시작/종료 · 설정 변경. 전송은 SSE + 변경 순번(재연결 시 이어 받기) — [ADR-022](ADR_022_클라우드-실시간-전송.md).
- 다시 연결되면 마지막으로 받은 시점 이후 변경을 한 번에 받는다.
- 변경 이력은 서버가 보관하고 행위자(구성원)를 기록한다. 앱의 이력·비교·되돌리기 화면은 그대로 쓴다.

### 실행 결과 가져오기

- 클라우드 실행의 **요약**(상태 · 단계 · 지표 · expect 결과)은 바로 받아 History 에 보인다.
- **스크린샷 · 영상 · trace · HAR** 는 사용자가 그 실행을 열 때 받는다(로컬 캐시).
- 엔진 결과 폴더 형식이 같으므로 받은 실행은 지금의 History · 리포트 · 재생으로 그대로 본다. 실행에는 출처(클라우드/로컬)와 실행 위치를 표시한다.
- 디자인 비교가 있는 실행은 받은 뒤 앱에서 AI 검수를 돌릴 수 있고, 검수 결과는 로컬(`design-reviews/`)과 서버(그 실행) 양쪽에 둔다 — [SPEC_디자인-검수](SPEC_디자인-검수.md#클라우드-c8).

## 실행 위임 · 러너

### 실행 흐름

```
요청 — 앱(클라우드에서 실행) · 웹 · 예약 · MCP
  │
  ▼
서버: 권한 확인 → 사전 검사 → 실행 등록(대기)
  │
  ▼
러너: 대기열에서 임대 → 실행 시작 시점에 테스트 계정 받음 → 엔진 하위 프로세스(`euta run`, 새 임시 폴더·새 브라우저)
  │   단계 이벤트를 서버로 실시간 전달 → 웹·앱 진행 표시(현재 단계 · 경과 시간)
  │   실행 중 주기적으로 임대 연장(생존 신호)
  ▼
종료: 결과 폴더 → 서버로 업로드(결과 파일 저장소) · 요약 → DB · 임시 폴더 삭제 → 알림 판정
```

- 러너는 **상주 프로세스 + DB 대기열**이다. 실행 하나마다 엔진을 별도 하위 프로세스로 띄워, 한 실행이 죽어도 다른 실행에 번지지 않는다.
- 러너는 인터페이스 뒤에 둔다 — "실행 1건 = 컨테이너 1개" 방식으로 바꿔도 서버는 그대로.
- 러너가 죽어 임대가 만료되면 그 실행은 "중단"으로 기록한다. 중간부터 이어 돌리지 않는다.

### 사전 검사

앱이 맡기기 전에 한 번, 서버가 등록 전에 다시 한 번(서버 판정이 정본).

| 검사 | 실패 시 |
|---|---|
| `input: os` 스텝 | 거절 — "클라우드에서는 OS 입력을 쓸 수 없음" |
| 대상 주소가 공개 주소인지 (환경 주소의 호스트가 사설 IP·사내 주소로 풀리면 거절) | 거절 — "클라우드에서 접속할 수 없는 주소" |
| 스크립트가 쓰는 테스트 계정이 환경에 등록됐는지 | 거절 — 없는 이름 표시 |
| 스크립트 검증(DSL 스키마) | 거절 — 검증 오류 표시 |

### 예약

- **서버 내장 스케줄러.** 시각이 되면 실행을 대기열에 **등록만** 하고, 실행은 러너가 맡는다. 서버가 여러 대여도 DB 잠금으로 한 곳만 등록한다.
- 주기: 화면은 프리셋(매시간 · 매일 HH:MM · 평일 HH:MM · 직접 입력), 내부는 cron 식. 시간대 Asia/Seoul.
- **놓친 회차**(서버 중단)와 **겹친 회차**(같은 예약의 이전 회차가 아직 실행 중)는 몰아 돌리지 않고 "건너뜀"으로 기록한다.
- 예약 화면은 최근 실행 시간이 예약 간격보다 길면 경고한다.

### 실행 운영 규칙

| 항목 | 규칙 |
|---|---|
| 시간 제한 | 스크립트·예약별 설정. 기본 6시간, 상한 24시간. 넘으면 강제 종료 → "시간 초과" |
| 멈춤 판정 | 러너 생존(임대 연장)과 엔진 하위 프로세스·브라우저 생존만 본다. **진행이 없다는 이유로 끊지 않는다** — 수 시간 대기는 정상일 수 있다(오래 기다리는 스텝은 DSL 스텝 `timeout` 으로 표현) |
| 동시 실행 | **같은 테스트 계정은 한 번에 1개**(같은 계정 동시 로그인은 세션 충돌). 러너당 상한은 설정값(기본 4 — 대기 중엔 CPU 보다 메모리가 제약. dev 는 2 — [배포·운영](#배포--운영)). 나머지는 대기 |
| 재시도 | 기본 없음. 예약 옵션 "실패 시 1회 재실행" — 재실행이 통과하면 결과를 "불안정"으로 표시 |
| 녹화 | 클라우드 실행 기본은 **실패 시에만 영상·trace 보관**(스크립트에 명시하면 그 값). 스크린샷·지표·콘솔·네트워크는 그대로 |
| 배포·재시작 | 러너는 종료 신호를 받으면 새 실행을 받지 않고 돌던 실행이 끝날 때까지 기다린다. 강제 종료되면 "중단" |
| 실행 위치 | 실행 기록에 러너 위치를 남긴다. 체감 지표 추이·시각 비교 기준 이미지는 실행 위치별로 따로 |

### 알림

- **Teams webhook(프로젝트별 URL) + 앱 알림.**
- 보내는 때: 실패 · 회복(실패 → 통과). 연속 실패는 처음 1번만. 건너뜀·중단은 알림 없이 기록(설정으로 켤 수 있게 — SPEC 에서 확정).
- 내용: 프로젝트 · 스크립트 · 환경 · 실패 단계 · 웹 실행 화면 링크. 테스트 계정 값·스크린샷은 싣지 않는다.

### 엔진 보완 (DSL SPEC 갱신 후 구현)

| 보완 | 내용 | 이유 |
|---|---|---|
| `record` 실패 시에만 보관 | `video` · `trace` 에 "실패 시에만 남김" 값 추가(실행 중 기록, 통과하면 삭제) | 수 시간짜리 실행의 영상·trace 용량 |
| `wait` 새로고침하며 기다리기 | `wait.for` 조건을 확인하다가 지정 간격마다 페이지를 새로고침(예: `reload: 5m`), 스텝 `timeout` 까지 | 화면이 자동 갱신되지 않는 서비스에서 실제 사용자처럼 새로고침하며 완료 확인 |
| 클라우드 실행 옵션 | `input: os` 거절 · 녹화 기본값 덮어쓰기 · **secrets 사용 위치 제한**(`fill`·`type` 값만) · **허용 도메인**(secrets 입력 스텝은 허용 도메인 페이지에서만) | 사전 검사 · 클라우드 기본 녹화 · AI·스크립트를 통한 테스트 계정 외부 유출 차단([SPEC_클라우드-MCP 보안](SPEC_클라우드-MCP.md)) |
| 시간 단위 `h` | `1h` 표기 | 수 시간 대기 스텝 |

- 구현 세부: DB·대기열·예약 [ADR-020](ADR_020_클라우드-DB-대기열-예약.md) · 결과 파일 저장 [ADR-021](ADR_021_클라우드-결과-파일-저장.md) · 실시간 전송 [ADR-022](ADR_022_클라우드-실시간-전송.md).

## 원격 MCP 커넥터

구성원이 **자기 Claude**(본인 구독)에 euta cloud 를 커넥터로 붙여, AI 가 클라우드 프로젝트를 읽고·고치고·실행한다. 서버는 AI 를 품지 않고 도구만 제공한다.

### 도구

- 서버가 **Streamable HTTP** MCP(`/mcp`, 무상태)로 도구를 노출한다. SSE 전송은 쓰지 않는다(Claude Code 문서상 폐기 예정). 도구 이름·입력 모양은 엔진 MCP 도구(ADR-008)와 맞추되, 엔진 도구 핸들러(로컬 실행 폴더·secrets 파일에 묶임)는 재사용하지 않고 서버 서비스(REST 와 같은 권한·작업 로그·실행 요청) 위에 다시 정의했다 — 엔진에서는 `@euta/core` 의 스키마·단계 문장·사전 검사만 쓴다([ADR-028](ADR_028_클라우드-MCP-구현.md)).
- 로컬 파일 대신 클라우드 프로젝트를 대상으로 한다 — 프로젝트·스크립트 목록, 스크립트 읽기·저장(저장은 [동기화](#동기화)의 충돌 규칙 그대로, 작성자 = 연결한 구성원, 출처 = AI), 검증, 실행 요청·예약, 실행 결과·스크린샷·지표 조회.
- 탐색형 도구(브라우저 세션을 열고 한 스텝씩 조작)는 러너 자원을 오래 잡으므로 1차에서는 제외 — SPEC 에서 확정.
- 테스트 계정 값은 어떤 도구로도 돌려주지 않는다(이름만).

### 연결 방식 — 계정별 개인 토큰 + 사내망

```
웹 "내 설정 > 토큰" 에서 발급 (이름 · scope read/write · 만료) → 원문 1번만 표시
        │
        ▼
구성원 PC 의 Claude (사내망·VPN)
  ├─ Claude Code:  claude mcp add --transport http euta https://<euta cloud>/mcp \
  │                  --header "Authorization: Bearer euta_…"
  ├─ euta-claude-plugin: skill(cloud-test-script) + README 의 claude mcp add 안내 (서버는 선택 — ADR-028 §6)
  └─ Claude Desktop 로컬 설정(중계 도구 경유) — 가능 여부는 C5 에서 확인
        │  MCP 요청은 구성원 PC 에서 출발 → 사내 주소로 접속 (인터넷 공개 없음)
        ▼
euta cloud /mcp — 토큰 해시 조회 → 토큰 주인·scope 확인 → 권한 판정
```

| 항목 | 규칙 |
|---|---|
| 형식 | 접두사 `euta_` + 무작위 값(유출 탐지·식별용 접두사) |
| 보관 | 서버는 해시만 저장. 원문은 발급 화면에서 1번만 보여 줌 |
| 만료 | 필수. 기본 90일, 최대 1년 — 값은 SPEC 에서 확정 |
| 관리 | 목록(이름·scope·만료·마지막 사용 시각) · 폐기. 계정 비활성화 시 그 계정의 토큰 전부 무효 |
| 권한 | 토큰 scope 와 토큰 주인의 프로젝트 역할 중 좁은 쪽 ([권한](#권한)) |
| 행위자 기록 | MCP 로 한 저장·실행은 토큰 주인 + 출처 "AI" 로 작업 로그·스크립트 이력에 남김 |

- 사람 로그인 방법(자체 가입 → 2026-10-30 Microsoft 로그인)이 바뀌어도 개인 토큰은 그대로 쓴다.
- **1차 제외 — claude.ai·Desktop "커넥터" 메뉴.** 이 경로는 Anthropic 클라우드(`160.79.104.0/21`)에서 접속하므로 MCP 경로를 인터넷에 공개해야 하고, Team 요금제는 조직 Owner 가 먼저 추가해야 한다(2026-10-20 공식 문서 확인). 필요해지면 MCP 경로만 공개 + Anthropic IP 허용 목록 + OAuth(동적 클라이언트 등록 · PKCE S256 · 콜백 `https://claude.ai/api/mcp/auth_callback`)를 추가한다. 인가 서버 구조라 개인 토큰과 함께 둘 수 있다.

## 보안

- **테스트 계정**: 암호화 저장 · 쓰기 전용(API 는 이름만) · 러너에만 실행 시점에 전달 · 로그·리포트는 엔진 `${secrets.*}` 마스킹 재사용. 민감 계정은 영상·trace 끔(ADR-006).
- **사용자 비밀번호**: 해시만 저장.
- **토큰**: 웹·로컬 앱 토큰은 짧은 수명 + 갱신 토큰, 폐기 가능. 로컬 앱은 OS 보안 저장소에 보관([ADR-023](ADR_023_클라우드-인증-구현.md)). **MCP 개인 토큰**은 해시만 저장 · 만료 필수 · 폐기 · 마지막 사용 시각 ([원격 MCP 커넥터](#원격-mcp-커넥터)).
- **노출 범위**: 1차는 사내망·VPN 전용 — 인터넷 공개 없음.
- 그 밖(전송 구간·감사 로그 등)은 *작성 예정*.

## 배포 · 운영

- **개발**: C1~C3 은 docker compose 로 로컬에서(서버 · 러너 · DB · 가짜 SMTP).
- **dev 배포**: 사내 공용 k8s 클러스터(노드 x86_64)의 네임스페이스 하나 · 이미지는 사내 레지스트리(풀 시크릿, **linux/amd64 로 빌드**) · ingress + TLS, 정식 호스트 이름 `https://<euta cloud>`. 클러스터에서 인터넷 접속 확인(러너가 공개 대상에 닿음). 실제 값은 사내 배포 설정(별도 비공개 저장소).
- **이름 해석**: 외부 DNS 에 정식 호스트 이름을 공용 ingress 공인 IP 로 등록(2026-10-30). 사내 DNS 도 같은 값을 답한다. 클러스터 안(러너 → 서버)은 Service 주소. ingress 는 Host 이름으로 서비스를 고르므로 IP 로 직접 열면 404 다. (2026-10-21~30 은 PC 마다 `/etc/hosts` 에 ingress 내부 주소로 대신 — 이제 지운다.)
- **접속 제한**(선택): 공용 ingress 가 인터넷에 열려 있으면 ingress `whitelist-source-range` 로 허용할 공인 IP(예: 사무실)만 받는다. 켜면 그 밖의 망(재택·모바일 데이터망)에서는 앱 클라우드 연결·업데이트를 포함해 403 이고, 내부 주소로 직접 붙으면 사설 주소로 보여 403 이다. 러너 → 서버는 클러스터 안 Service 라 무관.
- **배포 방식**: 매니페스트는 **사내 배포 설정**(별도 비공개 저장소)의 `k8s/dev/`(kustomize — ArgoCD App Path `k8s/dev`)에 둔다. 공개 소스 `euta-cloud` 에는 회사 값 없는 예시 `k8s/example/` 만 있다(2026-11-05, ADR-045). 1차는 이 폴더를 `kubectl apply -k` 로 직접 적용(원격 Git 저장소 없이 가능). 서버 비밀(세션 서명 키·테스트 계정 암호화 키·러너 토큰·DB 비밀번호)은 배포 때 생성해 k8s Secret 으로만 넣고 저장소에 두지 않는다. ArgoCD(GitOps)는 원격 Git 저장소가 생기면 같은 매니페스트로 전환(Path `k8s/dev`, 앱 Secret 은 Git 밖 — `create-secrets.sh` 로 1회 생성). 서버·러너는 둘 다 Recreate — 새 pod 를 먼저 띄우면 요청 합이 한도를 넘는다. 러너 pod 종료 때는 돌던 실행을 30분까지 기다리고, 그 뒤 남은 실행은 임대 만료로 `aborted`.
- **한도(크기 S)**: pod 20 · CPU 요청 2 · 메모리 요청 4Gi · 저장소 20Gi. 컨테이너 기본값 요청 100m/128Mi · 제한 1/1Gi 라 러너는 명시 설정이 필요하다. 배분 초안:

| 구성 | CPU 요청 | 메모리 요청 | 저장소 | 비고 |
|---|---|---|---|---|
| 서버(API·웹·스케줄러·MCP) | 0.2 | 384Mi | 14Gi | 결과 파일 저장소 겸함(PVC, [ADR-021](ADR_021_클라우드-결과-파일-저장.md)) |
| DB | 0.2 | 512Mi | 5Gi | |
| 러너 1개 | 1.0 | 2Gi | — | **dev 동시 실행 2**(기본 4 대신, 메모리 한도) · 제한은 요청보다 크게 |
| 여유 | 0.6 | ~1.1Gi | 1Gi | 임시 작업·배포 교체 |

- **결과 보관 기간**: 저장소 20Gi 안에서 돌려야 하므로 결과 파일(스크린샷·실패 영상·trace·HAR)은 기간·용량 기준으로 지우고, 요약·지표·색인은 남긴다. 기간 값은 SPEC 에서 정한다.
- **비공개 저장소 push**: ArgoCD 전환 때만 필요. push 시점은 사용자 확인 후. 1차 직접 적용에는 필요 없다.
- **앱 업데이트 배포**(단계 17): 서버 볼륨 `/data/updates/<채널>/<버전>/`(`UPDATES_DIR`)에 앱 설치·업데이트 파일(채널별 최근 3개, 결과 파일 상한과 별도, 목록은 DB `app_releases`) · 공개 경로 `/updates/<채널>/…` + `/api/app/releases` · 올리기는 관리자 읽기·쓰기 토큰, 큰 본문은 `/api/admin/app-releases` 전용 두 번째 Ingress(1g · 버퍼링 끔 · 같은 IP 허용 목록, [ADR-041](ADR_041_앱-업데이트-배포-클라우드-구현.md)) · `MIN_APP_VERSION`(ConfigMap) 미만 앱 요청은 `426 APP_TOO_OLD`. 실제 사용량 ≈ 50MB(2026-10-30)라 한도 증설 없이 기존 14Gi 에 둔다 — [SPEC_앱-배포-업데이트](SPEC_앱-배포-업데이트.md). 사내 전체 배포 전 DNS 등록 요청(`미결`)
- 백업·모니터링: 1차는 최소 — DB 는 수동 `pg_dump`(사내 배포 설정 `k8s/dev/README.md`), 결과 파일은 보관 정리 대상이라 백업 제외. 상태 확인은 `/healthz`(프로세스) · `/readyz`(DB 응답) 프로브와 `kubectl logs`. 정기 백업·경보는 운영 정식화 때.
