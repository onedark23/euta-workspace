# ADR - 032 테스트 세트 리포트 · Live 묶음 구현

## 상태

채택 (2026-10-23, 단계 14 구현). euta-app `ea0eddf`·`79d260c` · euta-cloud `581e202`(로컬 커밋). 엔진 변경 없음. 앱 단위 173(+5) · 앱 E2E 5 스펙(개발 빌드) · 클라우드 단위 259(+4) · 웹 E2E 14(+1). 패키징본 E2E 는 아직.

## 맥락

[SPEC_프로젝트-관리](SPEC_프로젝트-관리.md#live-화면--테스트-세트-묶음-2026-10-23) 가 Live 묶음과 세트 리포트(자동 생성 `suite-runs/<suiteRunId>/report.html`, 요약 + 지난 실행 대비 + 실패 상세, 클라우드는 웹 실행 상세)를 정했다. 이 ADR 은 SPEC 이 정하지 않은 저장 모양 · 비교 규칙 · 생성 시점 · 화면 연결을 기록한다.

## 결정

### 1. 저장 — JSON 은 그대로, 리포트는 옆 폴더 (이전 없음)

- 세트 실행 기록은 지금처럼 `suite-runs/<id>.json`. 리포트만 `suite-runs/<id>/report.html`(같은 이름의 폴더). `listSuiteRuns` 는 `<id>.json` 파일만 읽으므로 폴더가 섞여도 영향 없다 → 옛 실행은 JSON 만 있는 채로 그대로 읽힌다.
- `SuiteRun.hasReport` 는 **저장하지 않는 계산 값**(목록을 읽을 때 파일 존재로 채움).
- 대안: JSON 도 `suite-runs/<id>/run.json` 으로 옮기기 — 폴더 하나로 깔끔하지만 옛 파일 읽기 경로 둘을 유지하거나 이전이 필요하다. 추가만으로 끝나는 쪽을 골랐다.

### 2. 생성 시점 · 내용

- 세트가 끝나면(마지막 상태 저장·`suite.finished` 기록 뒤) 리포트를 쓰고, 화면에 `hasReport: true` 로 한 번 더 알린다(`suiteUpdate`). 최종 상태 알림은 선택자 점검을 기다리지 않는다.
- [리포트] 를 눌렀는데 파일이 없으면(옛 실행, 쓰기 직전 클릭) 그 자리에서 만든다. 실행 중이면 만들지 않는다.
- 렌더는 Electron 없는 순수 함수 `renderSuiteReport`(`src/main/project/suite-report.ts`), 자료 모으기는 `buildSuiteReport`.
- 실패 단계: 항목 실행의 `run.json` 단계에서 첫 `failed|error`(묶음이면 그 안의 실패 단계까지 내려감). 단계 문장은 **`run.json` 에 담긴 실행 당시 스크립트**(`script.steps`)의 그 단계로 `describeStep` — 라이브러리 파일이 나중에 바뀌어도 실행과 맞는다. 스크린샷은 그 단계의 `screenshot` 파일만 `data:` 로 넣는다(4MB 넘으면 생략). 
- 마스킹: 글자 부분을 프로젝트 모든 secret 값으로 한 번 더 가린다(실행 기록은 이미 엔진이 가림). 이미지 데이터는 건드리지 않는다. CSP 메타로 외부 요청 금지.
- 선택자 점검(있으면): 실패 항목의 실행 폴더에 `dom/` 이 있을 때만, 실행 당시 스크립트(JSON 문자열 = YAML)로 `checkTargets`. 한 리포트에 최대 5건, 건당 20초 넘으면 생략. 전체 판정 수 + 실패 단계 대상의 판정만 보인다. 실패 단계에 대상이 없으면(예: 제목 확인) 그렇게 적는다.
- 항목 이름: 실행의 `run.json` 이름, 실행 안 된 항목은 라이브러리 `name:`. 개별 리포트 링크는 상대 경로(`../../runs/<runId>/report.html`).

### 3. 지난 실행 대비 규칙

- 지난 실행 = 같은 세트 id · 같은 환경 id · 이 실행보다 먼저 시작 · 끝난 실행 중 가장 최근(클라우드는 같은 세트 · 같은 환경 id(없으면 이름) · 먼저 만들어짐 · 대기/실행/건너뜀 아님).
- 짝짓기: 두 실행의 스크립트 목록이 같으면 **자리(순번)** 로, 다르면 **스크립트 + 몇 번째 등장**(두 번째 `a.yaml` ↔ 두 번째 `a.yaml`, 클라우드는 스크립트 id)으로.
- 분류는 **이번에 실행된 항목만**: 이번 실패·오류(클라우드는 timeout·aborted 포함) + 지난번 실패 아님(통과·건너뜀·없음) = 새로 실패 · 이번 통과 + 지난번 실패 = 회복 · 둘 다 실패 = 계속 실패 · 둘 다 통과 = 그대로 통과. 이번에 건너뛴 항목, 지난번에 안 돌았고 이번에 통과한 항목은 어느 칸에도 넣지 않는다.

### 4. 앱 화면 연결

- [리포트] 버튼 세 곳: 테스트 세트 카드 최근 결과 옆 · History 세트 묶음 줄(줄 클릭 펼침과 분리) · Live 세트 머리(끝난 뒤). 이 PC 실행은 IPC `suite:report-open` → 기존 리포트 창(샌드박스 BrowserWindow, preload 없음) 공용 함수 `showReport`.
- 리포트 창은 이동이 막혀 있다(`hardenContents`). 개별 리포트 링크(`…/runs/<runId>/report.html`)를 누르면 이동 대신 그 실행의 리포트를 새 창으로 연다(기존 `openReport` 경로 — 프로젝트 실행만 찾으므로 임의 파일을 열지 않음). 시스템 브라우저로 열면 상대 링크가 그대로 동작한다.
- 클라우드 세트 실행의 [리포트] 는 main 이 `<프로젝트의 서버 주소>/projects/<클라우드 프로젝트 id>/runs/<실행 id>` 를 만들어(실행 id 는 UUID 만) 시스템 브라우저로 연다(IPC `cloud:run-web`). 렌더러가 주소를 넘기지 않는다. History 클라우드 세트 줄의 Report 도 같은 링크. Teams "실행 보기"는 서버 `runUrl`(같은 경로)이라 바꿀 것 없음.

### 5. Live 묶음

- 해석: 왼쪽 실행 목록에 세트는 **한 줄**(세트 이름 · 상태 · 완료/전체 · 환경), 그 세트의 스크립트 실행은 목록에서 빠진다. 세트(또는 그 안의 실행)를 고르면 오른쪽이 **세트 머리 + 항목 목록**: 항목 머리(순번 · 이름 + 작은 파일명 · 항상 실행 · 소요 · 상태)를 누르면 펼치고 접는다. 펼친 항목 안은 기존 단독 실행 화면(`RunDetail` 로 분리한 같은 컴포넌트)이다.
- 펼침 기본값: 실행 중인 항목만. 끝나면 접힌다. 끝난 실행을 바깥에서 골라 들어오면(History "Open" 등) 그 항목만 펼친다. 사용자가 누른 펼침·접힘은 그 세트를 보는 동안 유지.
- 연결: 앱 실행의 `RunView.suiteRunId`(main 이 세트 실행으로 시작할 때 붙임), 렌더러는 프로젝트의 `SuiteRun` 목록(열 때 History 목록 + `suites.onUpdate`)으로 묶는다. 실행 중이거나 그 실행 중 하나가 Live 에 있는 세트만 보인다.
- 클라우드: 부모 실행 `RunView` 에 `suiteItems`(자식 순서 · 상태 · 항상 실행 · 소요)와 `cloud.envName` 을 더했다(기존 `steps` 표현은 호환으로 유지). 피드로 부모를 다시 읽을 때 **실행 중인 자식도 다시 읽어** 자식 `RunView`(`cloud.parentRunId`)를 만든다 → 펼친 항목에 자식의 단계 요약이 보인다. 취소는 기존 클라우드 취소 버튼.
- 세트 머리 [취소]·[리포트] 는 테두리 있는 버튼(UI 그라운드룰). 진행 수 = 대기·실행 중이 아닌 항목 수.

### 6. 클라우드 웹

- 서버 `GET /api/projects/:id/runs/:runId/suite-report`(보기 권한, 세트 실행이 아니면 422): `previous` · `comparison`(위 규칙) · `names`(자식 실행 id → 고정된 스크립트 원문의 `name:`) · `failures`(실패 자식별 실패 단계 id · 단계 문장(`runs.script_source` 로 `describeStep`) · 저장된 오류 · 그 단계 스크린샷 경로(자식 결과 파일의 `run.json`)). 실패 상세는 최대 20건.
- 웹 실행 상세: 세트 실행이면 기존 "스크립트 실행" 표 자리에 **리포트 화면**(요약 · 지난 실행 대비(지난 실행 링크) · 스크립트별 표(순번 · 이름 + 작은 경로 · 상태 · 소요 · 항상 실행 · 열기 버튼) · 실패 상세(문장 · 오류 · 스크린샷, 누르면 크게)). 자식 상태가 바뀔 때마다 다시 읽는다. 기존 머리(환경 · 출처 · 시간 · 취소 · 다시 실행)는 그대로.
- 대안: 웹에서 자식마다 상세·`run.json`·스크립트 버전을 따로 읽어 조합 — 요청이 자식 수만큼 늘고 비교 규칙이 웹에만 생긴다. 서버 한 곳에서 계산했다.

## 결과

- 옛 `suite-runs/*.json` 은 그대로 읽히고, [리포트] 를 처음 누를 때 리포트가 생긴다.
- 리포트는 결과 폴더 안 파일 1개라 그대로 보관·전달할 수 있다(PDF·따로 내보내기는 범위 밖).
- 선택자 점검은 실패 항목마다 headless 브라우저를 띄우므로 세트 종료 후 리포트 쓰기가 몇 초 걸릴 수 있다(상한 5건 × 20초). 최종 상태 알림과 실행 결과에는 영향 없다. 20초를 넘긴 점검은 기다리지 않을 뿐 중단하지 않는다(끝나면 브라우저가 닫힘).
- 클라우드 Live 묶음은 단위 테스트(가짜 서버)로만 확인했다 — 앱 E2E 의 가짜 클라우드 서버에 세트 실행이 없어 화면 캡처 확인은 못 했다.
- 클라우드 Live 의 펼친 자식은 서버 요약(단계·현재 단계)이고 스크린샷은 없다 — 결과 파일은 History "열기"로 내려받아 본다(지금과 같음).
