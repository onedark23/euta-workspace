# ADR - 017 시연 녹화기 구현

## 상태

채택 (2026-10-02, 구현). macOS(arm64)에서 엔진 단위·E2E, 앱 단위·E2E(개발 빌드 + 패키징된 앱)로 검증했다. 결과는 아래 "결과" 절.

## 맥락

- [SPEC_스크립트-작성-시연녹화](SPEC_스크립트-작성-시연녹화.md) 가 흐름(시연 녹화 → 초안 → AI 정리 → 자동 확인 → 대화로 수정)과 녹화 형식·화면을 정했다. 이 ADR 은 SPEC 이 정하지 않은 **구현 방식**(수집 방법, 대상 지정, 민감 값 처리, 체크포인트 가로채기, 초안 변환 규칙, 앱 저장·도구, E2E 가 녹화 브라우저에 닿는 방법)을 기록한다.
- 확인한 사실(2026-10-02, Playwright 1.63)
  - `context.addInitScript` 는 모든 새 문서(하위 frame 포함)에서 페이지 스크립트보다 먼저 돈다. `context.exposeBinding` 은 모든 frame 에서 쓸 수 있고, 호출은 페이지가 부른 순서대로 Node 에 도착한다(입력 → 클릭 순서 유지).
  - `page.setContent` 는 `document.open` 을 써서 window 쪽 리스너를 지우지만 전역 값(설치 표시)은 남긴다 → 수집 스크립트 단위 테스트는 `page.route` 로 실제 문서를 띄워야 한다.
  - 사람이 칸에 입력하고 다른 칸으로 옮기면 앞 칸의 `change` 가 다음 칸 포커스 때 한 번 더 온다(값 변화 없음).
  - `page.screenshot({ mask })` 는 가릴 요소를 `#FF00FF` 상자로 칠한다(픽셀로 검증 가능).
  - Playwright 의 `selectOption`·`setInputFiles` 가 내는 `change` 는 isTrusted=false, 클릭·키·`fill` 은 신뢰 이벤트다.

## 결정

### 1. 수집 — init script + binding, 엔진 core 의 `Recorder`

- `openRecorder({ dir, baseUrl, startPath, browser, headless?, envId?, onUpdate, onFinished })` → 핸들: `page` · `view()` · `pause/resume` · `setCheckpointMode(kind|null)` · `undoLast` · `deleteEvent` · `markSensitive(seq)` · `annotate(seq, text)` · `setExpected(seq, value)` · `addNote(text)` · `stop() → Recording`. 앱과 향후 CLI 가 같이 쓴다.
- headed 브라우저 1개·컨텍스트 1개·페이지 1개. 수집 스크립트(`CAPTURE_SCRIPT`)는 **문자열 상수**로 둔다(TS 함수 + `toString()` 은 번들러 보조 함수가 섞일 수 있음 — `VITALS_INIT_SCRIPT` 와 같은 방식).
- 스크립트는 window 캡처 단계에서 click·dblclick·input·change·keydown·scroll 을 듣고 `__eutaRec(payload)` 로 보낸다. 상태(일시정지·체크포인트 모드·민감 선택자)는 문서가 시작할 때 `__eutaRecState()` 로 **당겨 오고**, 바뀌면 Node 가 현재 문서에 밀어 넣는다(이동 중 경합 없음).
- 합치기는 Node 의 순수 함수 `appendEvent`: 같은 요소 키(`<문서>:<n>`)의 연속 `fill` 은 하나로(마지막 값), 바뀐 게 없으면 그대로(스크린샷 다시 찍지 않음), `dblclick` 은 바로 앞 같은 요소 클릭 2개를 대신.
- 체크박스·라디오·select·파일은 `change` 로만 기록하고 그 요소와 연결 label 의 클릭은 보내지 않는다. 키보드로 생긴 클릭(`detail === 0` + 직전 키)은 버린다. 키는 Enter·Tab·Escape·수정키 조합만, 복사·붙여넣기·실행 취소 조합은 버린다(재생하면 값이 바뀜).
- 이동: `framenavigated`(메인 frame). 녹화기 첫 `goto` = `start`, 동작 후 2.5초 안 = `action`(초안에서 생략), 그 밖 = `direct`. 주소창 입력을 Playwright 가 따로 알려 주지 않아 시간 기준을 쓴다(CDP `Page.frameRequestedNavigation` 은 Chromium 전용이라 쓰지 않음).
- 다운로드: `download` 이벤트에서 이름만 남기고 파일은 지운다. 팝업·새 탭: `context.on('page')` → "녹화 안 됨: popup", 그 페이지의 이벤트는 버린다. 하위 frame 의 스크립트는 상호작용 때 "녹화 안 됨: iframe" 표시만 보낸다(5초에 1번).
- 스크린샷: 이벤트 0.4초 뒤(입력은 마지막 키 기준) 직렬 큐로 `scale: css` PNG, 실패(이동 중)는 건너뛴다. 종료 때 대기 중인 것 중 마지막 1장은 찍는다. `recording.json` 은 종료 때 한 번(임시 파일 → rename), 녹화 중 값은 메모리에만.

### 2. 대상 지정 — 페이지 안에서 후보와 유일성

- 우선순위(SPEC): role+이름 → label → placeholder → testId → text → CSS. 역할·접근 가능한 이름은 페이지 안에서 근사 계산한다(명시 role, 태그·type 별 암묵 role, `aria-labelledby` → `aria-label` → label → title/placeholder, 내용에서 이름을 얻는 역할은 textContent). 비밀번호 칸은 role 이 없으므로 label 이 대표가 된다(Playwright 와 같음).
- 각 후보의 일치 수를 **페이지 안에서 녹화 시점에** 센다. Playwright 기본 의미(공백 정규화, 대소문자 무시 부분 일치)로 1개면 그대로, 여러 개인데 정확 일치로 1개면 `exact: true`. text 는 "텍스트를 가진 가장 안쪽 요소" 로 센다. 마지막 후보 CSS 는 `#id`(유일·자동 생성처럼 보이지 않을 때) 또는 `tag:nth-of-type` 사슬로 항상 유일.
- **Node 에서 `locator.count()` 로 검증하지 않는다**: 제출 클릭 직후 페이지가 이미 다음 화면으로 넘어가 엉뚱한 결과가 나온다(경합). 대신 단위 테스트가 녹화된 대표 대상을 실행기의 `resolveTarget()` 으로 다시 찾아 **정확히 그 요소 1개** 인지 확인한다.
- 근사가 Playwright 와 다른 드문 경우는 "개수 과대" 쪽으로 기운다(숨김 요소도 셈) → 다음 후보로 내려갈 뿐 잘못된 유일 판정은 줄인다.

### 3. 민감 값 — 페이지 안 수집 단계에서 버림

- `type=password`, `autocomplete` 가 `current-password`·`new-password`·`one-time-code`·`cc-*` 인 칸, 그리고 "민감" 으로 표시된 칸(선택자 목록)은 **페이지 스크립트가 값 없이** `sensitive: true` 만 보낸다. 한 번 민감이 된 요소는 type 이 바뀌어도(비밀번호 보기) 계속 민감(WeakSet).
- "민감" 표시(`markSensitive`): 같은 칸의 모든 `fill` 값 삭제, secret 이름 제안, 그 칸의 선택자(`#id`·`[name]`·CSS 경로)를 수집 스크립트와 스크린샷 가림 목록에 추가, 그 칸을 처음 입력한 동작부터 같은 문서 안의 스크린샷 삭제, 표시 전에 찍기 시작한 스크린샷은 버림(세대 번호). 저장된 녹화에도 같은 함수(`markRecordingSensitive`)를 쓴다.
- 가림: 위 선택자 전부를 Playwright `mask` 로. 녹화 폴더에는 HAR·trace·영상이 없다(값이 남을 경로 자체가 없음). AI 로 가는 `get_recording` 결과는 도구 가드(SecretGuard)의 환경 secret 마스킹을 한 번 더 거친다.
- secret 이름 제안: password → `PASSWORD`, 이메일 → `USER_EMAIL`, 아이디 → `USERNAME`, OTP·카드 등, 아니면 ASCII 슬러그, 최후 `SECRET`. 초안 변환 때 **환경에 이미 있는 이름에 맞춘다**(정확히 → `*_<핵심>`/`<핵심>_*` → 포함; 예 `PASSWORD` → `USER_PASSWORD`) — 기존 스크립트·vault 관례와 어긋나 "등록 필요" 가 쓸데없이 나오는 것을 막는다.

### 4. 체크포인트 — 캡처 단계 가로채기

- 모드를 켜면 오버레이(닫힌 shadow root, `pointer-events: none`)가 마우스 아래 요소를 테두리로 강조하고 안내 띠를 보인다. pointerdown·mousedown·mouseup·click 등은 window 캡처 단계에서 `preventDefault` + `stopImmediatePropagation`(init script 가 페이지 스크립트보다 먼저 등록되므로 가장 먼저 받음, 포커스도 안 옮겨짐). 클릭한 요소를 대상으로, 종류에 따라 현재 값(innerText 정규화 · 개수)을 잡고 모드를 끈다(1회성). Esc 는 취소.
- "현재 주소" 는 요소가 필요 없어 고르는 즉시 기록. "개수" 는 클릭 요소가 속한 표의 행(또는 같은 태그 형제가 있는 조상)의 역할(없으면 태그+클래스)로 센다.

### 5. 초안 변환 — 순수 함수 `recordingToScript`

- SPEC 매핑 그대로 + 세부(SPEC "구현 세부"): 빈 영역 클릭 제거, 입력란 클릭 뒤 같은 칸 `fill`/`press` 면 클릭 제거, 다운로드는 직전 클릭·키를 `trigger` 로 감싼 `expectDownload { name: "*.<ext>", type }`, 스크롤은 뒤에 동작이 없거나 체크포인트만 있고 바닥일 때만, 메모는 시간상 가장 가까운 스텝 `name`. 결과는 기존 스키마로 검증된다(DSL 변경 없음). 머리 주석: 출처·"등록 필요 secret"·"녹화 안 됨" 건수.

### 6. 앱 — 저장소, 서비스, 도구, 화면

- `RecordingStore`(`projects/<id>/recordings/<rid>/`): 목록·이름 변경·삭제·사후 민감 표시, JSON 원자적 쓰기, 파일 경로 순회 금지. `ProjectService`: 녹화기 1개(앱 전체), 환경 주소·프로젝트 브라우저 기본값으로 시작(항상 headed; 단위 테스트만 `recorderHeadless`), 패널 제어, "AI 없이 저장"(`ScriptLibrary.writeNew`, 슬러그 경로), "AI로 정리"(새 채팅 + `recordingId:` 요청, 턴은 백그라운드), 작업 로그 3종.
- AI 도구 `get_recording`: `createAppTools({ recordings })` 로 붙인다(채팅 컨텍스트가 프로젝트 저장소를 넘김). 도구 가드의 `define` 을 써서 입력 검증·오류 매핑·텍스트 마스킹을 그대로 받는다. 스크린샷은 요청한 seq 만(최대 6). 시스템 프롬프트에 정리 지침·"말로 시키기" 지침 절(`RECORDING_GUIDE`).
- 가짜 에이전트(`EUTA_E2E_FAKE_AGENT`): 요청에 `recordingId:` 가 있으면 `get_recording` → 초안 끝에 `measure` 한 스텝을 붙여 `save_script`(`<slug>-ai.yaml`) → `run_script` 를 **실제로** 호출한다.
- 화면: 프로젝트 화면 오른쪽 패널(콘텐츠 영역과 나란히 — 표의 버튼을 가리지 않음), 시작 대화상자, 스크립트 탭 목록, AI 채팅 버튼·예시. IPC `rec:*`, 갱신은 `rec:update` 푸시.

### 7. E2E 가 녹화 브라우저에 닿는 방법

- `EUTA_E2E=1` 일 때만 생기는 main 전역 `__eutaTest` 에 `recorderPage()`(녹화기의 Playwright `Page`)를 더했다. 테스트는 `electronApp.evaluate` 로 main 에서 그 페이지를 Playwright API 로 조작한다("사람" 역할). 패널 조작(메모·민감·체크포인트·종료)은 렌더러에서 평소처럼 한다.
- 포트·CDP 가 필요 없고 개발 빌드와 패키징본이 같은 경로다. 렌더러에는 노출되지 않는다.
- 패키징 E2E 를 위해 `scripts/package.mjs` 에 출력 폴더 덮어쓰기 `EUTA_PACKAGE_OUT` 을 더했다(기본 `release`). 사용자가 `release/dist` 의 앱을 실행 중이어도 다른 폴더에 패키징해 검증할 수 있다.

## 대안과 기각 이유

| 대안 | 기각 이유 |
|---|---|
| Playwright codegen(`npx playwright codegen` / 내부 `Recorder`·`InjectedScript.generateSelector`) 재사용 | 비공개 내부 API(버전마다 바뀜), 출력이 Playwright 테스트 코드라 DSL 로 다시 파싱해야 함, 민감 값을 **페이지 안에서** 버리는 지점·체크포인트 가로채기·메모를 넣을 수 없음, 녹화 UI 가 Playwright Inspector 에 묶임 |
| Node 에서 `locator.count()` 로 후보 유일성 확인 | 제출·링크 클릭 직후 이동과 경합 — 다음 화면에서 세게 됨. 페이지 안 계산 + 단위 테스트의 `resolveTarget` 교차 검증으로 대체 |
| CDP 이벤트(Input/DOM) 로 수집 | Chromium 전용, 의미 정보(label·role)를 다시 계산해야 함, 값 폐기를 브라우저 밖에서 하게 됨 |
| 키 입력마다 이벤트 / 값을 Node 에서 가림 | 비밀번호가 한 번이라도 Node·디스크로 넘어감 — SPEC "어디에도 남지 않음" 위반 |
| E2E: 녹화기를 `--remote-debugging-port` 로 띄우고 `connectOverCDP` | Playwright pipe 연결과 포트 동시 사용·컨텍스트 가시성을 확신할 수 없고 포트 충돌·보안 노출, 엔진에 테스트 전용 옵션이 생김. `launchServer`+`connect` 는 다른 연결의 컨텍스트가 안 보임 |
| 녹화 중 `recording.json` 을 계속 쓰기(충돌 대비) | 나중에 "민감" 으로 표시할 값이 그 전에 디스크에 남음. 종료 때 1회 쓰기로 둔다(충돌 시 그 녹화는 잃음 — 알려진 한계) |

## 알려진 한계

- 접근 가능한 이름 계산은 근사다(복잡한 ARIA 구성·shadow DOM 안 요소는 CSS 경로로 떨어질 수 있음). 녹화 중 Node 측 재검증은 없다.
- 이동 원인 구분은 시간 기준(2.5초) — 동작 직후 사용자가 주소창으로 이동하면 생략될 수 있고, 늦은 스크립트 이동은 `goto` 로 남을 수 있다.
- 녹화 중 앱이 죽으면 그 녹화(`recording.json`)는 남지 않는다(스크린샷만 남음).
- 팝업·새 탭·iframe·여러 탭은 녹화하지 않는다(SPEC 범위 밖). 업로드는 초안에서 `files/<이름>` 자리표시라 파일을 넣어야 통과한다.
- 실제 모델로 "AI로 정리" 한 품질은 사용자 실사용 확인 대기.
