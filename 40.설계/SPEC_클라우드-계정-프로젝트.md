# SPEC - 클라우드 계정·프로젝트

> 상태: **확정** (2026-10-20, C0). 제안값은 2026-10-20 사용자 확인으로 모두 채택. 구현 단계: C1(서버) · C4(웹 화면 — 인증·장치 승인·토큰·관리자 승인 2026-10-21 먼저 구현, 프로젝트·실행 화면 2026-10-21 구현 — [ADR-029](ADR_029_클라우드-웹-화면-구현.md)).
> 결정 정본은 [PLAN_euta-cloud 결정 사항](../20.프로젝트관리/PLAN_euta-cloud.md#결정-사항), 구조는 [ARCH_euta-cloud](ARCH_euta-cloud.md). 로컬 앱 쪽 프로젝트 모델은 [SPEC_프로젝트-관리](SPEC_프로젝트-관리.md) 와 같은 말을 쓴다.

## 목적

- 회사 구성원이 euta cloud 에 가입·로그인하고, **클라우드 공유 프로젝트**(설정·환경·테스트 계정·스크립트·스위트·작업 로그)를 함께 관리한다.
- 실행·예약은 [SPEC_클라우드-실행-예약](SPEC_클라우드-실행-예약.md), 로컬 앱 연동은 [SPEC_클라우드-앱-연동](SPEC_클라우드-앱-연동.md), MCP 는 [SPEC_클라우드-MCP](SPEC_클라우드-MCP.md).

## 용어

| 용어 | 뜻 |
|---|---|
| 구성원 | 가입한 회사 도메인 사용자. 모두 같은 조직에 속한다 |
| 관리자 | 조직 관리자. 구성원 비활성화 · 가입 승인(메일 대체 시) |
| 프로젝트 역할 | 소유자 · 편집자 · 실행자 · 보기. 조직 공개 프로젝트에서 초대받지 않은 구성원은 "보기" |
| 테스트 계정 | 대상 서비스에 로그인할 아이디/비밀번호 등. 엔진의 `${secrets.NAME}` 으로 참조 |
| 개인 토큰 | MCP 접속용 계정별 토큰(`euta_…`) |

## 계정

### 가입·로그인

| 항목 | 규칙 |
|---|---|
| Microsoft 로그인 (주) | **회사 Microsoft 계정(Entra ID, 회사 테넌트 한정)** — 로그인 화면 주 버튼 "회사 계정(Office 365)으로 로그인". 처음 로그인이 곧 가입이며 **바로 활성**(관리자 승인 없음). 이름은 Microsoft 프로필에서. 회사 테넌트가 아니거나 메일이 허용 도메인(`ALLOWED_EMAIL_DOMAINS` — 필수 설정, 사내 배포는 회사 도메인) 밖이면 거절. Entra 설정(`MICROSOFT_TENANT_ID` · `MICROSOFT_CLIENT_ID` · `MICROSOFT_CLIENT_SECRET`)이 있을 때만 켜짐 (PLAN 결정 "로그인" 2026-10-30) |
| 기존 계정 연결 | Microsoft 로그인한 메일과 같은 메일(대소문자 무시)의 계정이 이미 있으면 **그 계정에 연결**된다 — 프로젝트·역할·관리자·토큰 그대로. 그 계정이 "승인 대기"였으면 활성으로 바뀐다. 비활성 계정은 Microsoft 로도 로그인 불가. **메일을 인증하지 않은 계정**(승인 대기 · 인증 메일을 열지 않은 계정 — 남의 메일로 먼저 가입했을 수 있음)은 연결할 때 **비밀번호를 지운다** — 그 뒤로는 Microsoft 로만 들어온다. 관리자(`ADMIN_EMAILS`)와 관리자가 승인한 계정은 비밀번호를 남긴다(관리자 예외 = 2026-11-02 사용자 결정, 메일 모드 미인증 계정 포함 = 구현 판단 [ADR-043](ADR_043_Microsoft-로그인-구현.md)) |
| 가입 (이메일) | Microsoft 로그인이 켜져 있으면 **이메일 새 가입은 닫힌다**(가입 화면·버튼 없음, API 거절). 꺼져 있으면(앱 등록 전·개발) 이전 규칙: 이메일 · 이름 · 비밀번호, **허용 도메인 밖이면 거절** |
| 기존 이메일 회원 로그인 | 이메일·비밀번호로 가입했던 사람은 로그인 화면의 접힌 "기존 이메일 회원 로그인"으로 계속 들어올 수 있다. Microsoft 로 한 번 연결한 뒤에도 비밀번호 로그인은 남는다(위 "기존 계정 연결"의 미인증 계정 예외) |
| 비밀번호 | 10자 이상 · 128자 이하. 다른 규칙(문자 조합)은 두지 않는다 |
| 메일 인증 | 가입 후 인증 메일의 링크를 눌러야 로그인 가능. 인증 링크 유효 24시간, 로그인 시도 때 미인증이면 다시 보냄 |
| 메일 대체 | SMTP 미설정 시(열린 결정 #12) **관리자 승인 모드** — 이메일로 가입하면 "승인 대기", 관리자가 승인해야 로그인. 이메일 가입이 열려 있을 때(Microsoft 로그인 꺼짐)만 해당 — PLAN 결정 "메일 발송"·"로그인" |
| 로그인 실패 잠금 | 이메일·비밀번호 로그인 실패 5회 연속이면 10분 잠금(Microsoft 로그인은 Microsoft 쪽 정책) |
| 비밀번호 재설정 | 메일 링크(1시간 유효). 메일 대체 모드에서는 관리자가 임시 비밀번호 발급 |
| 세션 | 웹: 쿠키 세션, 7일(사용 중 연장). 로그아웃 시 즉시 무효 |
| 관리자 지정 | 서버 설정 `ADMIN_EMAILS` 에 적힌 이메일이 가입하면(Microsoft 첫 로그인 포함) 관리자. 화면에서 관리자 추가·해제는 1차 범위 밖 |
| 비활성화 | 관리자만. 비활성 계정은 로그인 불가 · 모든 세션·장치 토큰·개인 토큰 무효 · 프로젝트 역할은 남기되 판정에서 제외. 다시 활성화 가능 |

| 알림 | Teams 워크플로 webhook URL(선택) · 기본 끔 알림 켜기(건너뜀 · 중단 · 통과 · 불안정) — [SPEC_클라우드-실행-예약](SPEC_클라우드-실행-예약.md#알림). **주소는 비밀값**(SAS `sig` 포함): 프로젝트 응답에 원문은 설정을 바꿀 수 있는 사람(편집자 이상, 토큰이면 `읽기·쓰기` — 권한 판정 `project.update`)에게만 싣고, 그 밖(보기·읽기 토큰)에는 `teamsWebhookConfigured`(있음/없음)만. 로그·작업 로그·변경 피드에는 원문을 남기지 않는다(로그는 호스트만, 작업 로그는 바뀐 필드 이름만) |
| 하루 실행 상한 | 기본 50, 1~10,000 — Asia/Seoul 하루의 스크립트 실행 수. 편집자 이상 — [SPEC_클라우드-실행-예약](SPEC_클라우드-실행-예약.md#하루-실행-상한) |

### 만들기·공개·구성원

- 구성원 누구나 프로젝트를 만들 수 있고(웹 "새 프로젝트" · 앱 "클라우드로 올리기"), 만든 사람이 **소유자**가 된다. 서버는 **출생 기록**(`origin`: `web` | `app` + `originLocalId` · `createdBy` · `createdAt`, 바꿀 수 없음)을 남긴다. 기존 프로젝트는 `origin: unknown`.
- **공개 범위**(`visibility`, 소유자만 변경): `org`(기본 — 조직 구성원 누구나 "보기", 받기 목록에 나옴) / `members`(구성원만 — 그 밖에는 목록에 없고 직접 접근도 404). `org → members` 로 바꾸면 초대받지 않은 사람의 작업 사본은 다음 동기화 때 "접근 권한 없음".
- **역할**: 소유자 · 편집자 · **실행자** · 보기 — 권한 표는 [ARCH 권한](ARCH_euta-cloud.md#권한). 조직 공개 프로젝트에서 초대받지 않은 구성원은 "보기".
- **초대**: 소유자가 조직 구성원을 **이름(이메일 작게)으로 검색해 골라** 역할 지정(`GET /api/users?q=`). 역할 변경 · 내보내기. 소유자는 최소 1명(마지막 소유자는 내보내기·낮추기·나가기 불가).
- **권한 요청**: 조직 공개 프로젝트를 볼 수 있는 사람이 원하는 역할(편집자·실행자) + 메모(선택, 200자)로 요청 → 소유자에게 웹·앱 알림 → 소유자가 승인(역할 바꿔 승인 가능)·거절 → 요청자에게 결과 알림. 열린 요청은 사람당 프로젝트당 1건, 30일 지나면 자동 만료. `members` 프로젝트는 목록에 없으므로 요청도 없음.
- **나가기**: 구성원 본인(소유자는 다른 소유자가 있을 때만).
- **소유권 이전**: 소유자가 다른 구성원을 소유자로 올린 뒤 자기 역할을 낮추거나 나간다(별도 "이전" 버튼 = 두 동작을 한 번에).
- **관리자 소유자 지정**: 소유자가 모두 비활성화된 프로젝트는 관리자 화면 "소유자 없는 프로젝트" 에 나오고, 관리자가 구성원 중 새 소유자를 지정한다(작업 로그 행위자 "관리자").
- **합치기**(앱 → 서버): 출처 `app` · `originLocalId` 일치 · 요청자 소유자일 때만. `unknown` 은 소유자 + 앱이 보낸 로컬 연결 기록 id(옛 `uploadedTo.localId`)가 일치하면 1회 허용하고 출생 기록을 `app` 으로 채운다. 그 밖은 403 `ORIGIN_MISMATCH`.
- 작업 로그 종류에 `member.invited` · `member.role_changed` · `member.removed` · `member.left` · `access.requested` · `access.approved` · `access.rejected` · `project.visibility_changed` · `project.owner_assigned`(관리자) · `project.transferred`(소유권 이전) · `project.merged`.

### 삭제

- 소유자만. 프로젝트 이름을 입력해 확인.
- **휴지통 30일** — 삭제하면 목록에서 사라지고 예약이 멈춘다. 30일 안에 소유자가 복원 가능, 지나면 스크립트·이력·결과 파일·테스트 계정 영구 삭제.

## 환경

| 필드 | 규칙 |
|---|---|
| 이름 | 1~40자, 프로젝트 안에서 유일. 예: dev · staging · prod |
| 주소 | `http(s)` 절대 URL, 사용자 정보 금지. 저장할 때 **공개 주소 검사**(사설 IP·사내 주소로 풀리면 경고 — 이 환경은 클라우드 실행 불가로 표시, 로컬 실행은 가능) |
| 변수 | 키 `[A-Za-z_][A-Za-z0-9_]*`. **자격증명처럼 보이는 키(`TOKEN`·`PASSWORD`·`API_KEY`…)는 거부** — 테스트 계정으로 넣도록(ADR-016 과 같은 규칙) |
| 테스트 계정 | 이름 `[A-Za-z_][A-Za-z0-9_]{0,63}`, 값 16 KiB 이하. **쓰기 전용** — API·웹·MCP 어디서도 값을 돌려주지 않음(이름·마지막 변경 시각·변경자만). 값 변경·삭제는 작업 로그에 남김(값 없이) |
| 허용 도메인 | 클라우드 실행에서 테스트 계정 값을 입력할 수 있는 페이지 도메인 목록. 기본 = 주소의 도메인. 외부 로그인(SSO)·결제 도메인은 추가([SPEC_클라우드-MCP 보안](SPEC_클라우드-MCP.md#보안--ai-가-테스트-계정을-바깥으로-보내는-경로)) |
| 기본 환경 | 프로젝트당 1개 지정 가능 |

- 테스트 계정 값은 DB 에 암호화해 저장한다(서버 비밀 키로, 키는 k8s Secret). 실행 시점에 러너에게만 전달([SPEC_클라우드-실행-예약](SPEC_클라우드-실행-예약.md)).
- 환경 삭제 = 그 환경의 테스트 계정·예약도 삭제(확인 대화상자에 예약 수 표시).

## 스크립트

| 항목 | 규칙 |
|---|---|
| 경로 | 프로젝트 안 상대 경로(`login.yaml`, `checkout/pay.yaml`). `..`·절대 경로 금지. `.yaml`·`.yml` |
| 저장 | 원문 그대로 저장(주석 보존). **기준 버전 필수** — 현재 버전과 다르면 `409 conflict`(응답에 현재 버전 원문·작성자·시각) |
| 검증 | 저장 시 엔진 검증을 돌린다. **검증을 통과해야 저장**(PLAN 결정 "스크립트 저장·이력" — 저장 버튼은 검증 통과 시)하고, 실패하면 422 + 오류 목록(MCP `save_script` 도 같음 — AI 가 고쳐 다시 저장). **예외: 출처 "앱 바깥 변경"**(외부 편집기로 고친 사본)은 검증 오류여도 버전으로 받고 "검증 오류" 표시(실행 불가) — 로컬 앱의 바깥 변경 기록(ADR-018)과 같음 |
| 버전 | 저장마다 새 버전 — 원문 · 내용 해시 · 작성자 · 출처(웹 · 앱 · AI(MCP) · 앱 바깥 변경 · 되돌리기) · 메모(선택). 스크립트당 최근 200개 보관 |
| 되돌리기 | 이전 버전 원문으로 새 버전을 만든다(이력은 지우지 않음) |
| 이름 변경·이동 | 경로만 바뀌고 이력 유지. 같은 경로가 있으면 거절 |
| 삭제 | 삭제 표시(목록에서 숨김) → 복원 가능. 프로젝트 휴지통 정책과 별개로 30일 뒤 영구 삭제 |
| 크기 | 원문 256 KiB 이하 |

- 녹화 원본·AI 채팅은 클라우드에 없다 — 정리된 스크립트만 올라온다(PLAN 결정 "개인 데이터").

## API 개요

> 경로·형식의 세부는 구현에서 확정한다(위임 범위). 모든 응답은 JSON, 오류는 `{ error: { code, message, details? } }`. 권한 없음 403, 없음 404, 충돌 409, 검증 실패 422.

| 영역 | 경로 |
|---|---|
| 인증 | `/api/auth/*` (Better Auth — 가입·로그인·인증 메일·재설정·세션·장치 인가) |
| 서버 설정(공개) | `GET /api/config` — 로그인 없이. `{ signUpMode: 'approval' \| 'email', allowedEmailDomains }` (가입·로그인 화면 안내용) |
| 내 정보·토큰 | `GET /api/me` · `GET/POST /api/me/tokens` · `DELETE /api/me/tokens/:id` |
| 사용자 검색 | `GET /api/users?q=` — 활성 구성원 누구나(로그인 세션 또는 개인 토큰, 읽기면 충분). **활성 사용자만**(승인 대기·비활성 제외), 이름 또는 이메일 **앞부분 일치**(대소문자 무시), 이름순 최대 20명, 응답 `{ users: [{ id, name, email }] }`. `q` 가 비면 이름순 처음 20명. `q` 100자 초과 422 |
| 관리자 | `GET /api/admin/users` · `POST /api/admin/users/:id/(approve|deactivate|activate|reset-password)` (reset-password = 메일 대체 모드의 임시 비밀번호) |
| 프로젝트 | `GET/POST /api/projects`(`?scope=mine|all` · `?trashed=1`, 목록 항목에 `lastRun`) · `GET/PATCH/DELETE /api/projects/:id`(DELETE 본문 `{ confirmName }`) · `POST /api/projects/:id/restore` |
| 구성원 | `GET /api/projects/:id/members` · `GET/PUT/DELETE /api/projects/:id/members/:userId` |
| 환경 | `GET/POST /api/projects/:id/environments` · `PATCH/DELETE …/:envId` |
| 테스트 계정 | `GET …/environments/:envId/credentials`(이름만) · `PUT/DELETE …/credentials/:name`(값 쓰기만) |
| 스크립트 | `GET /api/projects/:id/scripts` · `GET/PUT/DELETE …/scripts/*path` (PUT 본문: 원문 + 기준 버전) · `POST …/scripts/*path/(rename|restore|revert)` · `GET …/versions` · `GET …/versions/:v` · `POST …/scripts/check`(저장 없는 검사·폼 편집 적용 — 웹 편집기, 보기 이상) |
| 스위트 | `GET/POST /api/projects/:id/suites` · `PATCH/DELETE …/:suiteId` |
| 작업 로그 | `GET /api/projects/:id/activity?kind=&actor=&before=` |
| 변경 수신 | `GET /api/projects/:id/events` (SSE, [ADR-022](ADR_022_클라우드-실시간-전송.md)) |

## 웹 화면 (C4)

> **먼저 낸 화면**(2026-10-21, C4 1부): 가입 · 로그인 · 승인 대기 · 로그아웃 · **장치 승인 `/device`**(로컬 앱 로그인) · 관리자(가입 승인) · 내 설정 > 토큰(발급·폐기). 로컬 앱 사용자가 실제로 로그인하고 MCP 토큰을 받을 수 있게 하려는 것.
> **C4 2부**(2026-10-21): 프로젝트 목록 · 프로젝트(탭 전부) · 스크립트 상세 · 실행 화면 — 구현 방식 [ADR-029](ADR_029_클라우드-웹-화면-구현.md). 아직 없음: 내 설정 > 이름·비밀번호 변경 · 관리자 구성원 비활성화 · 메일 인증·비밀번호 재설정 화면(메일 모드용).

| 화면 | 내용 |
|---|---|
| 로그인 · 가입 · 메일 인증 · 비밀번호 재설정 · 승인 대기 | **Microsoft 로그인이 켜져 있으면**: 주 버튼 "회사 계정(Office 365)으로 로그인" + 안내 "처음 오셨다면 회사 계정으로 로그인하면 바로 사용할 수 있습니다." + 접힌 "기존 이메일 회원 로그인"(펼치면 이메일·비밀번호), 가입 링크 없음 — 사내 도구에서 흔한 배치. Microsoft 로그인 실패는 돌아온 주소의 오류 코드로 사유를 보여 줌(회사 계정 아님·허용 도메인 밖 · 비활성 · 취소 · 그 밖). 꺼져 있으면 이전 화면(이메일 로그인 + 가입). 로그인 실패 사유를 나눠 보여 줌(틀림 · 승인 대기 → 승인 대기 화면 · 비활성 · 잠금 · 메일 미인증). 로그인 뒤 `next`(같은 사이트 안 경로만)로 돌아감 — Microsoft 로그인도 같음(장치 승인 `/device` 로 복귀 포함) |
| 장치 승인 `/device` | 로컬 앱이 연 주소(`?user_code=`)의 코드를 보여 주고 **승인 / 거부**. 로그인 필요(안 돼 있으면 로그인 뒤 돌아옴). 순서: 로그인 확인 → `GET /api/auth/device?user_code=`(코드를 내 계정에 묶음) → `POST /api/auth/device/approve`·`/deny`. 주소에 코드가 없으면 입력칸. 만료·이미 처리된 코드는 안내 |
| 프로젝트 목록 | 내 프로젝트 / 전체, 최근 실행 상태, 새 프로젝트, 휴지통(소유자 복원) |
| 프로젝트 | 탭 — 현황(최근 실행·예약·실패·오늘 실행 수/하루 상한) · 스크립트 · 실행 이력 · 예약 · 스위트 · 작업 로그 · 설정(기본 정보·환경·테스트 계정·구성원·알림·테스트 규칙·하루 실행 상한·삭제). 보기 역할은 편집·실행 컨트롤 없이 "보기 전용" 표시, Teams webhook 입력칸은 편집자 이상에게만 |
| 스크립트 표시 (웹 전체) | 스크립트는 **이름(YAML `name:`)을 굵게, 경로를 그 아래 작게** 보여 준다 — 스크립트 탭 목록, 실행 이력 · 현황의 실행 대상, 실행 상세 제목, 예약 목록, 테스트 세트 항목. YAML 에 `name` 이 없으면 이름 자리에 "(이름 없음)"(흐리게). 실행에 표시하는 이름은 그 실행이 고정한 스크립트 버전의 이름. 스크립트 탭 검색은 이름 · 경로 둘 다. **고르기**(예약 대상, 테스트 세트에 스크립트 넣기)는 파일명 드롭다운 대신 **검색 + 체크** — 예약은 하나만, 테스트 세트는 여러 개를 체크한 순서대로(위로 모이고 순번 표시) 넣는다 (2026-11-05 사용자 결정) |
| 새 스크립트 (웹) | **이름을 입력**하면 경로를 자동으로 제안한다(고칠 수 있음): 소문자 영문 · 숫자 · 한글만 남기고 나머지는 `-`, 40자 이내, `.yaml` — 앱 TC 변환의 파일 이름 규칙과 같다. 같은 경로가 있으면 `-2`, `-3` … 이름은 폼 편집기에 `name` 으로 들어간다 (2026-11-05 사용자 결정) |
| 스크립트 상세 | 단계 문장 보기(`@euta/core/describe`) · 최근 실행 겹치기 · 폼 편집 · 이력·비교·되돌리기 — 로컬 앱 [SPEC_스크립트-보기-편집](SPEC_스크립트-보기-편집.md) 과 같은 동작, AI 요청 버튼은 없음 |
| 내 설정 | 이름 · 비밀번호 변경 · 개인 토큰(발급 — 원문은 발급 직후 1번만 + 복사, 목록 — 이름·권한·만든 날·만료일·마지막 사용·앞 4자리·곧 만료 표시, 폐기 — 확인 후) |
| 관리자 | 구성원 목록 · 승인 · 비활성화 |

### 2026-10-20 — C1 서버 1부 구현 반영 (구현 세부 · 빈칸 채움)
- 권한: ARCH 표에 없는 **프로젝트 설정 편집**(이름·설명·브라우저·테스트 규칙·알림·기본 환경, `PATCH /api/projects/:id`)은 **편집자 이상**으로 정함. 휴지통 프로젝트는 복원할 수 있는 소유자 외에는 404.

- 개인 토큰: 발급·목록·폐기는 로그인 세션으로만(토큰으로 토큰을 만들 수 없음). 목록에 `expiringSoon`(만료 7일 이내) 표시값. 만료된 토큰은 목록에서 빠짐.
- API 표 보완: 구성원 목록 `GET /api/projects/:id/members`, 휴지통 목록 `GET /api/projects?trashed=1`(내가 소유자인 것), 프로젝트 목록 `?scope=mine|all`, 삭제된 스크립트 목록 `GET …/scripts?deleted=1`, 프로젝트 삭제 본문 `{ confirmName }`.
- 스크립트: PUT 본문 `{ source, baseVersion, origin, memo }` — 출처 값 `web · app · ai_mcp · external`(`revert` 는 되돌리기 경로만). 기존 스크립트에 기준 버전 없이 저장·없는 스크립트에 기준 버전을 붙여 저장도 409. 내용이 같으면 새 버전을 만들지 않음(`unchanged: true`). YAML 로 읽히지 않으면 출처와 무관하게 422 `YAML_PARSE_ERROR`, 검증 실패 422 `SCRIPT_INVALID`, 크기 초과 422 `SCRIPT_TOO_LARGE`. 저장 검증은 `${secrets.*}`·`${env.*}` 값을 자리값으로 채우고 돌림(로컬 앱 편집기와 같음). 복원 기간이 지나면 404.
- 스위트: 스크립트를 경로가 아니라 **스크립트 id** 로 참조(이름 변경을 따라감). 응답에는 id·현재 경로.
- 작업 로그: `kind` 는 접두어 필터(`script` → `script.*`), `actor` 는 사용자 id 또는 행위자 종류(`user`·`ai`·`schedule`·`system`), `before` 는 항목 id 커서. 개인 토큰으로 한 변경은 행위자 "AI — <주인> (<토큰 이름>)".
- 변경 수신: 변경 피드 보관 7일, 그보다 오래된 위치로 재연결하면 `resync` — [ADR-020](ADR_020_클라우드-DB-대기열-예약.md) · [ADR-022](ADR_022_클라우드-실시간-전송.md) 결과.
- `/api/auth/*` 오류는 Better Auth 형식(`code`·`message`)에 euta 오류 봉투(`error`)를 함께 실음. 장치 인가 폴링 오류는 RFC 8628 형식(`{ error: "authorization_pending" }`) 그대로.
