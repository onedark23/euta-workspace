# ADR - 018 스크립트 편집기·이력 구현

## 상태

채택 (2026-10-02, 구현). macOS(arm64)에서 엔진 단위, 앱 단위, 앱 E2E(개발 빌드 + 패키징된 앱)로 검증했다. 결과는 아래 "결과" 절.

## 맥락

- [SPEC_스크립트-보기-편집](SPEC_스크립트-보기-편집.md) 이 화면(단계 문장 + 최근 실행 겹치기), 단계 단위 편집, 저장 버튼 + 변경 이력, AI 수정 요청을 정했다. 이 ADR 은 SPEC 이 정하지 않은 **구현 방식**을 기록한다: 직렬화(주석·순서 보존), 이력 저장 형식, 쓰기 경로, 실행 기록 해시, 비교, 화면 구조.
- 확인한 사실(2026-10-02, `yaml` 2.9.1)
  - `parseDocument` 의 노드는 `range [start, valueEnd, nodeEnd]` 를 가진다. 블록 시퀀스 항목의 `nodeEnd` 는 줄 끝 주석과 줄바꿈까지 포함한다. 첫 항목 앞 주석은 시퀀스 앞(키 줄 다음)에 있다.
  - Document 를 통째로 다시 문자열로 만들면(`toString`) 주석은 남지만 **서식이 정규화**된다 — 예: `[web-vitals, timing]` → `[ web-vitals, timing ]`(`flowCollectionPadding` 은 맵·시퀀스 공통 전역 옵션), 긴 줄 접기(`lineWidth`).
  - `Scalar.value` 만 바꾸면 따옴표 종류는 남고, 숫자처럼 보이는 문자열(`"12345"`, `"1,200"`)은 자동으로 따옴표가 붙어 타입이 유지된다.

## 결정

### 1. 단계 문장 — 엔진 core `describeStep` (의존성 없음, 하위 경로 export)

- `describeStep(step) → { action, icon, title?, sentence, details[], badges[], unstable, children? }`. 대상(역할+이름 · 라벨 · placeholder · 텍스트 · testId · CSS⚠ · n번째 · 정확히), 값 표기(🔒secret · {var} · [env]), 공통 옵션 배지, 묶음 재귀, `expect` 조건 줄마다, 다운로드 조건 한 줄. 깨진 단계에도 예외 없이 문장을 낸다(편집 중 반쯤 쓴 단계).
- `stepText(d)` = 비교용 한 줄(제목 + 문장 + 세부 + 배지).
- 파일 `src/dsl/describe.ts` 는 **타입 import 만** 쓴다. `@euta/core/describe` 하위 경로로 export 해 렌더러(Vite)가 그대로 번들한다 — core 본체는 playwright·node:fs 를 import 하므로 렌더러에서 쓸 수 없다. 메인 프로세스는 같은 함수를 본체 export 로 쓴다.
- 대안: 문장을 메인에서만 만들어 IPC 로 넘김 — 편집 중 키 입력마다 왕복이 생겨 기각(검증은 어차피 IPC 로 하지만 문장은 즉시 보여야 함).

### 2. 직렬화 — `rewriteScript(original, edit)`: 원문 이어 붙이기(splice) + Document 패치

- 편집 모델은 단계마다 **원본 경로**(`['steps', 3]`, `['steps', 2, 'group', 'steps', 0]`)를 들고 다닌다(`ScriptEdit { header, steps: StepEdit[{ src?, step, children? }] }`). 순서를 바꿔도·묶음을 옮겨도 같은 노드를 찾는다.
- 1차: **원문 이어 붙이기**. 최상위 키와 단계 항목을 원문 조각(chunk = 이전 항목 끝 ~ 이 항목 끝, 위쪽 주석·빈 줄 포함)으로 나눈다.
  - 바뀌지 않은 키·단계 → 원문 바이트 그대로(묶음 깊이가 바뀌면 들여쓰기만 이동).
  - 묶음 자체 필드는 같고 안쪽만 바뀜 → 묶음 머리 줄은 원문, 안쪽 단계만 다시 조립(재귀).
  - 바뀐 단계 → 원문 위쪽 주석 줄은 그대로 두고, 항목만 원래 노드의 복제본을 **필드 단위로 패치**(없어진 키 삭제, 있는 키는 제자리 수정, 새 키는 뒤에)해서 문자열로 만든다. 줄 끝 주석도 노드에 붙어 함께 간다.
  - 새 단계 → 생성. 단계 안의 짧은 맵·시퀀스(72자 이하)는 흐름 스타일 `{ ... }` 로(예제 파일과 같은 모양).
  - 새 머리 키는 `steps:` 바로 앞에 넣는다.
- 2차(대비책): 흐름 스타일 `steps: [ ... ]`, 한 줄 `steps: - ...` 같은 드문 배치는 Document 전체 패치 후 `toString({ lineWidth: 0 })`(주석 보존, 서식 정규화). YAML 이 깨진 원문은 처음부터 직렬화.
- 검증: 손대지 않은 모델 → **예제 파일 전부 바이트 동일**, 값 1개 변경 → 그 줄만 바뀜.
- 대안: (a) Document 통째 `toString` — 위 서식 정규화로 안 바뀐 줄까지 diff 에 나옴, 기각. (b) CST(`yaml` Lexer/Parser 토큰) 직접 편집 — 정밀하지만 노드 생성·들여쓰기 처리를 다 직접 해야 해 비용 큼. (c) 앱에 `yaml` 의존성 추가 — 엔진이 이미 YAML 정본(파서·검증)이라 core 에 둠, 앱 의존성 증가 없음.

### 3. 이력 저장 — 버전 = 그 시점 내용 스냅샷

```
<project>/script-history/keys.json             { paths: { <rel>: <scriptKey> }, deleted: [{ key, path, name?, at }] }
<project>/script-history/<scriptKey>/index.json [{ version, at, actor, kind, path, hash, summary }]
<project>/script-history/<scriptKey>/<version>.yaml   그 버전의 전체 내용(원문 그대로)
```

- 버전은 "쓴 **뒤** 내용 + 누가(actor) + 무엇(kind)". kind: `baseline`(이력 없던 파일 첫 기록) · `create` · `save` · `external` · `restore` · `rename` · `delete` · `undelete`. actor: `user` · `ai` · `recording` · `external` · `restore`.
- "직전 내용 보관"은 **쓰기 전 동기화**로 보장한다: 디스크 내용 해시 ≠ 마지막 버전 해시면 먼저 `external` 버전을 남긴 뒤 쓴다. 상세 화면을 열 때도 같은 동기화(앱이 꺼져 있던 동안의 변경도 잡힘).
- 같은 해시면 다시 기록하지 않는다(rename·delete·restore·undelete 는 강제 기록).
- `scriptKey` 는 무작위 id. 앱 이름 변경은 지도만 옮기고 `rename` 버전을 남긴다. 감시자가 본 "없어진 파일 + 내용 해시가 같은 새 파일"은 바깥 이름 변경으로 보고 이력을 잇는다.
- 삭제: 마지막 내용을 `delete` 버전으로 남기고 `deleted` 목록에 올린다. 복원은 원래 경로(차 있으면 `-2`)에 쓰고 키를 다시 붙인다.
- 스크립트당 최근 100개(`MAX_VERSIONS`), 번호는 재사용하지 않음. 쓰기는 `writeJsonAtomic`·버전 파일 0600.
- 대안: "직전 내용"만 보관(쓰기 전 내용 저장) — 마지막 버전이 현재 파일과 같지 않아 "누가 이 내용을 만들었나" 와 비교가 어색해 기각. SQLite — 버전 파일이 원문 그대로 남는 편이 복구·확인이 쉬워 JSON + 파일로.

### 4. 쓰기 경로 — `ProjectService.writeScript` 하나

- 앱 편집기 저장(user) · AI `save_script`(ai) · 녹화 "AI 없이 저장"(recording) · 되돌리기·삭제 복원(restore) · 새로 만들기·가져오기(user, create) 가 모두 이 함수를 지난다: 경로 검증 → (편집기) `baseHash` 충돌 검사 → 쓰기 전 동기화 → **숨김 임시 파일 + rename**(감시자는 `.` 파일 무시) → 버전 기록 → 작업 로그 `script.changed`(요약 = 비교 요약) / `script.restored` / AI 가 새로 만든 파일은 `script.created`(actor ai — 다른 생성 경로는 호출한 쪽이 자기 종류로 기록).
- AI 도구: `save_script` 에 `writeScript` 콜백(WorkspaceToolsOptions → AppTools → ChatContext)을 넣어 이 경로로 보낸다. 덮어쓰기 확인·`${env.*}` 자격증명 검사는 도구에 그대로.
- 자기 쓰기 표시: 감시자 무시 목록에 **쓴 내용의 해시**를 함께 둔다 — 2초 안이라도 디스크 내용이 다르면(바깥에서 바로 또 고침) 자기 쓰기로 보지 않는다.
- 감시자(바깥 변경): `external`(AI 대화가 도는 중이면 `ai` — 예: `session_export`), 없어짐 → `delete`.

### 5. 실행 기록 해시 — run.json `scriptHash` (엔진 필드)

- `runScript` 가 실제로 실행한 원문의 sha256(`scriptHash(text)`, 정규화 없음)을 RunContext 에 담아 run.json 최상위 `scriptHash` 로 남긴다(시작·종료 run.json 모두, 큰 `script` 객체보다 앞).
- 앱은 상세 화면에서 지금 파일 해시와 비교: 같으면 겹치기, 다르면 "수정 이후 아직 실행하지 않음" + 흐리게. 해시가 없는 예전 실행은 "다름".
- 대안: 앱 `meta.scriptHash` — 앱이 실행 직전에 따로 파일을 읽어야 해 실행 내용과 어긋날 틈이 있고, CLI·MCP·AI 실행에는 안 남아 기각. `index.sqlite` 열 추가 — 마이그레이션 위험, 최신 실행 1건은 run.json 을 읽으면 충분.
- 최근 실행 찾기: 프로젝트 `index.sqlite` 에서 같은 절대 경로의 최신 run → run.json `steps`(계층 id "3", "4.2", 다운로드 trigger "n.1")를 단계 경로와 위치로 맞춘다.

### 6. 비교 — 단계 문장 LCS

- 두 버전을 파싱 → 단계를 (깊이, `stepText`) 줄로 펼침(묶음 줄은 "(단계 n개)" 를 빼서 자식 추가가 묶음 변경으로 보이지 않게) → LCS. 연속한 삭제·추가 묶음 안에서 **같은 동작·같은 깊이**끼리만 "변경"(전→후)으로 짝짓는다. 머리 키는 이름별 비교(이름·설명·대상 주소·브라우저·변수·기본값·녹화).
- 요약: "단계 2개 추가, 1개 변경 · 머리 정보 변경: 이름" / "처음 기록 (단계 n개)" / "단계 변화 없음 (서식·주석만)". 이력 index 의 `summary`·작업 로그에 쓴다. 모듈은 `src/shared/script-diff.ts`(메인·렌더러 공용).

### 7. 검증 — 저장을 막는 것과 경고

- 편집 결과(직렬화한 텍스트)를 메인에서 검증한다(디바운스 200ms IPC). `${secrets.*}` 는 이름마다 자리값, 비어 있는 `${env.*}` 도 자리값을 넣어 **구조·참조 문법·`vars` 참조**만 저장을 막는다. 선택 환경에 없는 secret 이름은 경고(이름만). 시간·크기 형식 오류는 한국어 문장으로 바꿔 보여 준다.
- 저장 IPC 도 같은 검증을 다시 하고(렌더러를 믿지 않음) `baseHash` 가 다르면 `{ conflict }` 를 돌려준다. "내 것으로 저장" = `force`(바깥 변경은 동기화로 이력에 먼저 남음).

### 8. 화면 구조 (렌더러)

- `ScriptsTab` → 행 "보기"/이름 → `ScriptDetail`(목록 대신 같은 탭에, 탭 전환에도 유지). 모드: 보기 · 편집 · 이력.
- 편집 모델 `src/shared/script-model.ts`(순수 함수, 새 모델 반환): `toModel` · `toPayload` · `setStep` · `addStep` · `deleteStep` · `duplicateStep`(새 단계 = 원본 경로 없음) · `moveStep`/`moveUp`/`moveDown` · `groupIn`(위가 묶음이면 그 끝으로, 아니면 새 묶음으로 감쌈) · `groupOut`(묶음 바로 아래로) · `setHeader` · `issueStepPath`(검증 경로 → 단계).
- `StepForm.tsx`: 대상 고르기(종류 + 값, 역할 목록, n번째, 정확히), 값(일반 / 🔒secret 이름 목록 + 새 이름 / 변수 / 환경 변수), 동작별 필드 21종, `expect` 조건 추가·빼기, 측정 체크, 공통 옵션, 스텝 이름. 폼은 아는 필드만 바꾸고 나머지는 둔다. 머리 정보 폼(이름·설명·대상 주소·기본값·녹화·브라우저·변수).
- 끌어서 옮기기는 HTML5 drag & drop(같은 목록 안), 위/아래 버튼 병행. 단계 추가는 카드 아래·묶음 안·목록 끝의 분류 메뉴.
- 바깥 변경: `scripts:changed` 이벤트 때 상세를 다시 받아 해시가 달라졌으면 — 보기 모드는 갱신(+ 마지막 버전이 `ai` 면 배너 "AI 가 수정함 — 변경 보기" → 이력 비교), 편집 중 바뀐 것 있으면 충돌 알림("다시 불러오기" / "내 것으로 저장"), 편집 중 바뀐 것 없으면 조용히 다시 불러옴. 새 IPC 이벤트는 만들지 않았다.
- 저장하지 않은 변경 확인: 모듈 상태 `unsaved.ts` — 목록으로, 프로젝트 전환, 새 프로젝트·앱 설정 화면 이동 때 묻는다(탭 전환은 화면이 유지되므로 묻지 않음).
- AI 수정 요청: `requestScriptEdit` 가 선택 환경으로 새 채팅을 만들고 프롬프트(`scriptEdit: <path>` · 대상 단계 번호·문장 · 환경 · 요청 · 진행 지침)를 보낸 뒤 그 채팅을 연다. 시스템 프롬프트에 `SCRIPT_EDIT_GUIDE`(read_file → save_script overwrite → validate_script → 필요시 run_script → 단계 문장으로 보고). 가짜 에이전트는 `scriptEdit:` 를 다른 분기보다 먼저 보고 read_file → 단계 1개 추가 → save_script → validate_script 를 실제로 부른다.
- 스크린샷: `script:run-shot`(프로젝트 runs 에서 run 찾기 → `readArtifactImage`, Live 등록 없이).

- 바뀐 단계 안의 흐름 시퀀스는 `[ a, b ]` 로 정규화된다(그 단계만). 삭제한 단계 위의 주석은 함께 지워진다.
- 감시자의 바깥 이름 변경 인식은 내용이 똑같을 때만. 내용까지 바뀐 이동은 삭제 + 새 스크립트.
