# SPEC - 프로젝트(사이트) 단위 관리

> 상태: **구현 완료** (2026-10-02) — 단위·E2E(개발 빌드·패키징본) 검증. 구현 세부는 [ADR-016](ADR_016_프로젝트-저장소-구현.md). 결정 정본은 [PLAN 결정 사항](../20.프로젝트관리/PLAN_end-user-테스트툴-종합계획.md#결정-사항) "프로젝트 단위 관리" 4행.
> 참고 사례: naby(leonardo204/naby) — 앱 홈 한 곳에 데이터, 활동 로그는 append-only JSONL, 비밀값은 `safeStorage` 암호문. 코드는 참고만 했다(라이선스 없음).

## 목적

- 테스트 대상 사이트(서비스)마다 설정·스크립트·실행 이력·AI 대화·작업 기록을 **한 묶음(프로젝트)** 으로 관리한다.
- 모든 데이터는 **로컬에 영구 저장**한다(앱을 껐다 켜도 그대로). 저장 위치는 **앱 내부 저장소**(사용자 결정).
- 지금까지 앱 전역에 쌓인 데이터는 **이관하지 않는다**(사용자 결정) — 새로 시작한다. 옛 데이터는 지우지 않고 그대로 둔다.

## 용어

| 용어 | 뜻 |
|---|---|
| 프로젝트 | 테스트 대상 서비스 하나. 예: "고객 포털" |
| 환경 | 같은 서비스의 배포 단계. 예: dev · staging · prod. 환경마다 주소·변수·계정(secrets)이 다르다 |
| 스크립트 라이브러리 | 프로젝트에 속한 YAML 테스트 스크립트 모음 |
| 테스트 세트 (내부 이름 suite, 옛 화면 용어 "스위트") | 여러 스크립트를 묶어 한 번에 실행하는 단위 |
| 작업 로그 | 프로젝트에서 일어난 일(실행·AI 대화·스크립트 변경·설정 변경)을 시간순으로 남긴 기록 |

## 데이터 모델

```
Project      { id, name, description, defaultEnvId, browser: { engine, device?, headless },
               pinned, createdAt, lastOpenedAt }
Environment  { id, name, baseUrl, vars: {KEY: value}, secretNames: [NAME], secretsFile?, allowedDomains? }   ← 값은 vault (secretsFile 이 있으면 그 파일)
Suite        { id, name, scripts: [scriptPath], envId?, stopOnFailure }
SuiteRun     { id, projectId, suiteId, suiteName, envId, envName, stopOnFailure, startedAt, finishedAt?,
               status, cancelled?, interrupted?, items: [{ script, runId?, status }] }
ChatRecord   (ADR-015 형식 그대로, 프로젝트 폴더로 이동)
ActivityEvent{ at, kind, actor: user|ai|mcp|suite, summary, ref? }
```

- `id` 는 앱이 만든 짧은 무작위 문자열. 이름 변경과 무관하다.
- 실행(run)은 엔진 형식 그대로(`runs/<run-id>/` + `index.sqlite`) 프로젝트 폴더 안에 둔다.
- 변수(`vars`) 키가 자격증명처럼 보이면(`TOKEN`·`PASSWORD`·`API_KEY` 등) 저장을 거부한다 — secret 으로 넣는다(`${env.*}` 값은 마스킹되지 않으므로).
- `allowedDomains`(허용 도메인): secrets 가 들어간 입력 스텝을 실행할 수 있는 페이지 호스트 목록(아래 "secrets 규칙"). **없으면(옛 project.json 포함) 환경 주소의 호스트 1개가 기본값** — 기본값은 파일에 쓰지 않고 쓸 때 계산한다. 사용자가 목록을 저장하면 그 목록만 쓴다(빈 목록 = 어디서도 secrets 입력 안 함). 값 형식: 호스트 이름(`a.com`·`*.a.com`·`.a.com` 은 `a.com` 으로 정규화), 스킴·경로·포트는 저장할 때 떼어 낸다, 최대 20개.

## 저장 구조

```
<userData>/                               (macOS: ~/Library/Application Support/euta)
  app.json                                앱 전역: 최근 프로젝트 순서, 마지막 프로젝트, AI 기본 모델
  vault.json                              비밀값 암호문만 (safeStorage) — 키 = projectId/envId/NAME
  projects/<projectId>/
    project.json                          Project + Environment[] + Suite[]
    scripts/                              YAML 스크립트 (하위 폴더 허용)
    baselines/<envId>/                    시각 비교 기준 이미지 (환경별)
    runs/  + runs/index.sqlite            실행 결과 (엔진 형식)
    suite-runs/<suiteRunId>.json          테스트 세트 실행 묶음 결과
    suite-runs/<suiteRunId>/report.html   테스트 세트 리포트 (단계 14 — 옛 실행은 JSON 만, [리포트] 때 생성)
    chats/<chatId>.json                   AI 대화
    activity/<YYYY-MM>.jsonl              작업 로그 (append-only, 월 단위 파일)
```

- **쓰기 규칙**: JSON 은 임시 파일 → rename(원자적 교체). 작업 로그는 줄 단위 append(비정상 종료에도 앞선 기록 보존 — naby 와 같은 이유).
- **비밀값**: 화면에서 입력·교체·삭제만 가능하고 **다시 표시하지 않는다**(이름만 보임). `safeStorage` 가 OS 보안 저장소를 못 쓰는 환경이면 저장을 거부하고 경고한다. 외부 secrets 파일 지정도 계속 지원한다(환경 설정에서 선택). AI·로그·리포트에는 값이 가지 않는다(기존 마스킹 그대로).
- **삭제**: 프로젝트 삭제 = 확인 대화상자 → 프로젝트 폴더 + 해당 vault 항목 삭제.
- 기존 전역 데이터(`settings.json` · `runs/` · `chats/`)는 읽지 않는다(이관 없음).

## 실행과 환경

- 실행할 때 환경을 고른다(기본 = 프로젝트 기본 환경). 엔진에 넘기는 값:
  - `env`: 사용자 환경변수 + `BASE_URL = 환경.baseUrl` + 환경 `vars`
  - `secrets`: 환경의 vault 값(또는 지정한 외부 파일)
  - `runsDir` = 프로젝트 `runs/`, `baselineDir` = `baselines/<envId>/`, 브라우저 기본값 = 프로젝트 설정
- 스크립트는 지금처럼 `target.baseUrl: ${env.BASE_URL}` 로 쓴다 — **DSL 변경 없음**. 같은 스크립트를 환경만 바꿔 돌린다.
- 실행 기록(run.json)에 프로젝트 id·환경 이름을 남긴다 — 엔진 실행 옵션 `meta` 가 run.json 의 `meta` 객체로 기록(추가 필드, 기존 형식 유지). 스위트 실행이면 `suiteRunId`, AI 실행이면 `source: ai` 도 들어간다. History 의 환경 열은 이 값을 읽는다.
- 외부 secrets 파일을 고른 환경은 vault 대신 그 파일만 쓴다(합치지 않음).

### secrets 규칙 (모든 로컬 실행)

> PLAN_euta-cloud 결정 "secrets 규칙 적용 범위"(2026-10-21) — 로컬에서 통과한 스크립트가 클라우드에서도 똑같이 동작하고, 앱 AI 채팅의 프롬프트 인젝션으로 테스트 계정이 바깥으로 나가는 경로를 막는다.

| 규칙 | 내용 |
|---|---|
| secrets 사용 위치 | `${secrets.*}` 는 입력 스텝(`fill` 의 `value` · `type` 의 `text`, 그룹·다운로드 trigger 안 포함)에만. 그 밖(`goto` 주소 · `vars` · `expect` · `name` · target 등)에 쓰면 실행 전 검증 오류(브라우저를 띄우지 않고 실행 `error`) |
| 허용 도메인 | secrets 가 들어간 입력 스텝은 그 순간 페이지 호스트가 환경의 허용 도메인과 같거나 점 경계의 하위 도메인일 때만 실행, 아니면 그 스텝 오류 |
| 적용 경로 | **실행 버튼 · 테스트 세트 · 스크립트 상세 실행 · 앱 AI 채팅(`run_script`·`session_*`) · 고급 터미널의 외부 Claude Code/Codex 가 띄운 euta MCP 서버** — 사람·AI 구분 없이 같다 |
| 클라우드 전용(로컬엔 없음) | `input: os` 거절 · 녹화 기본값 `on-failure` — 로컬 실행은 지금처럼 OS 입력·녹화 기본값을 쓴다 |
| 허용 도메인 출처 | 로컬 프로젝트 = 환경의 `allowedDomains`(없으면 환경 주소 호스트). 클라우드 프로젝트의 이 PC 실행 = 서버 환경의 허용 도메인 |

- 엔진 실행 옵션 `restrictSecrets: true` + `allowedDomains`(ADR-024 결과 2026-10-21)를 모든 경로에 넘긴다. 고급 터미널에는 `EUTA_RESTRICT_SECRETS=1` · `EUTA_ALLOWED_DOMAINS=<프로젝트 모든 환경의 허용 도메인 합집합>` 을 더 준다(터미널은 환경을 고르지 않으므로 합집합).
- 위반은 한국어로 보인다: 검증 = "`${secrets.X}` 는 입력 스텝(fill·type)의 값에만 쓸 수 있습니다", 스텝 = "테스트 계정 입력 차단: 지금 페이지(호스트)는 허용 도메인이 아닙니다 — 프로젝트 설정 → 환경 → 허용 도메인". Run 탭 "검증"·스크립트 상세 경고에도 미리 보인다(저장은 막지 않음 — 서버 저장 규칙과 같음).

## 스크립트 라이브러리

- 프로젝트 `scripts/` 의 YAML 목록: 이름(스크립트 `name`), 경로, 최근 실행 상태·시각(프로젝트 `index.sqlite` 에서).
- 동작: 새로 만들기(빈 템플릿) · 가져오기(외부 파일 복사) · 이름 변경 · 삭제 · 내보내기(다른 곳에 저장) · 검증 · 실행 · 파일 열기(기본 편집기).
- 앱 안 편집기는 이번 범위 밖 — 외부 편집기 또는 AI 채팅으로 수정한다. 파일 변경은 감지해 목록을 갱신한다. → 단계 10 에서 앱 안 보기·폼 편집·이력으로 확장: [SPEC_스크립트-보기-편집](SPEC_스크립트-보기-편집.md)
- 가져오기·새로 만들기는 덮어쓰지 않는다(같은 이름이면 `이름-2.yaml`). 이름 변경·삭제는 테스트 세트의 참조도 고친다.

## 테스트 세트 (내부 이름 `suite`)

> **화면 용어는 "테스트 세트"** (2026-10-23 결정 — "스위트"는 일반 사용자에게 낯섦). 코드·API·저장 파일(`project.json.suites`, `suite-runs/`)·작업 로그 종류(`suite.*`)의 내부 이름은 `suite` 그대로 — 데이터 이전 없음. 앱·클라우드 웹·예약·알림의 화면 문구는 모두 "테스트 세트".

- 스크립트 여러 개를 순서대로 실행한다(직렬 — OS 입력·화면 점유와 충돌하지 않게, 병렬 없음). 옵션: 환경, 실패 시 중단.
- **항목별 "항상 실행"** — 표시한 스크립트는 앞 항목이 실패해 "실패 시 중단"이 걸려도, 사용자가 취소해도 실행한다(정리 스크립트용). 취소 때는 진행 중인 스크립트가 끝난 뒤 남은 항목 중 "항상 실행"만 돈다. 상태 계산에는 그대로 포함.
  - 저장: `Suite.alwaysRun`(스크립트 경로 목록, `scripts` 의 부분집합 — 없으면 표시 없음, 옛 파일 그대로) · 서버 `alwaysRun`(스크립트 id). 같은 스크립트가 두 번 들어 있으면 두 자리 모두 표시된다. 이름 변경·삭제가 표시도 고친다. → [ADR-031](ADR_031_테스트-세트-구현.md)
  - 클라우드 실행: 클라우드에는 "실패 시 중단"이 없어(실패해도 다음) 표시는 **취소**에만 작용한다 — 표시된 항목은 대기면 차례에 실행, 실행 중이면 끝까지(다시 취소해도). "실패 시 중단"은 이 PC 실행 옵션이다.
- 결과: 테스트 세트 실행 1건 = 각 스크립트 run 링크 + 전체 상태(최악값). History 에서 "테스트 세트: 이름" 묶음으로 보인다.
- 실행 중 취소: 남은 스크립트를 건너뛴다(진행 중인 스크립트는 끝까지 — 엔진에 중단 API 없음). 단 "항상 실행" 항목은 돈다.
- 한 프로젝트에서 동시에 테스트 세트 하나만 돈다.
- **화면 위치 — 스크립트 탭 안** (2026-10-23 결정). 스크립트 탭 위쪽 전환 `[스크립트 | 테스트 세트]`.
  - 테스트 세트 목록: 카드마다 이름 · 환경 · 항목 수 · **[▶ 실행]**(실행 위치 이 PC/클라우드는 실행 탭의 선택을 따름) · 최근 결과(상태 · 통과 수/전체 · 시각 · 소요 시간 · 첫 실패 스크립트) · 항목 순서(→, "항상 실행" 표시) · [편집].
  - **스크립트는 이름으로 보인다** — 카드·편집·진행·최근 결과 어디서나 스크립트 `name:`(굵게) + 파일 경로(작게, 흐리게). `name` 이 없으면 경로. 항목 추가는 **검색 + 여러 개 체크** 목록(이름·경로로 검색, 이미 들어 있는 스크립트 표시). **체크한 항목은 체크한 순서대로 목록 위로 모이고 순번(1, 2, …)을 보이며**, [선택한 N개 추가]는 그 순서대로 끝에 붙인다. 항목의 위로·아래로·빼기는 **테두리 있는 버튼**(▲ 위로 · ▼ 아래로 · ✕ 빼기)으로 — 텍스트 링크 아님 (상위 CLAUDE.md "UI 그라운드룰").
  - [+ 새 테스트 세트] → 이름 입력 → 바로 편집 상태.
  - 편집: 항목 추가(스크립트 선택) · 순서 ↑↓ · 빼기 · 항목별 "항상 실행" · 환경 · 실패 시 중단 · 이름 변경 · 삭제. 바뀌면 바로 저장(지금과 같음).
  - 실행 중에는 카드에 항목별 진행(대기 · 실행 중 · 통과 · 실패 · 건너뜀)과 [취소] — 이 PC 실행. 클라우드 실행은 실행 탭처럼 사전 검사 통과 후 시작하고 Live 로 간다(항목 진행은 Live 의 행). 카드는 마지막 이 PC 실행의 항목별 결과를 계속 보여 준다.
  - 스크립트 목록에서 여러 개 체크 → **[테스트 세트에 넣기]**(기존 세트 선택 또는 새로 만들기). 목록 순서로, 기존 세트면 아직 없는 스크립트만 뒤에 붙인다.
  - 클라우드 프로젝트: 편집·넣기는 온라인 + 편집자 이상(프로젝트 설정과 같은 조건), 보기 역할은 실행도 숨김.
  - 프로젝트 설정의 스위트 칸과 실행 탭의 스위트 영역은 없앤다(실행 탭은 단일 스크립트 실행 + Live 진입만).
- 앱이 실행 도중 종료되면 다음 실행 때 남은 항목을 건너뜀으로 닫고 "앱 종료로 중단" 으로 표시한다.

### Live 화면 — 테스트 세트 묶음 (2026-10-23)

- 테스트 세트 실행 중이면 Live 맨 위에 **세트 머리**: 세트 이름 · 환경 · 진행(완료 수/전체) · 경과 시간 · [취소] 버튼.
- 그 아래 **항목 목록**(스크립트 이름 + 작은 파일명, 순번): 대기 · 실행 중 · 통과 · 실패 · 건너뜀 · 항상 실행 표시. **실행 중인 항목은 펼쳐져** 기존 Live 내용(현재 단계·스크린샷·로그)을 그대로 보인다. 끝난 항목은 접혀 있고 눌러서 펼친다.
- 세트에 속하지 않은 단독 실행은 지금처럼 따로 보인다. 클라우드 세트 실행도 같은 묶음 모양(클라우드 Live 피드의 부모·자식 실행).
- 구현(단계 14, [ADR-032](ADR_032_테스트-세트-리포트-Live-구현.md)): 왼쪽 실행 목록에 세트는 한 줄(이름 · 상태 · 완료/전체 · 환경)이고 그 세트의 스크립트 실행은 목록에서 빠진다. 세트를 고르면 오른쪽에 머리 + 항목 목록, 항목 머리를 눌러 펼치고 접는다(펼친 안은 단독 실행 화면과 같음). 끝나면 모두 접히고 머리에 [리포트]. 바깥(History "Open")에서 끝난 항목을 열면 그 항목만 펼친다. 클라우드 세트의 펼친 항목은 서버 요약(단계)이다.

### 테스트 세트 리포트 (2026-10-23)

- **자동 생성** — 세트 실행이 끝나면 `suite-runs/<suiteRunId>/report.html`(스크린샷을 넣은 파일 1개, 외부 요청 없음). 앱에서 [리포트] 버튼으로 연다: 테스트 세트 카드의 최근 결과 옆 · History 의 테스트 세트 묶음 줄 · Live 세트 머리(끝난 뒤).
- **내용 — 요약 + 실패 상세**:
  - 머리: 세트 이름 · 프로젝트 · 환경 · 시작·끝 시각 · 소요 시간 · 실행 위치(이 PC/클라우드) · 전체 상태 · 통과 수/전체.
  - **지난 실행 대비**(같은 세트·같은 환경의 직전 세트 실행): 새로 실패 · 회복 · 계속 실패 · 그대로 통과 개수와 해당 스크립트.
  - 스크립트별 표: 순번 · 이름(파일명 작게) · 상태 · 소요 시간 · 항상 실행 표시 · 개별 리포트 링크.
  - **실패한 스크립트마다**: 실패한 단계 문장(`describeStep`) · 오류 메시지 · 그 단계 스크린샷 · (있으면) 선택자 점검 판정 요약.
  - secrets 는 실행 기록처럼 가린 값만.
- 범위 밖: PDF·HTML 파일 따로 내보내기(파일은 결과 폴더에 있으므로 필요하면 후속), 모든 단계 상세.
- 구현 세부(단계 14, [ADR-032](ADR_032_테스트-세트-리포트-Live-구현.md)):
  - 저장: `suite-runs/<id>.json` 은 그대로 두고 옆에 `suite-runs/<id>/` 폴더. 옛 실행은 [리포트] 를 처음 누를 때 만든다.
  - 지난 실행 대비: 스크립트 목록이 같으면 순번으로, 다르면 스크립트 + 몇 번째 등장으로 짝짓는다. 이번에 실행된 항목만 분류한다 — 이번 실패 + 지난번 실패 아님(통과·건너뜀·없음) = 새로 실패, 이번 통과 + 지난번 실패 = 회복. 이번에 건너뛴 항목과 지난번에 안 돌고 이번에 통과한 항목은 넣지 않는다.
  - 실패 단계 문장은 그 실행 당시 스크립트(실행 기록에 담긴 원문)로 만든다. 스크린샷은 실패 단계의 것만 넣는다.
  - 선택자 점검은 `dom/` 이 있는 실패 항목만, 리포트당 최대 5건 · 건당 20초(넘으면 생략).
  - 개별 리포트 링크는 앱 리포트 창에서 그 실행의 리포트를 새 창으로 연다.
  - 클라우드 [리포트] 는 앱이 웹 실행 상세를 시스템 브라우저로 연다(History 클라우드 세트 줄 포함). 웹 화면은 서버 `GET …/runs/:runId/suite-report` 를 쓴다([SPEC_클라우드-실행-예약 실행 화면](SPEC_클라우드-실행-예약.md#실행-화면-웹-c4)).
- **클라우드** — 클라우드 세트 실행은 웹 실행 상세(`/projects/:id/runs/:runId`, 세트 부모 실행)가 같은 내용의 리포트 화면이 되고, 앱 [리포트] 는 그 웹 링크를 연다. Teams 알림의 "실행 보기" 링크도 이 화면.

## 작업 로그 타임라인

- 기록하는 일 (`kind`): `project.created/updated` · `env.created/updated/deleted` · `secret.set/removed`(이름만) · `script.created/imported/renamed/deleted/changed` · `run.started/finished` · `suite.started/finished` · `chat.started` · `chat.turn`(사용자 요청 첫 120자 + 사용한 euta 도구 이름) · `settings.changed`
- `actor`: 사용자 직접(user) · AI 채팅(ai) · 외부 MCP(mcp) · 테스트 세트(suite — 화면 라벨 "테스트 세트").
- 기본 정보(이름·설명·고정)는 `project.updated`, 기본 브라우저·기본 환경·앱 AI 모델 변경은 `settings.changed`.
- 바깥에서 바뀐 스크립트 파일은 `script.created/deleted/changed` 로 남긴다. 행위자는 그 프로젝트 AI 채팅이 응답 중이면 ai, 아니면 user(파일 이벤트로는 구분할 수 없어 추정).
- 요약은 기록 직전에 프로젝트의 모든 secret 값으로 한 번 더 마스킹한다.
- 화면: 시간 역순 목록, 종류·행위자 필터, 항목 클릭 시 해당 run/채팅/스크립트로 이동.
- 비밀값은 어떤 경우에도 기록하지 않는다.

## AI 채팅과 프로젝트

- 대화는 프로젝트에 속한다(`chats/`). 프로젝트를 바꾸면 그 프로젝트의 대화 목록이 보인다.
- 채팅 작업 폴더 = 프로젝트 `scripts/` — AI 가 저장한 스크립트가 바로 라이브러리에 나타난다.
- 채팅 상단에 실행 환경 선택. AI 의 `run_script` · `session_open` 은 그 환경의 주소·변수·secrets 로 실행된다.
- 시스템 프롬프트에 프로젝트 이름·환경 목록(이름·주소)·secrets **이름** 을 넣는다.
- 새 채팅의 환경 = 프로젝트 기본 환경. 응답 중에는 환경을 바꿀 수 없다. 환경을 바꾸거나 그 환경의 주소·변수·secrets 가 바뀌면 다음 턴에 도구가 새 설정으로 다시 만들어진다(그 채팅이 연 AI 브라우저 세션은 닫힘).

## 외부 경로 (MCP·플러그인·고급 터미널)

- 고급 터미널에서 띄운 CLI 에는 `EUTA_RUNS_DIR` = 현재 프로젝트 `runs/` 를 준다(+ secrets 규칙 `EUTA_RESTRICT_SECRETS`·`EUTA_ALLOWED_DOMAINS`, 위 절) — 외부 Claude Code 가 MCP 로 돌린 실행도 그 프로젝트 이력에 쌓인다(Live·작업 로그에도 `mcp` 로 보임). 프로젝트를 바꾸면 그 화면의 터미널은 닫히고, 새 터미널은 새 프로젝트의 runs 폴더로 뜬다.
- 앱 밖에서 단독으로 쓰는 MCP 서버·플러그인 동작은 바꾸지 않는다.

## 화면 구성

- **프로젝트 선택**: 왼쪽 사이드바(프로젝트 목록 — 고정·최근순, 새 프로젝트). 첫 실행이면 "새 프로젝트 만들기" 안내.
- **프로젝트 안 탭**: 스크립트(위쪽 전환 스크립트 | 테스트 세트) · 실행(Run) · Live · History · AI · 작업 로그 · 프로젝트 설정(기본 정보·환경(주소·변수·허용 도메인)·secrets·기본 브라우저).
- **앱 설정**(전역): AI 기본 모델 등 프로젝트와 무관한 것만.
- 실행 중인 Live 는 프로젝트를 바꿔도 이어서 진행된다(다른 프로젝트 실행은 사이드바에 진행 표시).
- 앱을 다시 켜면 마지막으로 연 프로젝트가 열린다.
- 프로젝트 삭제 확인은 프로젝트 이름을 입력하는 앱 안 확인창이다. 실행 중인 run·테스트 세트·응답 중인 AI 채팅이 있으면 삭제를 거부하고 이유를 보인다.
- vault 를 쓸 수 없는 환경이면 프로젝트 설정의 secrets 영역과 앱 설정에 경고가 보이고 저장 버튼이 비활성화된다.

## 완료 기준 (검증)

- 단위: 프로젝트·환경·스위트 저장소(원자적 쓰기, 재시작 후 복원), vault(값 미노출, 비보안 백엔드 거부), 작업 로그(append·월 회전·필터), 실행 옵션 조립(환경 → env/secrets/runsDir/baselineDir), 스크립트 라이브러리 스캔·가져오기·이름 변경, 테스트 세트 실행(순서·실패 시 중단·항상 실행·취소·결과 묶음), 항상 실행 표시의 옛 파일 호환·이름 변경 추적·클라우드 왕복.
- E2E(개발·패키징본): 프로젝트 생성 → 환경 2개(픽스처 사이트 주소) → secrets 입력 → 스크립트 가져오기 → 환경별 실행 → History·작업 로그 확인 → 스크립트 탭에서 테스트 세트 만들기·편집 → 실행(중간 실패에도 항상 실행 항목 실행) → Live 세트 묶음(실행 중 항목 펼침 → 끝나면 접힘) → [리포트](요약 · 표 · 실패 단계 문장 · 스크린샷) → 한 항목 결과를 바꿔 다시 실행 → 리포트 "새로 실패" → **앱 재시작 후 모두 유지** → AI 채팅(가짜 에이전트)이 프로젝트 환경으로 실행 → 프로젝트 삭제.
- 비밀값이 어떤 파일(프로젝트 폴더·로그·채팅·리포트)에도 평문으로 없음을 검사.
