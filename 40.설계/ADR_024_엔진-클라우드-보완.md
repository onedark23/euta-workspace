# ADR - 024 엔진 클라우드 보완 구현

## 상태

채택 (2026-10-20, 구현 — C1 엔진 부분). euta-engine 커밋 `bf0469d`. macOS(arm64)에서 단위·픽스처 사이트 E2E·CLI 테스트로 검증했다. 결과는 아래 "결과" 절.

## 맥락

- [ARCH_euta-cloud 엔진 보완](ARCH_euta-cloud.md#엔진-보완-dsl-spec-갱신-후-구현) · [SPEC_test-script-dsl](SPEC_test-script-dsl.md) 이 엔진 보완 4건을 정했다: 시간 단위 `h`, `wait.reload`, `record` 의 `on-failure`, 클라우드 실행 옵션(`input: os` 거절 · 녹화 기본값 · secrets 사용 위치 · 허용 도메인). 서버는 브라우저 없이 같은 규칙으로 사전 검사를 해야 한다([SPEC_클라우드-실행-예약 사전 검사](SPEC_클라우드-실행-예약.md)).
- 이 ADR 은 SPEC 이 정하지 않은 **구현 방식**을 기록한다: 새로고침 간격의 기준 시각, 한 번의 새로고침에 주는 시간, `on-failure` 파일을 지우는 시점, 옵션 이름과 기본값, 도메인 비교 규칙, 사전 검사 API.
- 확인한 사실: 엔진의 `page.setDefaultNavigationTimeout` 은 스텝 `timeout` 이다 — `timeout: 3h` 스텝 안에서 `page.reload()` 를 그대로 부르면 한 번의 새로고침이 최대 3시간을 잡을 수 있다. Playwright `tracing.stop()` 은 `path` 없이 부르면 기록을 버린다.

## 결정

### 1. 시간 단위 `h`

- `DURATION_PATTERN` 에 `h` 를 더하고(×3,600,000) JSON Schema 설명을 고친다. 다른 단위와 같이 소수(`1.5h`)·대소문자 무관.

### 2. `wait.reload` — 조건 폴링 + 간격마다 새로고침

- 스키마: `wait` 에 `reload`(시간). zod refinement 로 `for` 가 `visible`·`hidden`·`url` 일 때만 허용, `ms`·`network-idle` 과 함께면 오류, 10초 미만이면 오류(`MIN_RELOAD_INTERVAL_MS`). 이 두 조건은 JSON Schema 로 표현하지 않는다(엔진 검증에서만 잡힘).
- 실행: 조건을 직접 폴링한다(`visible` = 보이는 요소 1개 이상, `hidden` = 0개, `url` = 현재 주소 일치). 기존 `wait` 의 `waitFor`/`waitForURL` 은 스텝 timeout 동안 막혀 간격마다 끊을 수 없어 쓰지 않는다.
- **간격의 기준 = 마지막 페이지 `load` 이벤트.** 실행기가 `page.on('load')` 로 시각을 기억한다. 스텝 시작 전에 로드가 한 번도 없으면 스텝 시작 시각. 기다리는 중에 페이지가 스스로 다시 로드되면 그 시각부터 다시 센다.
- **한 번의 새로고침과 그 뒤 `settle` 은 각각 `min(남은 시간, 간격)` 까지.** 새로고침이 실패(시간 초과·네트워크 오류)하면 경고 로그만 남기고 계속 기다린다 — 몇 시간짜리 대기가 한 번의 느린 응답으로 끝나지 않게.
- `settle` 은 스텝 `settle` → `defaults.settle` → `network-idle` 순(`wait` 은 원래 settle 대상이 아니라 새로고침 뒤에만 명시적으로 적용).
- 새로고침 횟수 `reloads` 를 스텝 결과(run.json)·`step.finished` 이벤트·report.html("reloaded n×")에 남긴다. 새로고침마다 `log`(info) 1줄. 시간 초과는 스텝 `error`: `target not visible after 12000ms (reloaded 1 time)`.
- 단계 문장: `'분석 완료' 텍스트 보일 때까지 5m마다 새로고침하며 기다리기`(사라질 때까지 · 주소에 … 포함될 때까지 동일).

### 3. `record` `on-failure` — 참조가 생기기 전에 버림

- `video`·`trace` = `true | false | 'on-failure'`. 실행 중에는 `true` 와 똑같이 기록한다.
- 종료 처리(`finalize`)에서 **증거 파일을 저장하기 전에 실행 상태를 먼저 계산**한다(스텝은 이미 끝났고 검증 오류·치명 오류도 정해져 있음). `on-failure` 이고 상태가 `passed` 면:
  - trace: `tracing.stop()` 을 경로 없이 호출(기록 폐기). `trace.zip` 을 만들지 않는다.
  - video: 컨텍스트를 닫은 뒤 원본 파일을 지운다. `video/video.webm` 으로 옮기지 않는다(빈 `video/` 폴더는 다른 실행과 같이 남음).
  - 두 경우 모두 `artifact.saved` 이벤트를 내지 않고, 버린 항목 이름을 담은 `log`(info) 1줄만 남긴다(예: `trace and video discarded (record: on-failure, run passed)`, video 만 `true` 면 `trace discarded (…)`).
- 그래서 steps.jsonl · run.json · report.html 어디에도 지운 파일 경로가 처음부터 없다. run.json `record` 에는 설정값(`on-failure`)이 그대로 남는다.

### 4. 클라우드 실행 옵션 — 엔진 옵션 `cloud` · `allowedDomains`, CLI `--cloud` · `--allowed-domains`

- 엔진: `runScript(…, { cloud: true, allowedDomains: ['a.com'] })`(`BaseRunOptions` — `openSession` 도 같은 옵션). CLI: `euta run <script> --cloud --allowed-domains a.com,b.com`(쉼표 구분, 여러 번 줘도 됨).
- `cloud` 가 켜는 것 ①②③④:
  - ① `input: os`(스텝·그룹·`defaults.input`·`expectDownload.trigger`) → **검증 오류**. 보간한 스크립트로 검사한다(`input: ${vars.mode}` 도 잡힘).
  - ② `record.video`·`trace` 기본값 = `on-failure`. 스크립트 `record` 에 적은 값이 우선.
  - ③ `${secrets.*}` 가 `fill.value`·`type.text` 밖(그룹·다운로드 trigger 깊이 포함)에 있으면 **검증 오류** — 위반 위치마다 하나(`steps[0].goto`, `vars.a`, `steps[2].fill.target.label` …). 보간 전 원문으로 검사한다.
  - ④ 도메인 검사(아래). 목록을 주지 않으면 빈 목록 = **secrets 입력 스텝은 어디서도 실행 안 됨(fail closed)**. 러너는 항상 목록을 넘겨야 한다.
- ①③ 실패는 기존 검증 오류와 같은 경로: 브라우저를 띄우지 않고 실행 상태 `error`, run.json `validationIssues`, CLI 종료 코드 2. 로컬 헤드리스 `input: os` 거절(실행 `error`, ADR-013)보다 먼저 판정한다.
- `--allowed-domains` 만 주면 ④만 켠다(로컬 실행 적용 여부는 열린 결정이라 기본은 끔).
- 세션(`openSession`): `defaults.input: os` 는 열 때 `ScriptValidationError`, 스텝마다 ①③ 을 `prepareStep` 뒤에 검사(경로 `step.…`), ②④ 는 실행과 같은 코드.

### 5. 허용 도메인 비교

- 대상: secrets 참조가 들어간 `fill`·`type` 스텝(보간 전 원문의 인자 전체에서 `${secrets.*}` 를 찾음 — 마스킹 대상 입력란을 정하는 기존 기준과 같음). 동작 직전에 `new URL(page.url()).hostname` 을 검사한다.
- 규칙: 소문자 비교, **호스트 이름만**(포트·스킴 무시), 정확히 같거나 점 경계의 하위 도메인(`login.a.com` ⊂ `a.com`, `evil-a.com` ⊄ `a.com`). 목록 값의 `*.`·앞뒤 점은 정규화한다. `about:blank` 처럼 호스트가 없으면 거절.
- 거절 = 스텝 `error`: `secret input blocked: page host "127.0.0.1" is not an allowed domain (localhost, example.com)`. 값은 메시지에 넣지 않는다(어차피 마스킹되지만 원천 차단).

### 6. 사전 검사 API — `cloudPrecheck`

```ts
import { cloudPrecheck } from '@euta/core';            // 또는 '@euta/core/precheck'
cloudPrecheck(source: string | object, opts?: { vars?: Record<string, string|number|boolean>; env?: Record<string, string|undefined> })
  → { issues: { kind: 'validation' | 'os-input' | 'secret-placement'; path: string; message: string }[]; secretNames: string[] }
```

- 순서: YAML 파싱 → secrets 이름 수집 → 이름마다 **자리값**을 넣고(`${run.*}` 도 자리값) `prepareScript` 로 스키마·참조 검증 → `input: os`(검증 통과 시 보간본, 아니면 원문) → secrets 사용 위치(원문). 실행 옵션 `cloud` 와 같은 함수(`src/dsl/cloud.ts`)를 쓴다.
- `env` 기본값은 `{}` — 서버 프로세스 환경변수를 쓰지 않는다. 스크립트가 `${env.*}` 를 쓰면 서버가 환경 변수를 넘겨야 한다. `vars` 도 같은 방식.
- `secretNames` 는 값 없이 이름만(정렬·중복 제거) — 서버의 "환경에 등록된 테스트 계정인지" 검사와 동시 실행 키에 쓴다. 없는 이름 검사는 서버 몫.
- 하위 경로 `@euta/core/precheck` 는 실행기·저장소·이미지 비교 모듈을 싣지 않는다. 다만 `load.ts` 가 장치 프리셋 검증에 `playwright` 의 `devices` 표를 import 하므로 playwright 패키지는 로드된다(브라우저는 띄우지 않음). 실측 import 약 0.4초.
- 기타 export: `osInputIssues` · `secretPlacementIssues` · `secretNamesOf` · `hostAllowed` · `normalizeDomains` · `MIN_RELOAD_INTERVAL_MS`.

## 고려한 대안

- **새로고침 간격 기준을 스텝 시작 시각으로** — 구현은 더 단순하지만 SPEC 문구("마지막 로드 후")와 다르고, 앞 스텝에서 오래 머문 뒤 들어온 경우 불필요하게 한 간격을 더 기다린다. 기각.
- **`wait.reload` 에 기존 `waitFor`/`waitForURL` 을 짧은 timeout 으로 반복** — 매 반복 예외 처리와 locator 재시작 비용이 있고, 결과적으로 폴링과 같다. 직접 폴링으로.
- **`on-failure` 파일을 정상 저장한 뒤 지우고 run.json·report 에 "삭제됨" 표시** — 이미 낸 `artifact.saved` 이벤트(라이브 구독자·steps.jsonl)를 되돌릴 수 없어 "참조하는데 파일이 없는" 상태가 생긴다. 상태를 먼저 계산하면 표시가 필요 없다. 기각.
- **CLI 개별 플래그(`--no-os-input` · `--secrets-in-input-only` · `--record-default on-failure`)** — 러너는 늘 셋을 같이 켜고, 규칙이 출처에 따라 달라지지 않게 하는 것이 SPEC 의 의도(SPEC_클라우드-MCP "적용 범위"). 묶음 `--cloud` + 목록 `--allowed-domains` 로.
- **`--cloud` 인데 목록이 없으면 `target.baseUrl` 의 호스트를 기본값으로** — 스크립트가 baseUrl 을 바꾸면 허용 범위도 따라 바뀌어 보안 규칙의 의미가 없다. 서버가 환경 주소로 기본 목록을 만든다(SPEC_클라우드-MCP). 엔진은 fail closed. 기각.
- **사용법 오류(목록 없는 `--cloud` 거절)** — 러너 버그 시 실행 자체가 안 돼 원인 파악이 오히려 어렵고, 테스트 계정이 없는 스크립트는 목록이 필요 없다. 스텝 오류로.
- **`load.ts` 에서 playwright `devices` 를 분리해 precheck 를 playwright 없이** — 장치 목록을 따로 복사·동기화해야 한다. 서버는 어차피 엔진 패키지(playwright 포함)를 의존하므로 지금은 하지 않는다.

CLI `euta run --restrict-secrets`. 엔진 MCP 서버: `ServerConfig.restrictSecrets` · `allowedDomains`(환경변수 `EUTA_RESTRICT_SECRETS` · `EUTA_ALLOWED_DOMAINS`(쉼표 목록, 빈 값 = 빈 목록 = fail closed) 또는 `--restrict-secrets` · `--allowed-domains`, 기본 끔 — 앱 밖 단독 사용은 동작 불변) → `run_script`·`session_open` 에 전달, `validate_script` 결과에도 위치 위반을 더한다(검증 통과 후 실행 오류가 나지 않게). 두 환경변수는 `${env.*}` 에서 숨긴다. 위치 위반 문구에서 "in cloud runs" 를 뺐다(`… only allowed in the value of a fill or type step (secret placement rule)` — 로컬에서도 같은 문구, 서버 사전 검사는 자체 문구라 영향 없음). 대안: `cloud` 를 쪼개 개별 플래그 3개(기각했던 안 — 러너는 여전히 묶음이 맞음) / 앱이 실행 전에 `secretPlacementIssues` 를 직접 호출(MCP·세션 스텝 경로를 덮지 못함). 테스트 194 → **198**(e2e: 위치 위반 `error`·`input: os` 는 검증 오류 아님·녹화 기본값 그대로·도메인 거절·세션 스텝 / CLI: 종료 코드 2 / MCP: `validate_script`·`run_script`·도메인 게이트·`loadConfig` 환경변수·플래그).
- 남은 한계
