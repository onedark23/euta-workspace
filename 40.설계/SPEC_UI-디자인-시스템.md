# SPEC - UI 디자인 시스템 (앱 · 웹 공통)

> 상태: **구현 완료** (2026-10-23, 웹 [ADR-033](ADR_033_UI-디자인-시스템-웹-구현.md) · 앱 [ADR-034](ADR_034_UI-디자인-시스템-앱-구현.md), dev 배포 서버 `4c3fec9`). 실사용 확인 대기. 결정 정본은 [PLAN 결정 사항](../20.프로젝트관리/PLAN_end-user-테스트툴-종합계획.md#결정-사항) "UI 디자인 시스템". 시안 B "부드러운 카드형" 채택.
> 이 문서가 토큰 값의 **정본**이다. 각 레포의 토큰 파일은 이 표의 사본이며, 값을 바꿀 때는 이 문서를 먼저 고친다.
> 별개 기능: Figma 대조 검수는 [SPEC_디자인-검수](SPEC_디자인-검수.md) — 이 문서와 무관하다.

## 목적

- 디자이너 없이 앱(euta-app)과 웹(euta cloud)을 **깔끔하고 처음 쓰는 사람도 편한** 한 제품처럼 보이게 한다.
- 화면마다 색·간격·크기를 새로 고르지 않도록 **선택지를 토큰과 공통 컴포넌트로 고정**한다. 새 화면은 여기 있는 것만 쓴다.
- 범위 밖: 일러스트·애니메이션 체계, 마케팅 페이지, 실행 리포트 HTML(`suite-report.ts` 의 자체 스타일 — 따로 다룬다).

## 원칙

- 상위 `CLAUDE.md` UI 그라운드룰을 그대로 따른다 — 이름으로 보이고 고르기(파일명·ID 는 옆에 작게), 조작은 **아이콘 + 글자 버튼**, 여러 개 고르기는 **검색 + 체크 + 순번**, 바꾼 화면은 캡처로 확인.
- 색은 **역할**로만 쓴다. 컴포넌트 CSS 에 색 값을 직접 쓰지 않고 토큰만 쓴다.
- 강조색(남색)은 화면당 **주 동작 하나**에만 채운다. 주황(포인트)은 선택 표시·현재 위치처럼 작은 면적에만.
- 상태(통과·실패 등)는 색 + 글자로 함께 보인다. 색만으로 구분하지 않는다.

## 테마 (밝은 / 다크)

- 기본은 **OS 설정을 따른다**. 사용자가 설정에서 **시스템 / 밝게 / 어둡게** 로 고정할 수 있다.
- CSS 구조는 두 레포 같다: `:root` 에 밝은 값 → `@media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) {…} }` → `:root[data-theme="dark"] {…}`. 다크 블록에 `color-scheme: dark`.
- **앱**: 설정 탭의 "화면 테마" 선택을 앱 설정에 저장하고 main 이 `nativeTheme.themeSource` 로 건다(Electron 이 `prefers-color-scheme` 을 그 값으로 바꾼다 — `data-theme` 불필요).
- **웹**: 상단 계정 메뉴의 "화면 테마" 선택을 `localStorage` 에 저장하고 `<html data-theme>` 로 건다. "시스템" 이면 속성을 지운다. 첫 그림 전에 적용(깜빡임 방지 — `index.html` 의 작은 인라인 스크립트).

## 글꼴 · 아이콘

- 글꼴: **Pretendard 가변 글꼴**(OFL) 을 npm `pretendard` 패키지로 받아 번들에 포함한다 — 앱은 오프라인에서도 같은 글꼴, 웹은 외부 CDN 없이 자체 제공.
- 아이콘: **lucide-react** 하나만. 크기 16(기본)·14(작은 버튼)·18(빈 화면), 선 굵기 2, 색은 글자색을 따른다(`currentColor`).
- 정확한 패키지 버전은 구현 ADR 에 기록한다.

## 공통 컴포넌트

레포마다 `ui/` 폴더에 둔다(앱 `src/renderer/src/ui/`, 웹 `packages/web/src/ui/`). 이름·속성·모양은 두 레포 같게.

| 컴포넌트 | 쓰임 · 규칙 |
|---|---|
| `Button` | 종류 `primary`(강조 면, 화면당 하나) · `secondary`(기본, 테두리) · `ghost`(테두리 없음, 보조 동작) · `danger`(빨간 글자·테두리, 삭제·빼기). 크기 `md`/`sm`. **아이콘 + 글자**가 기본, 아이콘만인 버튼은 툴팁 필수. 비활성은 투명도 .45 |
| `IconButton` | 공간이 좁은 반복 행(순서 바꾸기 등)에서만. 툴팁 필수, 누르는 영역 30px 이상 |
| `TextField` · `TextArea` · `Select` | 라벨 위, 도움말·오류는 아래 `--fs-xs`. 오류는 `--bad` 테두리 + 문구. 높이 `--h-md` |
| `Checkbox` · `Switch` | 체크 = `--accent` 면 + 흰 체크. 켜기/끄기 설정은 Switch |
| `Card` | 내용 묶음. 안쪽 여백 `--sp-4`, 모서리 `--r-lg` |
| `Table` | 머리 `--fs-xs` 600 `--muted`, 행 구분선, hover `--surface-2`. 이름 칸은 **이름(굵게) + 아래 파일명(작게, mono)** |
| `Badge` | 상태 표시. 아래 "상태 매핑" 표대로. 점 + 글자, 알약 모양 |
| `Tabs` | 알약형 묶음(`--surface-2` 바탕 위 선택 탭만 `--surface` + 그림자) |
| `Dialog` | 확인·편집 창. `--overlay` 위 `--surface` + `--shadow-2`. 확인 버튼은 오른쪽 끝, 위험한 동작은 `danger` |
| `Tooltip` | 아이콘만인 버튼·잘린 이름에. 지연 400ms |
| `EmptyState` | 아이콘(원형 `--accent-soft`) + 한 줄 제목 + 한 줄 설명 + 다음 동작 버튼 하나 |
| `PickList` | **검색 + 체크 + 순번** — 체크한 항목이 체크 순서대로 위로 모이고 순번 원(`--accent`)이 붙는다. 앱 테스트 세트 고르기(2026-10-23 구현)가 기준 동작이며 모양만 이 토큰으로 맞춘다 |
| `PageHeader` | 화면 제목(`--fs-xl` 700) + 오른쪽 동작 버튼들 |
| `Toast` | 저장·삭제 결과 한 줄. 4초 후 사라짐, 오류는 닫을 때까지 |

### 상태 매핑

| 상태 | 배지 글자 | 토큰 |
|---|---|---|
| 통과 | 통과 | `ok` |
| 실패 · 오류 | 실패 / 오류 | `bad` |
| 실행 중 · 대기열 | 실행 중 / 대기 중 | `run` |
| 불안정(flaky) · 경고 | 불안정 / 주의 | `warn` |
| 취소 · 건너뜀 · 아직 안 함 | 취소 / 건너뜀 / 대기 | 회색(`--surface-2` 바탕 + `--muted` 글자) |
| 수동 확인 필요(도달한 `manual` 단계 — 상태 `skipped` + `manual` 표시, `error` 없음) | 수동 확인 필요 | `manual`. 앞 단계 실패로 도달 못 한 `manual` 은 건너뜀(회색) |

## 화면 골격

- **앱**: 왼쪽 사이드바(`--surface`, 폭 210) — 로고 + `euta` · 프로젝트 목록 · 아래 설정. 현재 항목은 `--accent-soft` 바탕 + `--accent` 글자. 오른쪽 본문(`--bg`) 에 `PageHeader` + 카드들.
- **웹**: 위 헤더(`--surface`) — 로고 + `euta cloud` · 프로젝트 이동 · 계정 메뉴(테마 선택 포함). 프로젝트 안은 지금 구조대로 프로젝트 머리 + 탭(현황 · 스크립트 · 실행 이력 · 예약 · 테스트 세트 · 작업 로그 · 설정) — 탭 모양만 `Tabs` 로. 본문 최대 폭 1200px.
- 화면 구조(메뉴 위치·탭 구성)는 이번 적용에서 바꾸지 않는다 — 모양만 바꾼다.
- 본문 여백 `--sp-6`, 카드 사이 `--sp-4`.

## 글쓰기

- 사용자가 아는 말로 쓴다(내부 용어·영어 상태값을 그대로 보이지 않는다). 버튼은 하는 일 그대로("실행", "저장", "빼기").
- 오류 문구는 무엇이 잘못됐고 어떻게 고치는지 한 줄로.
- **앱·웹 같은 말** — 화면에 내부 상태값(`passed` 등)·영어 메뉴를 그대로 보이지 않는다. 테스트·코드가 읽는 값은 `data-status` 같은 속성에 둔다.

| 내부 값 · 영어 | 화면 글자 |
|---|---|
| `queued` · `leased` · `running` | 대기 · 시작 중 · 실행 중 |
| `passed` · `failed` · `error` | 통과 · 실패 · 오류 |
| `timeout` · `aborted` · `cancelled` · `skipped` · `flaky` | 시간 초과 · 중단 · 취소 · 건너뜀 · 불안정 |
| 탭 Run · Live · History | 실행 · 실시간 · 실행 이력 |
| Open · Report · Send · Screenshot · Runs · Secrets | 열기 · 리포트 · 보내기 · 스크린샷 · 실행 목록 · 비밀값 |
| 앱 전용 상태 `pending` · `unknown` · `done` | 대기 · 알 수 없음 · 완료 |
| script · session · Headless · Stop · Refresh · Shell | 스크립트 · 세션 · 창 없이 실행(옆에 작게 Headless) · 멈추기 · 새로고침 · 셸 |

## 적용 순서

1. **웹(euta cloud)** — `packages/web` 에 토큰·글꼴·아이콘·공통 컴포넌트를 넣고 기존 화면(인증·장치 승인·토큰·프로젝트 목록·프로젝트 안 화면 전부)을 교체.
2. **앱** — 토큰을 먼저 바꾸고(기존 `styles.css` 변수 이름을 이 표로 옮김) 사이드바 → 탭 하나씩 공통 컴포넌트로 교체. 설정 탭에 화면 테마 추가.
3. 각 단계는 기존 E2E 통과 + **바꾼 화면을 밝은·다크 두 모드로 캡처해 확인**.

## 완료 기준 (검증)

- 각 레포: 타입 검사 · 빌드 · 단위 테스트 · E2E 통과(선택자는 `data-testid`·역할 기준 유지).
- 바꾼 화면마다 밝은/다크 캡처에서 — 글자 대비가 읽히고, 색 값이 토큰 밖에서 쓰이지 않고(`#` 리터럴 검색 0건, 토큰 파일 제외), 아이콘 + 글자 버튼 규칙이 지켜진다.
- 테마 고정(밝게/어둡게)이 OS 설정보다 우선하고, 앱 재시작·웹 새로고침 후에도 유지된다.
