# ADR - 014 개인 테스트용 앱 패키징

## 상태

채택 (2026-10-02). 범위는 **개발자 본인 Mac 에서 더블클릭으로 실행** 까지다. 배포(공증·Developer ID 서명·설치 파일·자동 업데이트)는 범위 밖이다.

## 맥락

- 앱은 `pnpm start` 로만 켤 수 있었다(4단계에서 패키징 제외).
- `@euta/core` · `@euta/input-os` 는 형제 레포 `euta-engine` 을 가리키는 `link:` 의존성이고(ADR-001), 그 의존성(playwright·zod·unpdf 등)은 엔진 레포의 pnpm 저장소 안에 있다.
- 첫 시도에서 electron-builder 를 pnpm 레포(`euta-app`)를 projectDir 로 실행하자, 앱 레포의 의존성 트리를 수집해 **node-pty 만 담기고 엔진·Playwright 가 빠진** 앱이 나왔다(빌드는 성공 — 조용한 실패).
- 네이티브 모듈: node-pty 1.1.0 · robotjs 0.9.1 모두 N-API prebuild 포함(재빌드 불필요). `node:sqlite` 는 내장.
- Apple Silicon 은 서명이 깨진 번들 실행을 거부할 수 있다. 개인 테스트에는 Developer ID 가 없다.

## 결정

- `pnpm package`(`scripts/package.mjs`) 가 다음을 수행한다.
  1. 엔진 `pnpm -r build`, 앱 `electron-vite build`.
  2. `release/stage/` 에 앱 빌드 산출물(`out/`) 복사, 엔진 패키지를 `pnpm pack` 으로 tarball 화(`workspace:*` 가 버전으로 치환됨).
  3. 스테이징 `package.json` — 런타임 의존성만: `@euta/core` · `@euta/input-os`(tarball) · `node-pty` · `playwright`. `overrides` 로 input-os 의 `@euta/core` 를 같은 tarball 에 고정.
  4. `npm install --omit=dev` 로 평평한 실제 파일 `node_modules` 생성.
  5. electron-builder 26.15.3 을 **projectDir = 스테이징** 으로 실행(npm 수집기). 로컬에 받아 둔 Electron(`electronDist`) 사용, `npmRebuild: false`, target `dir`(`.app` 만).
  6. asar 사용 + `asarUnpack`: `*.node`, node-pty(spawn-helper), robotjs, playwright, playwright-core(자체 파일을 읽고 브라우저를 띄움).
  7. electron-builder 서명은 끄고(`identity: null`, `hardenedRuntime: false`) `codesign --force --deep --sign -` 로 **ad-hoc 서명** 후 `codesign --verify --deep --strict`.
- 산출물: `euta-app/release/dist/mac-arm64/euta.app` (gitignore).
- E2E 스모크를 `EUTA_E2E_EXECUTABLE=<.app 실행 파일>` 로 패키징된 앱에도 그대로 돌린다.

## 이유

- 스테이징 + tarball 은 pnpm `link:` · 심볼릭 링크 구조를 electron-builder 수집기와 분리하는 가장 단순한 방법이다. 결과 의존성 목록을 asar 헤더로 확인할 수 있다.
- 로컬 Electron 사용 → 네트워크 다운로드 없음. prebuild 사용 → 컴파일러 불필요.
- ad-hoc 서명은 이 Mac 에서만 유효하지만 개인 테스트 범위에 정확히 맞는다.

## 고려한 대안

- **electron-builder 를 앱 레포에서 그대로 실행** — 엔진 의존성이 빠진 앱이 조용히 만들어졌다(위 맥락). 제외.
- **엔진을 main 번들에 포함(vite 번들링)** — Playwright 는 번들링할 수 없어 어차피 외부 의존성이 남고, unpdf 등 동적 import 위험이 있다. 제외.
- **`pnpm deploy` / `node-linker=hoisted`** — 형제 레포 `link:` 의존성의 하위 의존성까지 평평하게 만드는 동작이 tarball 방식보다 불확실. 제외.
- **asar 끄기** — 동작은 단순하지만 필요 없음(unpack 으로 해결).
- **dmg 생성** — 개인 테스트엔 `.app` 이면 충분. 배포 단계에서 다룬다.

## 결과

- 검증(2026-10-02, macOS 26.5.1 arm64): asar 에 런타임 의존성만 포함(`@euta/core @euta/input-os fflate node-addon-api node-gyp-build node-pty pixelmatch playwright playwright-core pngjs robotjs unpdf yaml zod`), 패키징된 앱으로 E2E 스모크 통과(실행 → 라이브 → 이력 → MCP 이벤트 → hook → 터미널), `open` 으로 기동 확인. 용량 약 333MB.
- 2026-10-02 보강(ADR-015): AI 채팅용으로 `@euta/mcp-server` · Agent SDK(+ peer) · 플랫폼 CLI 패키지를 스테이징하고, CLI(`@anthropic-ai/claude-agent-sdk-darwin-arm64/claude`)는 asar 밖(unpack)에 실행 비트와 함께 둔다. 패키징 스크립트가 `.app` 안 CLI 의 sha256 이 npm 원본과 같은지 확인한다(ad-hoc 서명 후에도 Anthropic 서명 유지). 용량 약 580MB. 패키징된 앱으로 E2E(채팅 포함) 통과.
- 한계
  - Playwright 브라우저는 앱에 포함하지 않는다 — 사용자 캐시(`~/Library/Caches/ms-playwright`)를 쓴다. 없으면 `euta install-browsers` 필요.
  - AI 탭 연결 안내의 MCP 서버·플러그인 경로는 엔진 레포 위치를 기준으로 찾는다 — 패키징된 앱에서는 비어 보일 수 있다(플러그인 자체는 형제 경로로 엔진을 찾으므로 동작에는 영향 없음).
  - 다른 Mac 으로 옮기면 Gatekeeper 경고(ad-hoc). Windows 패키징은 코드만 있고 미검증.
