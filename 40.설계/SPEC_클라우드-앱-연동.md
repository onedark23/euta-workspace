# SPEC - 클라우드 앱 연동 (로컬 앱)

> 상태: **확정** (2026-10-20, C0). 제안값은 2026-10-20 사용자 확인으로 모두 채택. 구현 단계: C2(동기화 — **구현 완료 2026-10-21**, [ADR-025](ADR_025_앱-클라우드-동기화-구현.md)) · C3(실행 위임 — **구현 완료 2026-10-21**, [ADR-026](ADR_026_앱-클라우드-실행-위임-구현.md)).
> 동기화 규칙의 정본은 [ARCH_euta-cloud 동기화](ARCH_euta-cloud.md#동기화). 서버 쪽은 [SPEC_클라우드-계정-프로젝트](SPEC_클라우드-계정-프로젝트.md) · [SPEC_클라우드-실행-예약](SPEC_클라우드-실행-예약.md).

## 목적

- 로컬 앱(euta-app)이 euta cloud 에 연결해 **클라우드 공유 프로젝트**를 로컬 프로젝트처럼 쓴다 — 녹화·AI 정리·편집·로컬 실행은 지금처럼, 저장은 클라우드로.
- PC 를 끄고 싶은 실행은 **클라우드에 맡기고**(즉시·예약), 결과는 앱 History 에서 그대로 본다.
- 로컬 전용 프로젝트는 지금과 같다(동기화 없음).

## 클라우드 연결

| 항목 | 규칙 |
|---|---|
| 위치 | 앱 설정 > 클라우드 — 서버 주소(1개) · 연결 상태 · 로그인 계정 · 로그아웃 |
| 로그인 | **장치 인가**([ADR-023](ADR_023_클라우드-인증-구현.md)) — "로그인" → 앱이 코드 요청 → 시스템 브라우저로 승인 화면(코드 자동 입력) → 앱이 토큰 수신 |
| 토큰 보관 | `safeStorage` 암호문(vault 와 같은 방식). 렌더러로 보내지 않음 |
| 연결 상태 | 사이드바 하단 칩: 연결됨 · 오프라인(재시도 중) · 로그인 필요 |
| 로그아웃 | 토큰 삭제. 작업 사본은 남기되 열 때 로그인 요구. 보내기 대기분이 있으면 경고 |

## 프로젝트 종류

- 사이드바에 로컬 프로젝트와 **클라우드 프로젝트**(구름 표시)를 함께 보인다. 한 사이트 = 한 항목(올리기는 전환 — 아래 "로컬 프로젝트를 클라우드로 올리기").
- **[클라우드에서 받기]** (사이드바, 클라우드 연결 시): 내가 볼 수 있는 클라우드 프로젝트 목록 — "내 프로젝트"(소유·편집·실행 역할) / "조직 공개"(보기). 웹에서 만든 것·앱에서 올린 것 모두. 항목: 이름 · 만든 사람 · 출처(웹/앱) · 내 역할 · 최근 실행. 버튼 **[받기]** → 이 PC 에 작업 사본 생성 → 사이드바에 추가. 이미 받은 것은 **[열기]**(두 번 받지 않음). 보기 역할 항목에는 **[권한 요청]**(편집자/실행자 + 메모) — 요청 중이면 "요청 중" 표시.
- 다른 PC 의 같은 사람도 받기로 연다(합치기 대상은 그 프로젝트를 올린 로컬 프로젝트 하나뿐).
- 클라우드 프로젝트 안 탭은 로컬과 같다(스크립트 · Run · Live · History · AI · 작업 로그 · 설정) + **예약** 탭. 설정·구성원·예약 화면은 웹과 같은 항목. 설정에 클라우드 프로젝트 ID · 출처 · 만든 사람(참고용).
- **역할에 따른 화면**(서버 `can` 으로 판단): 보기 → 편집·실행 버튼 숨김 + 상단 "보기 전용"(+ [권한 요청]) · 실행자 → 실행 버튼만, 편집·클라우드 테스트 계정·설정 편집 숨김(이 PC 실행용 값 입력은 남김) + 상단 "실행 전용".
- **권한 변화 반영**: 서버 변경 피드로 역할 변경을 즉시 반영. 내보내졌거나 `members` 로 바뀌어 볼 수 없게 되면 그 작업 사본은 **"접근 권한 없음"** 으로 잠긴다 — 서버 내용은 더 받지 않고, 이 PC 실행 기록·리포트만 읽기([실행 이력]·[실시간] 탭만), 버튼 **[이 PC 에서 지우기]** · [다시 확인]. 다시 초대받으면 풀린다.
- 소유자에게는 권한 요청 알림(앱·웹) → 프로젝트 설정 > 구성원 에서 승인/거절.

### 작업 사본 저장 구조

```
<userData>/cloud/<서버 id>/projects/<projectId>/
  state.json          마지막으로 받은 변경 순번 · 스크립트별 기준 버전 · 내 역할
  snapshot.json       프로젝트·환경(주소·변수·테스트 계정 이름)·스위트·예약 (서버 사본, 읽기용)
  scripts/            스크립트 원문 사본 (기본 편집기로 열기·외부 변경 감지 대상)
  pending/            오프라인 중 보내기 대기 (순서 번호 · 경로 · 기준 버전 · 원문)
  runs/ + index.sqlite  로컬 실행 결과 (엔진 형식, 지금과 같음)
  cloud-runs/<runId>/   클라우드 실행 캐시 (요약 즉시, 파일은 열 때)
  cloud-uploads.json  이 PC 가 올린 로컬 실행 → 클라우드 실행 id (History 중복 표시·두 번 올리기 방지)
  chats/ · recordings/  AI 채팅 · 시연 녹화 원본 — 로컬에만
  baselines/<envId>/  로컬 실행용 시각 비교 기준 (이 PC 기준)
  designs/            프로젝트 디자인 사본 (서버 정본, 피드 design.changed 로 갱신 — C8)
  design-reviews/     AI 검수 결과 (로컬 보관 + 서버에 올림 — C8)
```

- 클라우드 실행 캐시 상한 2GB, 오래 안 본 것부터 지움(다시 열면 다시 받음).

## 동기화

### 열기·변경 받기

- 열 때: 마지막 순번 이후 변경을 받는다(처음이면 전체). 이후 프로젝트를 연 동안 SSE 로 실시간 수신 — 다른 사람의 저장(스크립트 사본 갱신, 편집 중이면 "다른 사람이 저장함" 배너) · 실행 시작/진행/종료 · 설정 변경.
- 보관 기간을 넘겨 "전체 다시 받기" 신호가 오면 snapshot·스크립트를 새로 받는다(보내기 대기분은 유지).

### 스크립트 저장

- 앱의 스크립트 쓰기 한 경로(`writeScript` — 편집기 저장 · AI `save_script` · 녹화 저장 · 되돌리기 · 만들기/가져오기 · 바깥 변경)를 클라우드 프로젝트에선 **서버 저장(기준 버전 포함)** 으로 보낸다. 출처: 편집기·녹화·가져오기 = 앱, AI = AI(채팅), 바깥 변경 = 앱 바깥 변경.
- 성공하면 새 버전이 기준 버전이 된다. 이력·비교·되돌리기 화면은 서버 이력을 보여 준다(로컬 `script-history` 대신).
- **충돌(409)** — 저장하지 않고 충돌 화면: 단계 문장 비교(내 것 ↔ 서버 최신) + 선택 ① 내 것으로 새 버전 ② 서버 것 받기 ③ 내 것을 사본 스크립트로(`<이름>-<내 이름>.yaml`). AI 저장이 충돌하면 AI 에게 "충돌 — 최신을 다시 읽으라" 결과를 돌려주고 사람에게도 배너.

### 오프라인

| 할 수 있음 | 할 수 없음(읽기만) |
|---|---|
| 스크립트 편집·저장(보내기 대기) · 녹화 · AI 채팅 · 로컬 실행 | 환경 · 테스트 계정 · 스위트 · 예약 · 구성원 · 클라우드 실행 요청 |

- 다시 연결되면 보내기 대기분을 순서대로 보낸다. 충돌이 나면 그 건에서 멈추고 충돌 화면을 띄운다(해결 후 이어서).
- 대기 중인 스크립트는 목록에 "보내기 대기" 표시.

## 실행

### 실행 위치 선택

- Run 탭·스크립트 목록·스위트에서 **실행 위치: 이 PC / 클라우드** 를 고른다(클라우드 프로젝트만). 기본값 이 PC.
- 클라우드 선택 시 사전 검사([SPEC_클라우드-실행-예약](SPEC_클라우드-실행-예약.md#사전-검사-서버-정본))를 미리 돌려 불가 사유를 버튼 옆에 표시. 보내기 대기 중인 스크립트는 클라우드 실행 불가("먼저 보내기").
- 클라우드 실행은 서버 실행 요청이 된다 — 진행은 SSE 로 Live 에 "클라우드" 표시로 보이고, 앱을 꺼도 계속된다.

### 이 PC 실행과 테스트 계정

- 서버는 테스트 계정 값을 돌려주지 않는다(PLAN 결정 "자격증명" — 값은 아무도 다시 못 봄). 그 결과 **클라우드 프로젝트를 이 PC 에서 실행할 때는 로컬 vault 의 값**을 쓴다(키 = 클라우드 projectId/envId/NAME, 내 PC 에만) — 구성원마다 이 PC 실행용 값을 따로 입력한다(이중 관리, 2026-10-20 사용자 확인).
- 환경 설정의 테스트 계정 영역에 이름마다 "클라우드: 등록됨 / 이 PC: 등록됨·없음" 을 보여 주고, 이 PC 값을 입력할 수 있게 한다. 같은 값을 클라우드에도 저장할지는 사용자가 따로 고른다(서버 저장은 편집자 이상).

### 로컬 실행 올리기

- History 의 로컬 실행에서 "클라우드에 올리기"(실행자 이상) → 결과 폴더 업로드 → 클라우드 실행 이력에 출처 "로컬 올림", 실행 위치 "PC — <이름>" 으로 추가.
- 실행한 원문 해시가 클라우드 버전과 같으면 그 버전에 연결, 다르면 "로컬 수정본" 표시.
- 자동으로 올리지 않는다(PLAN 결정 "실행 이력 공유").

### History · 결과 회수

- History 는 로컬 실행 + 클라우드 실행을 시간순으로 함께 보인다(출처·실행 위치 열).
- 클라우드 실행의 요약은 바로 보이고, 열면 파일을 내려받아 지금의 상세·리포트·재생 화면으로 본다.

### 예약 탭

- 웹과 같은 예약 목록·편집([SPEC_클라우드-실행-예약](SPEC_클라우드-실행-예약.md#예약)). 앱이 꺼져 있어도 클라우드가 돈다는 안내를 함께 보인다.

## 앱 알림

- 앱이 켜져 있는 동안 `GET /api/me/events`(SSE) — 내가 구성원인 프로젝트의 알림 대상 이벤트(예약 실행 실패류·회복, 내가 요청한 클라우드 실행의 종료)를 받아 OS 알림. 클릭 → 그 실행.
- 앱 설정 > 클라우드에서 알림 켜기/끄기.
- **앱이 꺼져 있던 동안의 알림도 받는다** — 마지막으로 읽은 위치를 저장해 다음 실행 때 그 뒤 알림을 받는다. 밀린 알림이 4건 이상이면 1건으로 접어 보여 준다(2026-10-21 사용자 승인, [ADR-026](ADR_026_앱-클라우드-실행-위임-구현.md)).

## 로컬 프로젝트를 클라우드로 올리기 — 전환 (한 프로젝트)

> 2026-10-23 변경: 올리기는 **복사가 아니라 전환**이다. 사이드바에는 그 프로젝트 하나만 남고, 그 프로젝트가 클라우드 프로젝트(구름 표시)가 된다. 로컬과 클라우드가 따로 노는 "이중 관리"를 없앤다.

| 항목 | 서버로 | 이 PC 작업 사본으로 옮김 |
|---|---|---|
| 설정 · 환경(이름·주소·변수·허용 도메인) | 올림 | — |
| 스크립트 | 현재 내용 올림(각 스크립트의 첫 서버 버전) | 원문 사본 |
| 스크립트 변경 이력 | — | 로컬 이력은 그대로 보관(읽기용) |
| 테스트 세트 | 올림(항상 실행·실패 시 중단 포함) | — |
| 테스트 계정 값 | **올리지 않음**(이름만 — 올린 뒤 클라우드에 입력 안내) | **이 PC 값 그대로**(이 PC 실행용, 이중 표시 유지) |
| 실행 기록 · 테스트 세트 실행·리포트 · 시각 비교 기준 · 디자인 | — (원하면 실행별 "클라우드에 올리기") | **그대로 옮김** — History·리포트가 끊기지 않음 |
| AI 대화 · 시연 녹화 · 작업 로그 | — | **그대로 옮김** |

- 절차: 확인 대화상자(옮기는 것·서버로 가는 것 요약) → 서버에 프로젝트 생성·스크립트 올림 → 이 PC 데이터를 작업 사본 폴더로 옮김 → 원래 로컬 프로젝트 항목 제거 → 같은 자리에서 클라우드 프로젝트로 열림. 중간에 실패하면 로컬 프로젝트는 그대로 두고(옮기기 전 상태) 오류를 보인다 — 서버에 만들어진 프로젝트는 "이어서 하기"로 재사용.
- 로컬 전용 프로젝트는 여전히 만들 수 있다(올리지 않으면 그대로).
- 범위 밖(후속): 클라우드 연결 끊기(클라우드 프로젝트 → 로컬 전용으로 되돌리기).

### 이미 갈라진 프로젝트 합치기

복사 방식(2026-10-21~23)으로 올려 **로컬 프로젝트와 클라우드 작업 사본이 따로 있는 경우**(로컬 `project.json.uploadedTo` 가 있는 프로젝트) — 로컬 프로젝트 화면 위쪽에 **[클라우드 프로젝트와 합치기]**. **대상은 그 연결 기록의 클라우드 프로젝트 하나로 정해져 있고 고를 수 없다.** 내가 그 프로젝트의 소유자이고 서버의 출생 기록과 맞을 때만 버튼이 보이며, 서버도 같은 조건을 검사한다([SPEC_클라우드-계정-프로젝트 합치기](SPEC_클라우드-계정-프로젝트.md#만들기공개구성원)). 다른 사람의 프로젝트나 웹에서 만든 프로젝트에 로컬 프로젝트를 붙이는 기능은 없다 — 그런 프로젝트는 받아서 쓴다.

- 스크립트 비교(경로 기준): 로컬에만 있음 → 서버로 올림 · 서버에만 있음 → 그대로 · 양쪽 같음 → 그대로 · **양쪽 다름 → 스크립트마다 고르기**(로컬 것 / 서버 것 / 둘 다 — 로컬 것을 `이름-로컬.yaml` 로), 단계 문장 비교 화면 재사용.
- 테스트 세트: 서버에 같은 이름이 없으면 올림, 있으면 고르기(로컬 / 서버).
- 환경: 서버에 같은 이름 환경이 있으면 그대로, 없으면 올림. 이 PC 테스트 계정 값은 같은 이름 환경으로 옮김.
- 이 PC 데이터(실행 기록·세트 실행·대화·녹화·작업 로그·기준 이미지)는 클라우드 작업 사본으로 옮기고, 작업 사본에 이미 있던 이 PC 실행과 합친다.
- 끝나면 로컬 프로젝트 항목은 사라지고 클라우드 프로젝트 하나만 남는다. 합치기 전 확인 대화상자에 위 요약(올릴 스크립트 수 · 고를 것 · 옮길 실행 수)을 보인다.

- 저장: 클라우드 프로젝트도 **작업 사본에 먼저 쓰고 보내기 대기열을 거쳐** 보낸다(온라인이면 즉시, 편집기·AI 는 서버 답을 기다림). 충돌(409)이면 서버에는 저장하지 않고, 해결할 때까지 작업 사본에는 내 내용이 남는다.
- 충돌 화면은 서버 409 외에 **편집 중 다른 사람 저장이 먼저 도착한 경우**에도 뜬다(그대로 보내면 남의 저장을 덮으므로). ③ 사본 이름의 "내 이름" 은 계정 이름(경로 문자 → `-`, 겹치면 `-2`).
- AI 저장 충돌: AI 가 `read_file` 한 버전 이후 서버가 바뀌었으면 저장하지 않고 "충돌 — 최신을 다시 읽으라" 도구 오류 + 배너. 서버에 "앱 AI 채팅" 출처가 없어 출처는 `ai_mcp`("AI").
- (2026-11-05, [ADR-046](ADR_046_TC-변환-자동-진행.md)) AI `save_script` 는 서버의 저장 검사와 같은 규칙으로 **먼저 검증**하고, 오류면 저장 · 대기열에 넣지 않고 AI 에게 돌려준다. **거절된 저장 버리기**: 같은 스크립트의 뒤 저장이 대기열에 있으면 그 거절 건만 빼고 뒤 저장을 보낸다(로컬 파일 유지, 버튼 "이 저장만 버리기 (뒤 저장 N개 보내기)"). 뒤 저장이 없으면 예전대로 서버 것 받기. 충돌 버리기는 그대로.
- 오프라인: 이름 변경·삭제·되돌리기·삭제 복원도 읽기만 쪽(온라인 전용)으로 둔다. 앱 밖에서 지운 파일은 서버로 보내지 않는다. 작업 사본 지우기는 보내기 대기분이 있으면 막는다.
- 테스트 계정: 이름 목록 = 클라우드 이름 ∪ 이 PC 이름. 클라우드 프로젝트의 이 PC 값은 vault 만(외부 secrets 파일 미지원). "실패 시 중단"·headless 는 서버에 필드가 없어 이 PC 설정.
- 올리기: 주소 없는 환경은 건너뛰고 알림, 검증 오류 스크립트는 "앱 바깥 변경" 출처로 보관(서버 표시 "검증 오류"), 이 PC 의 테스트 계정 값은 새 작업 사본의 이 PC 값으로 옮긴다(서버로는 안 감).
- 작업 로그 탭: 이 PC 기록 아래에 클라우드 작업 로그(구성원 전체, 최근 100건).
- 서버 공백(앱 쪽 우회): 일반 구성원용 사용자 검색 API 가 없어 이메일 초대는 관리자만 · 웹 장치 승인 화면(`/device`)이 C4 전이라 브라우저 승인 불가(E2E 는 API 로 승인).
