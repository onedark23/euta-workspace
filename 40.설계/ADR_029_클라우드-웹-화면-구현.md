# ADR - 029 클라우드 웹 화면 구현

## 상태

채택 (2026-10-21, C4 2부 구현). 실제 서버 + compose PostgreSQL + 실제 러너(엔진 CLI · Chromium) + 엔진 픽스처 사이트 대상 웹 E2E(Playwright)와 웹 단위 테스트로 검증했다. 결과는 아래 "결과" 절.

## 맥락

- C4 1부(ADR-019 결과 "C4 1부")에서 웹 패키지(React 19 + Vite 7, 서버 동봉, 직접 만든 작은 라우터 + `fetch`)와 인증·장치 승인·토큰·관리자 화면이 나왔다. 2부는 SPEC 의 프로젝트 목록 · 프로젝트 탭(현황·스크립트·실행 이력·예약·스위트·작업 로그·설정) · 스크립트 상세 · 실행 상세다.
- 스크립트 상세는 로컬 앱([SPEC_스크립트-보기-편집](SPEC_스크립트-보기-편집.md))과 같은 동작이어야 한다(AI 요청 버튼만 없음). 앱은 렌더러가 편집 모델을 만들고, **메인 프로세스**가 엔진 `rewriteScript`(주석 보존 직렬화)와 `validateScript` 로 검사한다(ADR-018).
- 확인한 사실(2026-10-21, 엔진 `@euta/core` 코드)
  - 브라우저에서 import 할 수 있는 하위 경로는 `./describe`(의존 없음)와 `./precheck` 뿐이다. `./precheck` 도 `load.ts` 를 거쳐 `playwright`(`devices`)·`node:fs` 를 끌어온다. `rewriteScript` 는 메인 진입점(`.`)에만 있고, 그 진입점은 러너·저장소 모듈까지 묶는다.
  - 서버의 실행 단계 색인(`RunStepDto`)에는 스크린샷 경로가 없다. 엔진 `run.json` 의 `steps[].screenshot`(실행 폴더 기준 상대 경로)과 `steps.jsonl` 의 `console.message`·`network.failed` 이벤트(엔진이 이미 secrets 를 가림)가 결과 파일에 있다.
  - 프로젝트 목록 응답(`GET /api/projects`)에는 실행 정보가 없다.

## 결정

### 1. 편집기 직렬화·검증은 서버 — `POST /api/projects/:id/scripts/check`

- 본문 `{ source }`(그 원문을 검사) 또는 `{ base, edit }`(엔진 `ScriptEdit` 를 base 원문에 `rewriteScript` 로 적용 — 주석·순서 보존) + 선택 `environmentId`. 저장하지 않는다.
- 응답 `{ source, contentHash, script(파싱 결과 또는 null), validation: { parsed, ok, issues }, secretNames, missingSecrets, ruleIssues, osInputIssues, unstable }`. `validation` 은 저장과 **같은 검사**(`checkScript` — `${secrets.*}`·`${env.*}` 는 자리값). `missingSecrets` 는 그 환경의 테스트 계정 이름과 비교(이름만), `ruleIssues` = secrets 사용 위치(`secretPlacementIssues`), `osInputIssues` = `input: os`(`osInputIssues`) — 둘 다 클라우드 실행 사전 검사에서 거절되는 것을 저장 전에 경고로. `unstable` = CSS 대상 수(`describeStep`).
- 권한 **보기 이상**(읽기 전용 계산). 웹이 YAML → 단계 문장을 그릴 때도 이 경로로 파싱하므로 보기 역할에도 필요하다. 크기 상한은 저장과 같은 256 KiB.
- 웹은 편집 중 200ms 묶음으로 부르고(앱 `draftCheck` 와 같음), **저장은 이 응답의 `source` 그대로** 보낸다(검사한 것 = 저장하는 것).

### 2. 앱 모듈은 복사 — 공용 패키지 추출은 제안으로

- euta-app 의 `src/shared/script-model.ts`(편집 모델) · `src/shared/script-diff.ts`(단계 문장 비교) · `src/renderer/src/tabs/StepForm.tsx`(동작별 폼·머리 정보 폼) · 메시지 한국어화(`friendly` · `koSecretRule`)를 `packages/web/src/script/` 로 **복사**했다(파일 머리에 원본 경로와 "keep in step"). 웹 쪽 차이: 버튼 `type="button"`, 폼으로 못 고치는 단계 안내 문구(“AI에게” 대신 “로컬 앱에서”).
- euta-app 은 고치지 않는다(작업 범위). 두 사본을 하나로 묶는 추출은 아래 "남은 일" 의 제안으로 둔다.

### 3. 라우터 — 직접 만든 라우터 유지 + 패턴·떠나기 확인

- `matchPath('/projects/:id/runs/:runId', path)` · 끝 `*` 는 나머지 경로(스크립트 경로, 조각마다 디코드 · `/` 유지). 화면 표가 평평하고 작아 react-router 를 들이지 않았다(ADR-019 결과 C4 1부의 "중첩 경로가 필요해지면" 조건 — 패턴 하나로 충분).
- **저장하지 않은 변경 확인**: `setLeaveGuard()` 가 앱 안 이동(`navigate`) 전에 묻고, 탭 닫기는 `beforeunload`. 브라우저 뒤로 가기(popstate)는 묻지 않는다(1차).
- 실행 상세 경로 `/projects/:id/runs/:runId` — Teams 카드·앱 알림의 링크가 이 경로로 열린다.

### 4. 실시간 — 프로젝트 화면당 EventSource 1개

- 프로젝트 화면(탭 전환에도 유지)이 `GET /api/projects/:id/events` 를 1개 열고, 화면들이 구독한다(ADR-022). 프로젝트·환경·테스트 계정·구성원 이벤트와 `resync` 는 프로젝트 정보를 다시 읽는다.
- 실행 상세: 그 실행(또는 스위트 자식)의 `run.*` 이벤트 → 0.3초 묶어 다시 읽음. 실행이 끝나지 않은 동안 **5초 폴링**을 대체 경로로 둔다(ADR-022 "SSE 장애 시 대체 경로"). 경과 시간은 `startedAt` 부터 브라우저가 1초마다 센다. 현재 단계 = 서버 `currentStep` + 고정 버전 스크립트의 단계 문장.
- 스크립트 상세: 이 스크립트의 `script.saved/reverted/restored` 가 다른 사람에게서 오면 — 보기 중이면 최신으로 바꾸고 안내, **편집 중(바뀐 것 있음)이면 배너** "다른 사람이 저장함 — 저장하면 충돌 화면". `script.renamed` 는 새 경로로 옮김.

### 5. 결과 표시 — 결과 파일에서 읽음

- 단계 스크린샷은 `files/run.json` 의 `steps[].screenshot`, 콘솔 오류·경고와 실패 요청은 `files/steps.jsonl`. 결과 파일이 `expired` 면 둘 다 건너뛰고 **"파일 만료"** 안내(요약·단계·지표는 DB 에 남음).
- report.html 은 `GET …/runs/:runId/report`(서버가 `files/report.html` 로 302, 리포트의 상대 링크가 동작). 파일 목록은 내려받기 링크.

### 6. 스크립트 상세의 세부

- **최근 실행 겹치기**: `GET …/runs?target=<스크립트 id>&limit=1`(최상위 스크립트 실행 — 스위트 자식은 제외) → 실행의 `script.contentHash` 가 지금 버전 해시와 같을 때만 겹치고, 다르면 흐리게 + "수정 이후 아직 실행하지 않음"(앱과 같은 규칙, 스크립트 id 로 찾으므로 이름 변경 뒤에도 이어짐).
- **기준 버전 = 편집을 시작한 버전**. 저장 409(`SCRIPT_CONFLICT`)면 응답의 `details.current`(서버 최신 원문)와 내 것을 단계 문장으로 비교하는 충돌 화면 + 3선택(앱 SPEC 충돌과 같음): ① 내 것으로 새 버전(서버 최신 버전을 기준으로 다시 저장) ② 서버 것 받기(내 변경 버림) ③ 내 것을 사본 `<이름>-<내 이름>.yaml`(경로 문자 → `-`, 겹치면 `-2`)으로.
- **이력**: 버전 목록(버전 · 출처 · 작성자 · 시각 · 메모 · 검증 오류 표시) → 고른 버전과 바로 앞 버전의 단계 문장 비교 → "이 버전으로 되돌리기"(`POST …/revert`, 기준 버전 포함). 앱처럼 목록의 **버전마다 요약**("단계 2개 추가")은 보이지 않는다 — 버전마다 원문 2개를 받아 파싱해야 해서, 고른 버전의 비교에만 요약을 보인다.
- 새 스크립트: 스크립트 탭에서 경로 → 폼 편집기(템플릿 `goto: /`, `baseUrl: ${env.BASE_URL}`) → 저장(기준 버전 없음).

### 7. 실행 요청·다시 실행

- 실행 버튼 옆 폼: 환경 · 변수 덮어쓰기(`이름=값` 줄) · 시간 제한(분, 비우면 프로젝트 기본). 값이 바뀔 때마다 `POST …/runs/precheck`(0.25초 묶음)로 **사전 검사 사유를 실행 전에** 보이고, 통과해야 실행 버튼이 켜진다. 하루 실행 상한(422 `DAILY_RUN_CAP_REACHED`)은 사용/상한으로 안내.
- **같은 설정으로 다시 실행** = 같은 대상(스크립트 id / 스위트 id) · 환경 · 변수 · 시간 제한으로 새 요청. 스크립트 버전은 서버 규칙대로 **요청 시점의 현재 버전**(고정 버전 재실행이 아님). 로컬 실행 올리기 기록은 다시 실행 대상이 아님.

### 8. 권한 표시

- 서버가 프로젝트 응답에 주는 `can`(공용 `allowedActions`)으로 버튼을 숨긴다 — 보기 역할(또는 읽기 토큰 세션)은 편집·실행·예약·설정 변경 컨트롤이 없고 머리에 **"보기 전용"**. 사전 검사 API 도 실행 권한이 있을 때만 부른다.
- Teams webhook 은 프로젝트 응답에 `teamsWebhookUrl` 이 **있을 때만** 입력칸을 보인다(서버가 `project.update` 가능자에게만 싣는다). 그 밖에는 "Teams 알림: 설정됨/설정 안 됨".

### 9. 서버 보탬

- 위 1의 확인 경로, 그리고 프로젝트 목록 항목에 `lastRun`(최상위 실행 중 최신 1건 — id · 상태 · 불안정 · 요청/종료 시각, 한 번의 `distinct on` 질의). 목록의 "최근 실행 상태" 용 — 프로젝트마다 실행 목록을 부르는 N+1 을 피함.

### 10. 웹 E2E 하네스

- `e2e/server.mjs` 가 서버(새 DB, 관리자 승인 모드)에 더해 **엔진 픽스처 사이트**(`tsx …/fixture-site/start.ts`, 포트 = 기본 포트 + 2)와 **실제 러너 프로세스**(`packages/runner/dist/main.js` → 엔진 CLI → Chromium, 실행 위치 `e2e-lab`)를 띄운다. 서버에는 개발 전용 `ALLOW_PRIVATE_TARGETS=true` · 러너 토큰 · 하트비트 1초. 멈출 때 러너 → 서버 → 픽스처 순(각각 SIGTERM, 시간 넘으면 SIGKILL), DB 삭제.
- 계정은 HTTP 가입 + 관리자 API 승인으로 준비(화면 가입 흐름은 1부 스펙이 검증).

## 고려한 대안

| 대안 | 제외 이유 |
|---|---|
| 웹에 `yaml` 을 넣어 브라우저에서 파싱 | 검증·주석 보존 직렬화는 어차피 서버(엔진)가 해야 함 — 파서만 브라우저로 옮기면 번들 +30KB(gzip) 에 규칙이 두 군데가 됨 |
| 엔진에 브라우저용 하위 경로(`./rewrite`·검증) 추가 | 검증이 `playwright` `devices` 에 묶여 있어 엔진 구조 변경이 큼 — 엔진 레포 작업이라 범위 밖. 추출 제안으로 남김 |
| 앱 모듈을 지금 공용 패키지로 추출 | euta-app 수정 금지(작업 범위). 복사 + "keep in step" 표시 후 제안 |
| react-router | 평평한 화면 표에 패턴 함수 하나로 충분 — 의존·번들 증가 대비 이득 없음 |
| 실행 상세를 폴링만으로 | 진행 표시가 늦음. SSE 가 정본이고 폴링은 대체 경로 |
| 스크린샷 경로를 서버 단계 색인에 추가 | 정본은 업로드된 `run.json`(ADR-022 결과 — "원본 이벤트는 DB 에 두지 않는다"). 웹이 결과 파일을 읽으면 서버 변경이 없음 |
