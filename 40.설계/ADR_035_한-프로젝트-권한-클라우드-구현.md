# ADR - 035 한 프로젝트 + 권한 클라우드 구현

## 상태

채택 (2026-10-23). 단계 15 의 **클라우드 쪽(서버·웹)** 구현. 앱 쪽은 별도. 브랜치 `feat/one-project-perms`(euta-cloud) — 커밋 b2704b7 · f9d29b1 · fdfe7a8 · 1b4f448. 앱이 쓰는 API 계약은 작업 폴더의 `API_CONTRACT.md`(이 ADR 의 "API" 절과 같은 내용).

## 결정

### 데이터 (마이그레이션 `0004_project_birth_access`)

- `projects` 에 `visibility`(`org` 기본 · `members`) · `origin`(`web` · `app` · `unknown`, 열 기본값 `unknown`) · `origin_local_id` 추가. **기존 프로젝트는 그대로 `unknown` + `org`**, 기존 구성원 행(owner/editor)은 역할 그대로 — 데이터 변환 단계 없음(마이그레이션 테스트로 확인).
- 출생 기록의 "만든 사람·시각" 은 기존 `created_by` · `created_at` 을 쓴다. 바꿀 수 없음은 코드로 지킨다(PATCH 스키마에 필드 없음). 유일한 예외는 `unknown` 프로젝트 합치기 때 1회 `app` 으로 채우기.
- `access_requests` 표: 열린 요청은 `(project_id, user_id) WHERE status='open'` 부분 고유 색인으로 사람당 프로젝트당 1건. `expires_at = created_at + 30일`. 만료는 **읽을 때 게으르게**(`expireAccessRequests` — 요청·목록·승인 전에 해당 범위를 `expired` 로) + 정리 작업(`purgeExpired`)이 나머지를 쓸어 낸다. 대안(예약 작업 전용 타이머)은 정확도 이득이 없어 버림.
- `project_members.role` 은 네 역할 모두 저장한다 — **구성원만 공개 프로젝트에 "보기"로 초대**할 수 있어야 하므로(이전엔 owner/editor 만).

### 권한 판정

- `shared/permissions.ts` 역할 표에 `runner` 와 동작 `project.visibility` · `project.transfer` · `project.merge` · `access.request` · `member.leave` 추가. `run.execute` · `run.upload` 는 실행자 포함.
- 공개 범위는 `projectAccessFor` 한 곳에서 판정: `members` 인데 구성원 행이 없으면 **어떤 동작이든 404** (REST·SSE·MCP 공통). 목록(`GET /api/projects`, MCP `list_projects`, 받기 목록)은 같은 `visibleTo` 조건.
- 응답의 `can` 은 표에 문맥을 더한 `canFor` — 구성원 행이 없으면 `member.leave` 빼고, `access.request` 는 보기·실행자만(요청 가능한 역할이 편집자·실행자뿐이라 편집자는 요청할 것이 없음). 서버도 요청 역할이 지금 역할보다 높지 않으면 409 `ALREADY_HAS_ROLE`.
- "소유자 최소 1명" 은 **활성 소유자** 기준(`services/members.ts`): 비활성 소유자만 남게 하는 낮추기·내보내기·나가기도 409 `LAST_OWNER`. 초대·역할 변경·승인·이전·관리자 지정이 같은 함수를 쓴다.
- 관리자 소유자 지정은 `/api/admin/projects/ownerless` · `POST /api/admin/projects/:id/owner` 로 분리 — 관리자에게 `projectAccess` 특권을 주지 않는다(구성원만 프로젝트 내용은 관리자도 404). 대상은 활성 조직 사용자 누구나(SPEC 용어 "구성원" = 조직 구성원), 화면은 기존 구성원을 먼저 보인다. 작업 로그 행위자 라벨 `관리자 (이름)`.

### 합치기 문 지키기

- 서버는 **검사 + 기록만** 한다(`POST …/merge/check`, `POST …/merge`). 스크립트·세트·환경 비교와 올리기는 앱이 기존 API 로 한다 — 합치기 전용 일괄 API 는 만들지 않음(같은 검증·충돌·작업 로그 경로를 재사용).
- 거절: 웹 출생 403 `ORIGIN_MISMATCH(web_origin)` · 로컬 id 불일치 `ORIGIN_MISMATCH(local_id_mismatch)` · `unknown` 의 연결 기록 불일치 `ORIGIN_MISMATCH(link_mismatch)` · 소유자 아님 403 `FORBIDDEN(not_owner)`.
- `unknown` 의 "로컬 연결 기록 일치" = 앱이 보낸 `uploadedTo.projectId` 가 대상 id 이고 `uploadedTo.localId` 가 대상 id 에서 `-` 를 뺀 값(옛 복사 방식이 만든 작업 사본 id). 이 값은 계산할 수 있으므로 실제 문은 "소유자" 검사이고, 연결 기록은 엉뚱한 프로젝트로 붙는 실수를 막는 용도다.

### 올리기 = 전환 (서버 쪽)

- `POST /api/projects` 에 `origin`(`web` 기본 · `app`) + `originLocalId`(app 필수). **같은 사람 · 같은 로컬 id · 휴지통 아님** 이면 새로 만들지 않고 200 + `resumed: true` — "이어서 하기" 를 서버가 멱등으로 받는다. 대안(앱이 만든 id 를 따로 기억)은 앱이 중간에 죽으면 잃으므로 버림.

### 알림·실시간

- `GET /api/me/events` 에 `access.requested`(소유자들) · `access.approved` / `access.rejected`(요청자) — `data` 모양이 실행 알림과 달라 공유 타입은 `AccessUserEventDto` 로 따로 둠(기존 `UserEventDto` 는 그대로).
- 프로젝트 SSE 는 구성원·공개 범위·이전·삭제 종류 이벤트를 보낸 뒤 호출자의 접근을 다시 검사하고, 못 보게 됐으면 `event: access_lost` 후 스트림을 닫는다. 웹은 이를 받으면 다시 읽어 "찾을 수 없음" 으로, 앱은 "접근 권한 없음" 잠금으로.

### 작업 로그 종류

SPEC 목록 그대로 + **`project.transferred`**(소유권 이전 한 건 = 한 항목, SPEC 목록에 없어 추가). 기존 `member.added` 는 `member.invited` 로 이름을 바꿨다(새 항목부터).

### 웹 화면

- 설정 > 공개 범위(조직 공개 / 구성원만 토글 버튼 + 출처·만든 사람) · 권한 요청(소유자: 요청자 이름·메모·만료일, 줄 역할 고르기 + [승인] [거절]) · 구성원(역할 고르기, [소유권 이전] 대화상자 — 이전 뒤 내 역할/나가기, [내보내기], 내 행 [나가기] — 마지막 활성 소유자는 숨김) — `project/members.tsx` 새 파일.
- 초대 = 이름 검색 + 체크: 체크한 사람은 체크한 순서대로 목록 위에 번호와 함께 모이고, 검색어를 바꿔도 남는다. [N명 <역할>(으)로 초대] 가 그 순서대로 초대.
- 머리: 역할 배지 · "보기 전용"/"실행 전용" · "구성원만" · [권한 요청](대화상자: 역할 + 메모) 또는 "<역할> 권한 요청 중".
- 관리자 화면 아래 "소유자 없는 프로젝트"(`pages/admin-ownerless.tsx`).
- **고친 버그**: 스크립트 화면 [실행…] 이 `script.edit` 로 숨겨져 실행자가 실행할 수 없었다 → `run.execute` 로 분리.

## 검증

- 서버·shared 316 테스트(30 파일) 통과 — 역할 4 × 동작 17 HTTP 행렬(세션·read·read_write 토큰·초대된 보기 12 주체), `one-project.test.ts` 16(공개 범위 404·목록·받기 목록, SSE access_lost 2종, 요청 수명·만료·1건 제한·다른 역할 승인·알림, 나가기·이전, 합치기 통과 + 거절 3종 + unknown 1회, 관리자 지정·관리자 내용 404, 활성 소유자 기준), `migration-0004.test.ts`.
- 웹 E2E 19 통과(새 `members-perms.spec.ts` 5 — 요청 → 승인 → 실행 전용 실행 통과·편집 없음, 검색 + 체크 초대, 구성원만 전환 시 열려 있던 비구성원 화면이 찾을 수 없음, 관리자 소유자 지정). 화면 캡처 `e2e-results/perm-1~7` 눈으로 확인.
- 타입체크·빌드(server · web · shared · runner) 통과.

## 남은 것 · 주의

- 마이그레이션 번호 0004 — main 에 다른 0004 가 먼저 들어가면 다시 생성해야 한다(`drizzle-kit generate`).
- 앱 쪽(받기 목록·잠금·합치기 화면)은 앱 작업에서. 웹에는 내 요청 목록 화면(`GET /api/me/access-requests`)을 따로 두지 않았다(프로젝트 머리에 "요청 중" 표시).
