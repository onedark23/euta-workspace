# ADR - 010 데스크톱 앱 구성 · 빌드 · 엔진 내장

## 상태

채택 (2026-09-29, 4단계 구현). 레포 `euta-app/`. macOS(arm64)에서 검증, Windows 는 코드상 고려만.

## 맥락

- 앱은 엔진(`@euta/core`)을 **같은 프로세스 계열에 내장**해 실행하고 이벤트를 직접 구독한다(ARCH). 엔진은 ESM · `tsc` 산출물(`dist`)만 내보낸다(ADR-001).
- 엔진 색인은 `node:sqlite`(ADR-003) — "4단계에서 Electron 메인 프로세스 스모크로 재확인" 이 남아 있었다.
- Playwright 가 엔진 안에서 브라우저를 띄우므로, Electron 메인 프로세스에서 Playwright 가 도는지가 이 단계의 최대 위험이었다.
- 확인한 사실(2026-09-29): Electron 최신 안정판 44.4.5(Node 24.21.0). electron-vite 5.0.0 은 vite `^5 || ^6 || ^7` 피어(8 미지원). node-pty 1.1.0 은 N-API prebuild(darwin/win32 × x64/arm64) 포함. Electron 44 는 `npm install` 때가 아니라 첫 실행 때 바이너리를 내려받는다(`index.js` 의 lazy download).

## 결정

### 1. 스택

| 영역 | 선택 |
|---|---|
| 런타임 | **Electron `^44.10.0`** (범위 — 정확한 버전은 lockfile. 2026-10-28 Node 보안 패치로 44.4.5 고정에서 바꿈, [ADR-040](ADR_040_Playwright-1.64.1-Node-보안-패치.md)) |
| 빌드 | **electron-vite 5** + vite 7 — main · preload · renderer 3개 빌드를 한 설정으로 |
| UI | **React 19** + 평범한 CSS(프레임워크 없음) |
| 터미널 | xterm.js 6 + node-pty 1.1.0 (ADR-011) |
| 테스트 | vitest 4(main 로직 단위) · **@playwright/test `^1.64.1` `_electron`**(E2E, 엔진과 같은 Playwright 줄 — 2026-10-27 1.63.0 고정에서 올리고 2026-10-28 범위로, [ADR-040](ADR_040_Playwright-1.64.1-Node-보안-패치.md)) |
| 언어 | TypeScript 5.9 strict (엔진과 같은 메이저) |

### 2. 프로세스 구성

- **main (ESM)** — `package.json "type": "module"`. `@euta/core` · `node-pty` · `playwright` 는 번들하지 않고 external(electron-vite 5 기본). core 는 `link:../euta-engine/packages/core` 로 `dist` 를 그대로 불러온다(ADR-001).
  - 모듈: `settings` · `local-server` · `live-reducer`/`live-store` · `hook-store` · `runner`(validateScript · runScript · secrets 파일) · `history`(RunIndex) · `artifacts`(실행 폴더 안 이미지만) · `terminal-env`/`pty-manager` · `index`(IPC 배선·창).
- **preload (CommonJS 한 파일)** — 샌드박스 preload 는 ESM 을 못 쓰므로 `output.format: 'cjs'`, `externalizeDeps: false` 로 `index.cjs` 하나를 만든다. `contextBridge` 로 `window.euta` 좁은 API 만 노출(Node·Electron 객체는 건너가지 않음).
- **renderer** — `sandbox: true` · `contextIsolation: true` · `nodeIntegration: false` · `webSecurity: true`. CSP(meta): `default-src 'none'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; connect-src 'self' ws://localhost:*` 외. `style-src 'unsafe-inline'` 은 xterm 이 런타임에 `<style>` 을 만들기 때문. `ws://localhost` 는 `pnpm dev` HMR 용.
- **IPC** — `ipcMain.handle` + 채널 상수(`src/shared/ipc.ts`). 모든 핸들러가 보낸 쪽이 메인 창의 `file://`(또는 dev URL) 프레임인지 확인한다. 인자는 main 에서 다시 검증한다(경로 존재, 브라우저 enum, 숫자 clamp).
- **창 보호** — 모든 webContents 에서 `window.open` 거부, 다른 URL 로의 navigate 차단, `<webview>` 차단, 권한 요청 전부 거부. 리포트는 preload 없는 샌드박스 창으로 연다(또는 `shell.openPath` 로 시스템 브라우저).

### 3. 엔진 사용

- 실행: `runScript({ path }, { env: {...process.env, ...덮어쓰기}, vars, secrets, runsDir, baselineDir?, headless, browserEngine })`. core 가 `env ?? process.env` 이므로 덮어쓰기만 넘기면 `${env.*}` 가 사라진다 — 반드시 병합해서 넘긴다.
- 라이브: `handle.events.onAny(fn, { replay: true })` → live store(ADR-012) → 100ms 스로틀로 렌더러에 `RunView` 푸시.
- 이력: `RunIndex.with(runsDir, …)` 로 열고 바로 닫는다(ADR-003 원칙 그대로, CLI · MCP 서버와 파일 공유).
- runs 폴더 기본값: `<userData>/runs`(Settings 에서 변경). 설정은 `<userData>/settings.json`.
- secrets: Settings 의 파일을 main 에서만 `loadSecretsFile` 로 읽는다. 렌더러에는 **키 이름**만 보낸다. 파싱 오류 메시지는 파일 내용을 인용할 수 있으므로 일반 문구로 바꿔 보낸다. 마스킹은 core(ADR-006)에 맡긴다.

### 4. 설치 보정 (`postinstall`)

- Electron 바이너리를 미리 내려받는다(44 의 lazy download 로 첫 `pnpm start`/E2E 가 멈추는 것을 막음).
- node-pty `prebuilds/*/spawn-helper` 의 실행 비트를 복구한다 — pnpm 설치에서 빠져 `posix_spawnp failed` 가 나는 알려진 문제.
- `pnpm.onlyBuiltDependencies: [electron, esbuild, node-pty]`.

### 5. 검증 방식

- **게이트 스모크**(착수 직후): Electron 44 main 에서 `RunIndex.with(...).listRuns()` 와 `runScript(widgets.yaml)` 실행 → `electron 44.4.5 node 24.21.0 / GATE sqlite ok / GATE run passed {"total":20,"passed":19,"skipped":1}` / 색인에 1건. **node:sqlite · Playwright 모두 Electron main 에서 그대로 동작**(better-sqlite3 opener 불필요).
- **E2E**(`pnpm test:e2e`): 빌드된 앱을 `_electron.launch` → UI 로 예제 실행 → Live passed → History → 합성 `/events` · `/hooks/claude` → 터미널 셸 출력. 테스트용 접근은 `EUTA_E2E=1` 일 때만 main `globalThis.__eutaTest`(Playwright `electronApp.evaluate` 로만 접근, 렌더러 비노출). `EUTA_USER_DATA_DIR` 로 프로필을 임시 폴더로 돌린다.

## 이유

- electron-vite 는 main/preload/renderer 세 타깃의 형식(ESM main · CJS preload · 브라우저 번들)을 한 설정에서 다루고, 의존성 external 이 기본이라 엔진 `dist` 와 네이티브 모듈을 건드리지 않는다.
- 엔진을 번들하지 않으면 core 의 `createRequire(import.meta.url)`(node:sqlite 지연 로딩)와 Playwright 의 런타임 경로 탐색이 원래대로 동작한다(ADR-001 "playwright 는 external").
- React 는 스텝 타임라인·세션별 활동처럼 자주 바뀌는 목록을 다루기 쉽고, UI 규모가 작아 상태 관리 라이브러리가 필요 없다.
- 네이티브 모듈이 N-API(node-pty)뿐이고 SQLite 는 내장이라 `@electron/rebuild` 가 필요 없다 — Electron 업그레이드 비용이 낮다.

## 고려한 대안

| 대안 | 제외 이유 |
|---|---|
| Electron Forge + webpack/vite 플러그인 | 패키징까지 한 번에 되지만 1차 범위(패키징 제외)에 비해 설정이 크다. 패키징 ADR 에서 재검토 |
| tsc 만으로 main/preload + vite 로 renderer | preload CJS 번들·dev 서버 연동을 직접 짜야 함 |
| vite 8 | electron-vite 5 피어 범위 밖(6.0 은 beta) |
| Svelte/Vue/바닐라 TS | 어느 쪽도 가능. 팀 친숙도·생태계로 React |
| 렌더러에서 core 직접 사용(nodeIntegration) | 보안 기본선 위반. Playwright 는 어차피 Node 필요 |
| Playwright 를 별도 utility process/자식 Node 로 분리 | main 에서 문제없이 도는 것을 확인했고, 이벤트 버스를 직접 구독하는 ARCH 구조가 단순. 실행이 UI 를 막는 징후가 보이면 `utilityProcess` 로 옮긴다 |
| 스크린샷을 커스텀 프로토콜로 제공 | IPC + data URL 이 경로 검증 지점을 하나로 모으고 테스트가 쉽다. 큰 영상·trace 를 보여 줄 때 재검토 |

## 결과

- 명령: `pnpm build` · `pnpm start`(빌드 산출물 실행) · `pnpm dev` · `pnpm typecheck` · `pnpm test` · `pnpm test:e2e` · `pnpm verify`.
- 종료: `will-quit` 에서 동기 정리(pty kill · 타이머 · 서버 소켓). `before-quit` 에서 `preventDefault` 후 비동기로 다시 `app.quit()` 하면 macOS 에서 멈추는 것을 확인해 쓰지 않는다. SIGINT/SIGTERM 도 `app.quit()` 로 같은 경로를 탄다.
- 남은 일
  - **패키징**(dmg/exe · 서명 · 공증): `playwright`·`node-pty` 를 asar unpack, 엔진을 tarball 로 포함할지(ADR-001 보류 사항), Playwright 브라우저 설치 위치 안내.
  - Windows 실기 검증(ConPTY · PowerShell · `.cmd` shim · 경로).
  - 실행 취소 — core 에 중단 API 가 생기면 Run/Live 에 버튼 추가.
  - 렌더러 번들 1.1 MB(React + xterm) — 코드 분할은 필요해지면.
