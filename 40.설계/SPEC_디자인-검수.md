# SPEC - 디자인 검수 (Figma 대조)

> 상태: **초안** (2026-10-23, 구현 전). 결정 정본은 [PLAN 결정 사항](../20.프로젝트관리/PLAN_end-user-테스트툴-종합계획.md#결정-사항) "디자인 검수". 단계: 로컬 = 단계 11, 클라우드 = [PLAN_euta-cloud C8](../20.프로젝트관리/PLAN_euta-cloud.md#단계-계획).
> 선행: [SPEC_test-script-dsl](SPEC_test-script-dsl.md)(형식) · [SPEC_프로젝트-관리](SPEC_프로젝트-관리.md)(프로젝트 저장소) · [SPEC_스크립트-보기-편집](SPEC_스크립트-보기-편집.md)(편집기) · [ADR-015](ADR_015_앱-AI-채팅-Agent-SDK.md)(본인 구독 AI) · [SPEC_클라우드-앱-연동](SPEC_클라우드-앱-연동.md) · [SPEC_클라우드-실행-예약](SPEC_클라우드-실행-예약.md).

## 목적

- 출시 전에 **"디자인대로 구현됐나"** 를 테스트 실행 중에 함께 본다. 첫 대상은 실사용 대상 서비스.
- 판정은 **경고 + 검수 리포트** — 디자인 차이로 단계·실행이 실패하지 않는다. 사람이 대조하기 쉬운 비교 화면과 AI 가 뽑은 차이 목록이 산출물이다.
- 제공하는 것(사용자 결정)
  - Figma 프레임을 **앱에서 가져와 프로젝트에 저장**한다. 실행할 때는 저장된 이미지만 쓴다.
  - 스크립트의 **디자인 비교 단계**로 화면과 프레임을 짝짓는다.
  - **AI 검수는 결과 화면의 버튼**으로 돌린다(로컬 앱, 본인 구독).
  - 클라우드 실행에서도 비교한다. 클라우드 실행을 앱으로 받아 와 AI 검수를 하면, 결과를 **로컬에 저장하고 그 클라우드 실행에도 올린다**.
- 범위 밖: 실행 때 Figma 호출 · 실패 판정 · Figma 노드 속성 ↔ DOM 스타일 비교 · 실행이 끝나면 AI 를 자동으로 돌리는 것 · 검수 리포트 파일 내보내기(후속) · 웹에서 AI 검수(클라우드는 AI 를 품지 않음).

## 흐름

```
[앱] Figma 연결(개인 토큰) ─▶ 디자인 탭 "Figma 에서 가져오기"(프레임 링크) ─▶ designs/<이름>.png + .json
                                                                         │ (클라우드 프로젝트면 서버로 올림 → 구성원·러너가 받음)
[앱] 편집기 "디자인 비교" 단계 추가 ─▶ 스크립트에 - design: { name: <이름> }
[엔진] 실행 중 그 단계에서 화면을 찍어 디자인과 맞춰 봄 ─▶ 실행 폴더 designs/<이름>/ (실제 · 디자인 · 차이) + design.compared
[앱·웹] 실행 상세 "디자인 검수" ─▶ 나란히 · 슬라이더 · 겹치기 · 차이
[앱] "AI 검수" 버튼 ─▶ 차이 목록 + 사람 판정 ─▶ design-reviews/<실행 id>.json (+ 클라우드 실행이면 서버에 올림 → 웹에서 보임)
```

## 설계 선택 — `visual` 을 넓히지 않고 단계를 따로 둔다

기존 `visual`([ADR-005](ADR_005_시각-비교-픽셀-diff.md))은 회귀 검사라 Figma 기준과 뜻이 셋 다르다. 그래서 `design` 단계를 따로 둔다.

| | `visual` (회귀) | `design` (디자인 대조) |
|---|---|---|
| 기준이 없을 때 | 지금 화면으로 만들고 통과 | 만들지 않음 — 경고 "디자인 없음" |
| 기준의 단위 | 환경 · 실행 위치마다(`baselines/<envId>/…`) | 프로젝트에 하나(환경과 무관한 디자인 원본) |
| 판정 | 임계치를 넘으면 단계 실패 | 실패 없음, 차이 비율은 참고 수치 |

## 디자인 참조

### 저장 형식

```
<프로젝트>/designs/
  <이름>.png     Figma 가 렌더한 프레임 (scale 2)
  <이름>.json    { name, figma: { fileKey, nodeId, url, frameName, version, lastModified, nodeHash },
                   width, height,        ← 프레임 크기 (Figma 단위 = CSS px)
                   scale, fetchedAt, fetchedBy }
```

- `scale` 은 요청값(참고)이다. Figma 는 32메가픽셀을 넘는 렌더를 줄여서 주므로, 엔진은 실제 배율을 `PNG 픽셀 ÷ width` 로 구한다.

- `<이름>` = 글자(한글 포함)·숫자·`-`·`_`, 64자 이하. `/ \ . :` 와 공백은 쓰지 않는다. 기본값은 프레임 이름에서 공백을 `-` 로, 그 밖의 금지 문자를 지운 값이다. 비면 `frame-<nodeId>`(`:` → `-`), 겹치면 뒤에 `-2` 를 붙인다. 프로젝트 안에서 겹치지 않는다. 이름 바꾸기는 없다 — 스크립트가 이름으로 가리키므로 지우고 다시 가져온다.
- 로컬 프로젝트: `<userData>/projects/<id>/designs/`. 클라우드 프로젝트: 서버가 정본이고, 작업 사본 `designs/` 는 받은 사본이다(아래 "클라우드").

### Figma 연결 (앱 설정 › 연결)

- **개인 액세스 토큰**(권한 `file_content:read` 하나)을 넣는다. 따로 확인 호출은 하지 않고, 첫 가져오기의 응답으로 확인한다(`/v1/me` 는 다른 권한이 필요해 쓰지 않는다). 토큰은 **앱 전역 설정**으로 `safeStorage` 암호문에 둔다. 프로젝트 vault 에 넣지 않고, 엔진 · 클라우드 · AI 에 넘기지 않으며, 로그에 남기지 않는다.
- 토큰이 없거나 거절되면(403) 가져오기 · 새 버전 확인 버튼에 "Figma 연결 필요" 를 띄운다. 저장된 디자인으로 하는 비교와 실행은 그대로 된다.

### 가져오기

1. 디자인 탭 "Figma 에서 가져오기"에 프레임 링크를 한 줄에 하나씩 붙여 넣는다. 받는 링크: `figma.com/design/<fileKey>/…?node-id=<a>-<b>`(`/file/` 도), 브랜치 링크는 브랜치 키를 쓴다. `node-id` 의 `-` 는 `:` 로 바꾼다.
2. `GET /v1/files/<fileKey>/nodes?ids=<nodeId>` 로 파일 `version` · `lastModified`, 노드 이름 · 종류 · `absoluteBoundingBox`(width · height)를 얻는다. `nodeHash` = 노드 `document` JSON 의 SHA-256 이다. 노드 종류가 FRAME · COMPONENT · COMPONENT_SET · INSTANCE · SECTION 이 아니면 경고만 하고 받는다.
3. `GET /v1/images/<fileKey>?ids=<nodeId>&format=png&scale=2` 가 돌려준 주소에서 PNG 를 받는다. 주소는 저장하지 않는다(서명된 임시 주소).
4. 미리보기(썸네일 · 이름 · 크기)를 확인하고 저장한다. 오류(404 노드 없음 · 렌더 실패 `null` · 429)는 링크별로 표시하고, 나머지 링크는 계속 받는다.

### 새 버전 확인

- 디자인 탭을 열 때(파일당 10분에 한 번까지)와 "새 버전 확인" 버튼을 누를 때, 파일별로 `GET /v1/files/<fileKey>/nodes?ids=<그 파일의 노드들>` 을 부른다. 노드별 `nodeHash` 가 저장값과 다르면 **"새 버전 있음"** 으로 표시한다. 파일 `version` 만 바뀐 것은 무시한다(다른 프레임이 바뀐 것일 수 있음).
- 자동으로 바꾸지 않는다. "다시 가져오기"를 누르면 같은 이름으로 덮는다. 이미 끝난 실행의 비교 결과는 실행 폴더의 사본이라 바뀌지 않는다.

## 스크립트 — `design` 단계

```yaml
- design: { name: login }                                   # 화면(뷰포트) 전체를 디자인 'login' 과 비교
- design: { name: header, target: { testId: app-header } }  # 요소만
- design: { name: home-long, fullPage: true }               # 페이지 전체
  mask: [ { testId: clock } ]                               # 공통 옵션 — 비교에서 뺄 영역
```

| 필드 | 뜻 |
|---|---|
| `name` | 디자인 이름 (필수) |
| `target` | 요소만 찍는다(선택). `fullPage` 와 함께 쓸 수 없다(검증 오류) |
| `fullPage` | 페이지 전체(기본 `false`) |

- 공통 옵션 `name` · `timeout` · `optional` · `mask` 를 쓸 수 있다. 화면을 바꾸지 않는 단계라 `settle` 은 적용하지 않는다. 화면이 준비될 때까지 기다리려면 앞에 `wait` 를 둔다.
- 디자인 폴더: 엔진 실행 옵션 `designsDir`(CLI · MCP `--designs-dir`). 기본값은 `<스크립트 폴더>/designs/` 이다. 앱은 프로젝트의 `designs/` 를, 클라우드 러너는 받아 둔 임시 폴더를 넘긴다.

### 편집기 · 녹화 · AI

- 편집기 "단계 추가 › 디자인 비교": 디자인을 썸네일 목록에서 고르고 대상 · 전체 페이지를 정한다. 단계 문장은 `🎨 디자인 'login' 과 비교` 이다(대상이 있으면 `… 의 '헤더' 영역`).
- **뷰포트 안내**: 스크립트 뷰포트 너비(`browser.viewport` · 디바이스 프리셋, 기본 1280)가 프레임 너비와 다르면 그 단계 아래에 "디자인 너비 1440 · 뷰포트 1280 — 크기가 달라 겹쳐 보기만 됩니다 [뷰포트를 1440 으로]" 를 띄운다. 버튼은 `browser.viewport.width` 를 바꾼다(저장은 평소대로).
- 시연 녹화의 체크포인트 종류에 "디자인 비교"(디자인 고르기)를 더한다. 녹화 저장 · AI 정리 때 `design` 단계가 된다.
- 앱 AI 도구에 `list_designs`(이름 · 프레임 이름 · 크기)를 더해, AI 가 스크립트를 만들거나 고칠 때 `design` 단계를 넣을 수 있게 한다.

## 엔진 — 비교 규칙

1. **디자인이 없으면** (`<designsDir>/<name>.png` 없음) 단계는 `passed`, 비교 상태는 `missing`, 경고 로그 1줄을 남긴다. 디자인을 만들지 않는다.
2. **화면 찍기**: 뷰포트 · 요소 · 페이지 전체. 일반 스크린샷과 같이 secrets 입력란과 `mask` 영역을 가리고, 가린 영역은 디자인 쪽에서도 같은 자리를 비교에서 뺀다. 요소를 못 찾으면 다른 단계처럼 `failed` 이다(디자인 판정이 아님).
3. **크기 맞추기**: 실제 화면의 CSS 크기 = 이미지 픽셀 ÷ `devicePixelRatio`, 디자인의 CSS 크기 = `.json` 의 `width`·`height`.
   - 너비가 같으면(±1px) 디자인 이미지를 실제 픽셀 크기로 다시 샘플링한 뒤 비교한다.
   - 너비가 다르면 `size-mismatch` — 픽셀 비교 없이 두 이미지만 남긴다(나란히 · AI 검수는 됨).
   - 높이가 다르면 위에서부터 겹치는 부분만 비교하고 `heightDiffers`(디자인 · 실제 높이)를 기록한다.
4. **픽셀 차이(참고 수치)**: `pixelmatch`(색 임계 0.1)로 다른 픽셀 비율 `diffRatio` 를 구하고 차이 이미지를 남긴다. `diffRatio > 0.01` 이면 `differs: true` — 목록 표시용일 뿐 판정이 아니다.
5. **단계 · 실행 상태는 바꾸지 않는다.** 디자인 차이 · 크기 다름 · 디자인 없음 모두 단계 `passed` 이므로 실행 실패 · 실패 알림(Teams · 앱)이 생기지 않는다.

### 결과 기록

```
runs/<run-id>/designs/<name>/
  actual.png       실제 화면 (가림 적용)
  reference.png    비교에 쓴 디자인 (크기를 맞춘 것)
  diff.png         차이 (compared 일 때만)
  reference.json   디자인 .json 사본 (Figma 링크 · 버전)
```

- 한 실행에서 같은 이름을 두 번 비교하면 둘째부터 `<name>-2` … 폴더를 쓴다.
- 이벤트 `design.compared` = `{ stepId, name, dir, status: compared | size-mismatch | missing, diffRatio?, differs?, heightDiffers?, actual: { width, height, dpr }, reference?: { width, height, figma } }`.
- `run.json` 의 `designChecks[]` 는 이벤트와 같은 내용이다. 요약 `summary.designChecks = { total, differing, sizeMismatch, missing }` 이다(없으면 생략).
- `report.html` 에 "디자인 비교" 절을 넣는다. 비교마다 디자인 · 실제 · 차이를 나란히 두고, 차이 비율과 Figma 링크를 단다. AI 검수는 실행 뒤에 생기므로 `report.html` 에는 넣지 않는다(앱 · 웹 화면에서 본다).

## 앱 — 검수 화면 · AI 검수

### 화면

- **디자인 탭**(프로젝트): 썸네일 · 이름 · Figma 프레임 이름 · 크기 · 가져온 시각 · 상태(최신 / 새 버전 있음 / 확인 못 함). 동작은 Figma 에서 가져오기 · 다시 가져오기 · Figma 에서 열기 · 삭제(쓰는 스크립트가 있으면 이름을 보여 주고 확인)이다. 클라우드 프로젝트에서 "보기" 역할이면 목록만 보인다.
- **Live**: 디자인 비교 단계에 배지 🎨 `차이 3.2%` / `크기 다름` / `디자인 없음` 을 단다.
- **실행 상세 › 디자인 검수**(비교가 있는 실행만): 왼쪽은 비교 목록(이름 · 단계 · 배지 · AI 항목 수), 오른쪽은 보기 전환(**나란히 · 슬라이더 · 겹치기**(투명도) · **차이**)이다. 맨 위에 **[AI 검수]** 버튼을 둔다. 내려받은 클라우드 실행도 같은 화면이다.

### AI 검수

- 버튼을 누르면 `missing` 을 뺀 비교마다 AI 에 1번씩 묻는다. 경로는 앱 AI 채팅과 같다([ADR-015](ADR_015_앱-AI-채팅-Agent-SDK.md) — 본인 PC · 본인 구독 · 격리 설정). 이 질의에는 도구를 주지 않는다. 입력은 디자인 · 실제 이미지와 비교 정보(크기 · 크기 다름 여부)이다.
- AI 는 차이 목록을 JSON 으로 돌려준다.
  ```
  items: [ { category: layout | spacing | size | color | typography | text | missing | extra | other,
             severity: high | medium | low, summary: "로그인 버튼이 디자인보다 8px 아래", box?: { x, y, width, height } } ]
  ```
  `box` 는 실제 이미지 좌표다. 화면에서는 실제 이미지 위에 상자로 그리고, 목록 항목을 누르면 그 상자를 강조한다.
- 응답 형식이 틀리면 그 비교만 "AI 응답을 읽지 못함"으로 표시하고 [다시] 버튼을 단다. 진행 중에는 [중지] 버튼을 둔다(이미 받은 비교는 남음).
- **사람 판정**: 항목마다 `수정 필요` / `의도된 차이` / 미정. 판정은 바로 저장한다.
- 다시 돌리면 확인을 받은 뒤 그 실행의 AI 항목과 판정을 새 결과로 바꾼다.

### 검수 결과 저장

```
<프로젝트(또는 작업 사본)>/design-reviews/<실행 id>.json
  { runId, source: local | cloud, cloudRunId?, createdAt, updatedAt,
    checks: [ { name, items: [ { …위 항목, verdict?: fix | intended } ], error? } ] }
```

- 실행 id 는 로컬 실행이면 엔진 실행 id, 클라우드 실행이면 클라우드 실행 id 이다. 실행 폴더 · 클라우드 실행 캐시(2GB, 오래된 것부터 지움) **밖**에 두므로 캐시가 지워져도 남는다.
- **클라우드에 올리기**: 클라우드 실행, 그리고 이 PC 가 클라우드에 올린 로컬 실행(☁ 올림)은 저장할 때마다 서버에도 보낸다(편집자 이상). "보기" 역할이거나 오프라인이면 로컬에만 저장하고, "클라우드에 못 올림"을 표시한 뒤 다음 저장 · 연결 때 다시 보낸다.
- 실행을 지우면 그 검수 결과도 지운다.

## 클라우드 (C8)

### 디자인 동기화

- 서버 저장: `<root>/<projectId>/designs/<name>.png|.json`. 결과 정리(30일 · 용량 상한) 대상이 아니다. 프로젝트를 영구 삭제할 때 함께 지운다.
- API (권한: 보기 이상 = 읽기, 편집자 이상 = `design.write`, 개인 토큰이면 `읽기·쓰기`)

| 호출 | 뜻 |
|---|---|
| `GET /api/projects/:id/designs` | 목록 (`.json` 내용 + 갱신 시각 · 올린 사람) |
| `GET /api/projects/:id/designs/:name/image` | PNG |
| `PUT /api/projects/:id/designs/:name` | 올리기·덮기 — multipart(`image` PNG ≤ 20MB, `meta` JSON). 이름 규칙 · PNG 시그니처 검사 |
| `DELETE /api/projects/:id/designs/:name` | 지우기 |

- 변경 피드 `design.changed { name, action: put | delete }` 를 받으면 앱 작업 사본 `designs/` 를 갱신한다. 클라우드 프로젝트에서 가져오기 · 다시 가져오기 · 삭제는 서버에 먼저 반영하고, 성공하면 작업 사본을 바꾼다(오프라인이면 버튼을 막음).
- 러너: 실행 전 `GET /internal/runs/:id/designs`(tar, 내부 포트 · 러너 토큰)를 임시 폴더에 풀고 엔진 `--designs-dir` 로 넘긴다. 실행 결과 폴더의 `designs/` 는 다른 결과 파일처럼 올라간다(tar 검사에 경로 허용).
- 서버 실행 색인에 `summary.designChecks` 를 저장한다(목록 · 현황에 "디자인 차이 N" 표시용).

### 검수 결과

- `GET /api/projects/:id/runs/:runId/design-review` (보기 이상) · `PUT …/design-review` (편집자 이상, JSON ≤ 1MB, 형식 검사). **DB 에 저장**하므로 결과 파일이 만료돼도 남는다. 실행 기록과 함께 1년 뒤 지운다.
- 피드 `run.design_review { runId }` — 그 실행을 보고 있는 웹 · 앱 화면이 다시 읽는다.

### 웹

- 실행 상세 **"디자인"** 탭: 앱과 같은 보기 전환(나란히 · 슬라이더 · 겹치기 · 차이)을 결과 파일로 보여 주고, 올라온 AI 항목 · 판정은 읽기만 한다. 결과 파일이 만료되면 이미지는 "파일 만료"로 두고 항목 목록만 보인다. AI 검수가 없으면 "앱에서 AI 검수를 돌리면 여기에 보입니다" 를 띄운다.
- 프로젝트 **"디자인"** 목록(읽기만): 썸네일 · 이름 · Figma 링크 · 갱신 시각.
- 실행 목록 · 현황: 요약에 "디자인 차이 N" 을 표시한다.

## 보안

- Figma 토큰은 이 PC 의 앱 설정에만 있다(위). Figma 렌더 주소는 저장하지 않는다.
- 디자인 이미지는 프로젝트 자료로 취급한다. 로컬 프로젝트이거나 사내 클라우드 서버(공개 범위는 프로젝트 권한과 같음)에 둔다.
- AI 검수는 디자인 · 실제 이미지를 본인 구독 AI 에 보낸다. 실제 이미지는 secrets 를 가린 것이다. 클라우드로 올리는 것은 AI 가 낸 텍스트 항목과 사람 판정뿐이다.

## 완료 기준 (검증)

- **엔진**(단계 11): 단위 테스트 — 링크·이름 규칙, 크기 맞추기(같은 너비 · 다른 너비 · 다른 높이 · dpr 2), 가림 영역 제외, 같은 이름 두 번, `missing`. 픽스처 E2E — 픽스처 페이지를 찍어 둔 것을 디자인으로 두면 `differs: false`, 페이지를 바꾸면 `differs: true`, 다른 너비면 `size-mismatch`, 없는 디자인이면 `missing` 이고 넷 다 실행 `passed`. `report.html` 에 디자인 비교 절이 있어야 한다.
- **앱**(단계 11): 단위 테스트 — Figma 링크 해석 · 응답 매핑 · `nodeHash` · 새 버전 판정 · AI 응답 검사. E2E(개발 · 패키징본, 가짜 Figma API 서버 · 가짜 에이전트) — 가져오기 → 편집기에서 단계 추가 → 실행 → 검수 화면 보기 전환 → AI 검수 → 판정 → 재시작 후 유지. 토큰이 결과 · 로그 · 설정 평문에 0건이어야 한다.
- **클라우드**(C8): 서버 단위 테스트(디자인 API 권한 · 피드 · 러너 tar · 검수 결과 크기 · 형식) · 실제 러너 실행 결과에 `designs/` · 웹 E2E(디자인 탭 · 검수 결과 표시 · 파일 만료) · 앱 E2E(디자인 올리기 → 클라우드 실행 → 내려받아 AI 검수 → 서버에 올라감 → 웹에 보임) · dev 배포본 반영.
- **수동 1회**(사용자 Figma 토큰): 실사용 대상 서비스의 실제 프레임 가져오기 → 실행 → AI 검수(실제 모델).
