# ADR - 030 선택자 점검 구현

## 상태

채택 (2026-10-23, 단계 12 구현). euta-engine `1f9b334` · euta-app `c987aeb` · euta-claude-plugin `aac4654`(로컬 커밋). macOS(arm64)에서 엔진 단위·픽스처 E2E·MCP 스모크, 앱 단위(가짜 에이전트 호출 포함)·타입체크·빌드로 검증했다. 실사용 대상 서비스 실제 실행 수동 점검(완료 기준 마지막 항목)은 아직 하지 않았다.

## 맥락

- [SPEC_선택자-점검](SPEC_선택자-점검.md) 이 기능(스냅샷 시점·범위·판정·화면 지도·AI 도구 2종)을 정했다. 이 ADR 은 SPEC 이 정하지 않은 **구현 방식**을 기록한다: 직렬화 방법, 스타일 저장, 파일 배치·압축, 오프라인 재현, 후보 생성, 화면 묶기, trace 복원, 도구 출력.
- 시작점은 실사용 대상 서비스 TC 작성 때 손으로 만든 프로토타입(trace → HTML 복원, 실사이트 CSS 를 `<base href>` 로 빌려 aria 스냅샷, 스크립트 대상 개수 세기). SPEC 은 스타일을 저장해 **오프라인**으로 점검하라고 정했다.
- 확인한 사실: Playwright 는 `javaScriptEnabled: false` 컨텍스트에서도 `page.evaluate`·locator·`ariaSnapshot` 이 동작한다. `getByRole` 은 숨은 요소를 원래 제외한다. 최신 trace 의 `resource-snapshot` 은 응답 본문을 `_sha1` 대신 `_file`(`resources/<sha1>.<ext>`)로 가리킨다.

## 결정

### 1. 직렬화 — 페이지 안 직렬화기 (CDP 아님)

- `DOMSnapshot.captureSnapshot`(CDP)은 Chromium 전용이라 쓰지 않는다. 페이지 안에서 DOM 을 걸어 HTML 문자열을 만든다(`runner/dom.ts` `DOM_SERIALIZE_BODY`). 녹화기 수집 스크립트처럼 **문자열**로 두고 Node 쪽에서 `new Function` 으로 함수를 만들어 `page.evaluate` 에 넘긴다(번들러 헬퍼가 페이지에 섞이지 않음 · CSP 영향 없음).
- 버리는 것: `<script>`·`<noscript>`, `on*` 속성, `javascript:` URL(→ `#`), `<meta http-equiv=refresh>`, `preload`/`prefetch` 링크.
- 상태는 속성으로: 입력란 `value`(현재 값), `checked`, `<option selected>`, `<textarea>` 내용. 열린 shadow root 는 선언형 `<template shadowrootmode>`. 같은 출처 iframe 은 `srcdoc` 으로 안에 넣고, 다른 출처 iframe 은 상자만(`src` 대신 `data-euta-src`).
- **password 입력란 값은 페이지 안에서 버린다**(원래 `value` 속성도). 또 `${secrets.*}` 로 채운 입력란(실행기의 `secretMaskTargets` — 스크린샷 가림과 같은 목록)은 요소 핸들로 넘겨 값을 쓰지 않는다. 그 위에 HTML 전체를 실행의 `Redactor` 로 마스킹한다(ADR-006 — 인코딩 변형 포함). 직렬화기의 HTML 이스케이프는 `secretVariants` 의 HTML 이스케이프와 같은 규칙(`& < > " '`)이라 이스케이프된 secret 도 잡힌다.

### 2. 스타일 — CSSOM 규칙 텍스트, 실행 안 내용 해시로 1번만

- `<style>`·`<link rel=stylesheet>`·`adoptedStyleSheets` 의 `cssRules` 텍스트를 모은다(CSSOM 이라 `insertRule()` 로 만든 CSS-in-JS 도 잡힘, `@import` 는 펼침). 읽을 수 없는 다른 출처 시트는 주소만 남긴다(점검 때는 네트워크를 막으므로 적용되지 않음).
- 요소 자리에 `<link rel="stylesheet" href="/__euta__/styles/<hash>.css">` 를 넣어 **원래 순서(캐스케이드)를 지킨다**. `<hash>` = 마스킹한 CSS 텍스트의 sha256 앞 16자. 파일은 실행 안에서 1번만 쓴다(`dom/styles/<hash>.css.gz`).
- 대안: 스냅샷마다 `<style>` 로 인라인 — 화면마다 수백 KB 가 반복되어 버림. 실사이트 CSS 를 `<base href>` 로 빌림(프로토타입) — 오프라인 불가·사이트가 바뀌면 결과가 달라져 버림.

### 3. 파일 배치 · 압축 · 시점

- `dom/<seq 3자리>-<stepId(. → _)>-<before|after>.html.gz` + `dom/styles/` + `dom/index.json`(`{ version: 1, viewport, snapshots: [{ seq, stepId, phase, action, url, title, file, bytes, styles[], ts }], styles: { <hash>: { file, bytes } } }`). `dom/` 은 첫 스냅샷 때 만든다(`record.dom: false` 면 폴더 자체가 없음).
- **압축 = gzip(`node:zlib`)**. 새 의존성 없음, 표준 도구로 열 수 있음. 대안: 압축 없음(화면당 수십~수백 KB) · zip 한 파일(실행 중 덧붙이기 어려움).
- `index.json` 은 **스냅샷마다 다시 쓴다** — 열린 탐색 세션·중간에 끊긴 실행도 점검할 수 있게. `run.json` 의 `dom` = `{ snapshots, styles, bytes }`(남겼을 때만). `record` 기본값 표에 `dom: true`, `--cloud` 는 `dom: 'on-failure'`(스크립트 명시값 우선).
- 시점: `goto`·입력 스텝은 동작 직전(`before`, 첫 `goto` 처럼 페이지가 `about:blank` 면 건너뜀)과 settle 뒤(`after` — 동작이 실패해도 찍음: 실패 화면), `expect`·`wait` 는 판정이 끝난 뒤 `after` 1장. `measure`·`visual`·`expectDownload`·`group` 자체는 찍지 않는다(그룹·트리거의 하위 단계가 찍음).
- `on-failure` 이고 실행이 `passed` 면 종료 처리에서 `dom/` 을 지우고 로그 1줄 `DOM snapshots discarded (record.dom: on-failure, run passed)` — 기존 `trace and video discarded …` 문장은 그대로 둔다.
- 스냅샷 1장은 5초 제한. 실패(페이지 이동 중 등)는 `log` 경고 1줄 `DOM snapshot (before) failed: …` 뿐, 단계 결과는 그대로. 픽스처 31장 실행에서 시간 차이는 측정 오차 수준(약 5.0s 대 5.0~5.4s).
- `artifact.saved` 이벤트는 내지 않는다(단계마다 2건이 Live·리포트를 채움). MCP `get_run` 의 `artifacts[]` 는 `dom/` 을 `{ path: 'dom/', size, files }` 1줄로 접는다.

### 4. 오프라인 재현 · 판정

- 점검용 headless Chromium 1개(실행 엔진과 무관), 실행의 viewport, **`javaScriptEnabled: false`**, 서비스 워커 차단. 컨텍스트 `route('**/*')`: 스냅샷의 원래 주소로 가는 내비게이션 1번에 저장 HTML 을, `/__euta__/styles/<hash>.css` 에 저장 CSS 를 돌려주고 나머지는 모두 abort(원래 주소로 열어 상대 경로·`location` 이 맞음; http(s) 가 아니면 `http://euta.snapshot/`). `setContent` 는 상대 경로가 깨지고 외부 리소스를 기다리다 멈출 수 있어 쓰지 않는다.
- 개수 = 실행기와 같은 `resolveTarget(page, t).filter({ visible: true }).count()`. 단계 id 는 실행기와 같은 규칙(`group` → `n.i`, `expectDownload.trigger` → `n.1`).
- 판정 구현 메모(SPEC 표 보완 — SPEC Change Log 에 반영):
  - `dynamic` 은 확인뿐 아니라 **동작**에도 쓴다 — 동작 전 화면에 0개인데 실행에서 그 단계가 통과했으면(Playwright 가 기다리는 동안 나타남) `missing` 이 아니라 `dynamic`.
  - `expect.text` 는 2개 이상이면 `ambiguous` — 실행기의 `innerText()` 가 strict 라 실행하면 오류.
  - `expect.count` 는 실행기처럼 숨은 요소 포함 개수로 보고, 0개인데 조건이 0을 허용하지 않을 때만 `missing`.
  - "통과했으면" = 같은 단계 id 의 실행 결과가 `passed` 이고, 스크립트가 같거나(`scriptHash`) 그 단계의 원문이 run.json `script` 의 같은 단계와 같을 때만. 다른 스크립트로 점검하면 `dynamic` 이 나오지 않는다.
  - `${secrets.*}` 가 든 대상·정의 안 된 참조·형식이 틀린 대상은 `skipped`(+ 이유). `${vars.*}` 는 run.json `vars` → 스크립트 `vars` 위에 도구 입력 `vars`, `${env.*}` 는 도구 입력/서버 환경으로 채운다(검증 없이 대상만 보간 — secrets 가 없어도 로그인 스크립트를 점검할 수 있게).

### 5. 후보 — 녹화기 규칙 재사용

- 녹화기 수집 스크립트의 순수 함수(역할·접근 이름 근사, 개수 세기, `cssPath`, `targetOf`)를 `TARGET_HELPERS` 문자열로 떼어 녹화기와 점검이 같이 쓴다(녹화기 동작은 그대로 — 기존 녹화기 테스트 통과).
- `ambiguous`: 보이는 일치 요소 각각(최대 3). `missing`: 대상의 이름·라벨·텍스트·placeholder·testId 문자열과 비슷한(같음 1 · 포함 0.6~1 · 글자 bigram Dice) 보이는 요소를 점수순으로 최대 3개 — 동작 대상이면 상호작용 요소 우선, 라벨은 그 입력란으로 바꾸고 서로 포함하는 요소는 하나만. CSS·역할만 있는 대상은 후보 없음.
- 요소마다 `targetOf` 후보를 **SPEC 순서(role+이름 → 라벨 → placeholder → 텍스트 → testId → CSS)** 로 다시 정렬하고 Playwright 로 다시 세어 처음으로 1개인 것(필요하면 `exact: true`)을 고른다 — 후보 개수가 판정과 같은 규칙. 녹화기 자체 순서(testId 가 텍스트 앞)는 바꾸지 않았다.

### 6. 화면 지도

- 화면 = 주소(쿼리·해시 제외) + **구조 해시**: aria 스냅샷에서 역할만 남기고(이름·텍스트·상태 제거) 연속 반복 줄을 하나로 접은 것의 sha1. 그래서 입력값·체크 상태·행 개수만 다른 스냅샷은 같은 화면, 대화상자가 열린 상태는 다른 화면(`dialog` = 대화상자 이름). 화면마다 **마지막** 스냅샷의 aria·h1 을 보여 준다. 같은 HTML 은 한 번만 렌더.
- 공통 머리말·꼬리말: 첫 화면의 최상위 블록(3줄 이상) 중 돌려주는 모든 화면에 똑같이 있는 것은 2번째 화면부터 `- banner: … (same as the first screen, N lines omitted)`.
- 상한: 화면 20(도구 입력 최대 50), 화면당 400줄 — 잘렸으면 `truncated` 와 `… (N more lines)`.

### 7. trace 복원 (보조 경로)

- `dom/index.json` 이 없고 `trace.zip` 이 있으면 프로토타입을 엔진으로 옮긴 `snapshotsFromTrace` 로 복원: 메인 프레임 `frame-snapshot`(프레임별 목록 · 하위 트리 참조 `[[n, i]]` · 후위 순회 번호), `__playwright_value_/checked_/selected_/style_sheet_/shadow_root_` 반영, password 값 미복원. 단계 짝짓기 = `steps.jsonl` 의 `step.started`~`step.finished` 시각 창 안의 스냅샷 `wallTime` — 첫 장 `before`, 마지막 장 `after`. CSS 등 하위 리소스는 trace 의 `resource-snapshot`(`_file`/`_sha1`)·`resourceOverrides` 에서 그대로 돌려준다(오프라인).
- 둘 다 없으면 `NoDomSnapshotsError`: "DOM 스냅샷 없음 — record.dom 을 켜고 다시 실행하세요". 도구에서는 `isError` 결과.

### 8. 도구 (공용 핸들러 · 앱 · 플러그인)

- `@euta/mcp-server/tools` 에 `get_page_map`·`check_script_targets`(`readOnlyHint`). `check_script_targets` 입력은 SPEC 대로 `script`(본문) 또는 `path` — 다른 도구의 `yaml` 이름과 다르다. `path` 는 기존 `loadScript`(작업 폴더 기준 → 앱에서는 프로젝트 스크립트 폴더). 출력: 요약 JSON + 단계별 결과(최대 150건, 넘으면 `truncated`), `problems`(missing·ambiguous·present 수), `next` 안내. `get_page_map` 출력: 화면 목록 JSON + 화면별 aria 텍스트(`### Screen n: url — title [dialog "…"] (steps …)`). 모든 텍스트는 서버 secret 로 다시 마스킹.
- 앱: 게이트는 등록된 euta 도구 이름 집합이라 핸들러 목록에 넣는 것만으로 확인 없이 허용(`get_run` 과 같은 등급). 시스템 프롬프트 "How to work" 와 cheatsheet 에 "쓰기 전에 get_page_map, 실행 전에 check_script_targets" 한 줄. `session_open` 의 `record` 입력에 `dom`.
- 플러그인: `write-test-script` 스킬에 두 도구 허용·안내 1단락, 도구 목록 테스트 갱신(13 → 15).

## 결과

- 엔진 단위 `dom.test.ts` 10건(직렬화·마스킹·스타일 중복 제거·index·판정 표·판정 7종 + 후보(합성 실행)·스냅샷 없음·화면 묶기/대화상자/공통 머리말/상한·trace 복원), 픽스처 E2E `selector-check.test.ts` 4건(성공 실행 `dom/` · 틀린 스크립트 missing/ambiguous/present + 후보 · 후보로 고친 스크립트 점검 ok·실행 통과 · `record.dom` false/on-failure/`--cloud` · 로그인 스냅샷 secret 0건 · trace 복원 같은 판정), MCP 스모크 1건 + 도구 목록 2건 갱신, 앱 단위 1건(가짜 에이전트 → 두 도구 게이트 allow) + 도구 수 갱신.
- 남은 것: 실사용 대상 서비스 실제 실행 수동 점검 1회. 앱 화면·CLI·클라우드 원격 MCP 는 범위 밖(후속).
- 알려진 한계: 다른 출처 CSS·iframe 은 점검에 반영되지 않는다(SPEC 대로 주소만). `:hover`·애니메이션 중 상태·닫힌 shadow root·캔버스 내용은 재현되지 않는다. 역할·이름 근사(후보 생성)는 Playwright 계산과 다를 수 있어 후보 개수는 Playwright 로 다시 센다.
