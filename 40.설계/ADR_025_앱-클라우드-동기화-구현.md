# ADR - 025 앱 클라우드 동기화 구현

## 상태

채택 (2026-10-21, C2 구현). macOS(arm64)에서 앱 단위 테스트와 **실제 로컬 euta cloud 서버**(euta-cloud docker compose PostgreSQL + 빌드된 서버) 대상 앱 E2E(개발 빌드 + 패키징본)로 검증했다. 결과는 아래 "결과" 절. C3(실행 위임·예약·알림)는 범위 밖이다.

## 맥락

- [SPEC_클라우드-앱-연동](SPEC_클라우드-앱-연동.md) 이 연결·작업 사본·동기화·충돌 3선택·오프라인·이 PC 테스트 계정·올리기를 정했다. 이 ADR 은 SPEC 이 정하지 않은 **구현 방식**과 구현 중 정한 세부를 기록한다.
- 서버 쪽 사실(euta-cloud 코드로 확인): 스크립트 PUT 본문 `{source, baseVersion, origin, memo}`(origin `web·app·ai_mcp·external`), 409 `details.current`(버전·원문·작성자·시각), 내용이 같으면 `unchanged`, 변경 피드 data = 작업 로그 details(`path`·`version`·`from/to` 등), SSE `ready`/`change`/`resync`, 장치 인가는 브라우저에서 `GET /api/auth/device?user_code=` 로 코드를 확보한 뒤 승인, 토큰 요청은 JSON 만(ADR-023 결과). 서버 id 는 UUID.

## 결정

### 1. 모듈 — 메인 프로세스 `src/main/cloud/`, Electron 비의존

| 모듈 | 하는 일 |
|---|---|
| `client.ts` `CloudClient` | fetch 래퍼(주입 가능). Bearer = 장치 토큰. 오류 봉투 → `CloudError(status, code, details)`, 연결 불가·게이트웨이 오류 → `CloudNetworkError`. 요청 15초 시간 제한. 장치 코드·토큰 폴링(JSON), 전 API, SSE 스트림(`events()`) |
| `sse.ts` `SseParser` | fetch 본문을 읽는 SSE 파서 — `EventSource` 는 `Authorization` 헤더를 못 보내서 직접 구현(`id`·`event`·`data`·주석·`retry`·CRLF·청크 경계) |
| `account.ts` `CloudAccount` | `<userData>/cloud/account.json` = 서버 주소 · 계정(id·이메일·이름·관리자) · 토큰 **safeStorage 암호문**. 복호화는 메인에서만 |
| `workcopy.ts` `WorkingCopy` | `state.json` · `snapshot.json` · `pending/<순번>.json` 파일 계층 |
| `sync.ts` `ProjectSync` | 프로젝트 1개의 동기화 엔진: 보내기 대기열·충돌·피드 반영·전체 다시 받기 |
| `cloud-service.ts` `CloudService` | 연결 상태·재연결·장치 로그인, 작업 사본 등록, 연 프로젝트의 SSE, 서버 이력, 클라우드 쪽 설정, 올리기. `ProjectService` 에 `CloudBridge` 로 붙는다 |

- 서버 응답 타입은 앱 안(`cloud/types.ts`)에 필요한 필드만 옮겨 둔다. `@euta-cloud/shared` 를 `link:` 하지 않는다 — 다른 레포의 빌드 산출물·잠금 파일에 묶이지 않게(대안: 타입 전용 devDependency — 패키징·동시 작업 레포 결합 때문에 기각).

### 2. 프로젝트 모델 — 같은 `ProjectStore` 안의 두 종류

- 작업 사본 폴더는 SPEC 대로 `<userData>/cloud/<serverId>/projects/<cloud projectId>/`(serverId = 서버 주소 sha256 앞 12자). `ProjectStore` 가 이 루트도 읽고, 클라우드 프로젝트는 `dir(id)` 만 그 폴더를 가리킨다. 그래서 스크립트 라이브러리·감시자·실행 조립·History·채팅·녹화·작업 로그는 **로컬 프로젝트 코드 그대로** 작업 사본에서 돈다.
- **앱 id = 클라우드 UUID 에서 `-` 를 뺀 32자 hex** (환경·스위트도 같음). 앱의 id 규칙(`[a-z0-9]{6,32}`)·IPC 검사·vault 키 형식을 바꾸지 않아도 되고, vault 키 `projectId/envId/NAME` 이 그대로 **클라우드 id 기준**이 된다(SPEC "키 = 클라우드 projectId/envId/NAME"). 대안: id 규칙에 `-` 허용 — 검사 지점이 많아 기각.
- `project.json` 은 클라우드 프로젝트에도 둔다: `snapshot.json`(서버 사본) + 이 PC 설정(고정·headless·스위트 "실패 시 중단" — 서버에 없는 필드)으로 다시 만든 파생본. `Project.cloud = { serverUrl, serverId, projectId }`. 로컬 프로젝트에는 올린 뒤 `uploadedTo`.

### 3. 스크립트 저장 — 쓰기 한 경로 + "먼저 대기열" (local-first)

- `ProjectService.writeScript`(편집기·AI `save_script`·녹화 저장·만들기/가져오기)가 클라우드 프로젝트면 **작업 사본 파일을 쓰고 → 대기열에 넣고(`pending/`, 기준 버전 = state 의 그 스크립트 버전) → 온라인이면 즉시 보낸다**. 온라인·오프라인이 같은 경로다(ARCH "오프라인 대기분도 같은 규칙").
- 보내기는 순번 순서, 같은 스크립트가 여러 건이면 앞 건이 성공해 올린 버전이 다음 건의 기준이 된다. 성공 → 새 버전이 기준 버전. 409 → 그 건이 `conflict` 가 되고 **대기열이 거기서 멈춤**(뒤 건은 대기 유지). 422(검증)·403 → `rejected`, 역시 멈춤. 네트워크 오류 → 오프라인 전환, 대기 유지. 401 → 로그인 필요.
- 호출자는 결과 Promise 를 받는다: 편집기 저장은 서버 답(저장됨/보내기 대기/충돌)을 기다려 화면에 반영하고, AI 저장도 기다린다.
- 출처: 편집기·녹화·만들기·가져오기 = `app`, AI = `ai_mcp`(서버에 "앱 AI 채팅" 출처가 없어 MCP 와 같은 "AI" 로 표시), 감시자의 바깥 변경 = `external`, 되돌리기 = 서버 `revert` 경로.
- 클라우드 프로젝트는 로컬 `script-history` 를 쓰지 않는다. 이력·비교·되돌리기·삭제된 스크립트 화면은 서버 이력(`versions`·`versions/:n`·`revert`·`restore`)을 같은 화면 형식(`ScriptVersionView` + 작성자·출처)으로 보여 준다. 버전 원문은 메모리 캐시.

### 4. 충돌 — 하나의 3선택 화면

- 충돌이 생기는 곳은 셋이고 모두 같은 `pending` 항목(`status: conflict`, 내 원문 + 서버 현재)과 같은 화면으로 모인다.
  1. 서버 409(오프라인 대기분 재전송, 피드가 아직 안 온 동시 저장).
  2. **편집 중에 작업 사본이 바뀜**(다른 사람 저장이 피드로 먼저 도착) — 편집기 기준 원문의 해시 ≠ 지금 파일이면 서버로 보내기 전에 충돌로 만든다. 피드가 기준 버전을 이미 올려 두었으므로 그냥 보내면 남의 저장을 덮기 때문.
  3. AI 저장 — 아래 5.
- 선택: ① 내 것 = 서버 현재 버전을 기준으로 다시 PUT(그사이 또 바뀌면 충돌 정보 갱신) · ② 서버 것 = 서버 최신을 받아 쓰고 그 스크립트의 대기분 모두 버림 · ③ 사본 = `<이름>-<내 이름>.yaml`(이름의 공백·경로 문자는 `-`, 겹치면 `-2`…)로 새 스크립트 PUT, 원본은 ②. 거절(422 등)은 "다시 보내기"/"버리기".
- 해결 전까지 작업 사본에는 내 원문이 남는다(이 PC 실행은 내 것으로 돈다). 목록·사이드바·프로젝트 상단에 "충돌" 표시, 화면을 닫아도 배너로 다시 연다.
- 화면 비교는 앱의 단계 문장 비교(`diffScripts`, 서버 최신 → 내 것)를 메인에서 계산해 넘긴다.

### 5. AI 저장 충돌 — "AI 가 읽은 버전"이 기준

- 문제: AI 가 `read_file` 한 뒤 다른 사람 저장이 피드로 도착하면 기준 버전이 이미 올라가 있어, AI 의 저장이 그대로 받아들여져 남의 변경을 지운다.
- 결정: 채팅마다 `read_file` 시점의 서버 버전을 기억(`onRead` 훅을 workspace 도구에 추가)하고, `save_script` 때 그 스크립트의 지금 기준 버전이 다르면 **저장하지 않고** 도구 오류 "conflict … 최신을 read_file 로 다시 읽고 다시 저장"을 돌려준다. 피드가 늦어 서버가 409 를 주면 같은 문구 + 서버 최신을 작업 사본에 받는다(AI 텍스트는 버림). 두 경우 모두 사람에게 `ai-conflict` 알림 배너.
- `ChatContext.writeScript` 는 Promise 를 허용하고, 실패는 `ToolError` 로 바뀌어 AI 가 읽는다.

### 6. 변경 받기 — 연 프로젝트 1개만 SSE

- 프로젝트를 열면 `GET …/events?lastEventId=<state.lastSeq>`(처음이면 위치 없이) — `ready` 인데 `lastSeq` 가 없으면 또는 `resync` 이면 전체 다시 받기(스냅샷 + 스크립트 목록, 해시가 같으면 건너뜀, 서버에서 사라진 것은 지움, **대기분이 있는 스크립트는 내 원문 유지 + `remoteNewer` 표시**). 그 밖에는 `change` 를 순서대로 반영.
- 스크립트 이벤트: `version <= 기준 버전`이면 무시(내 저장의 메아리), 대기분이 있으면 손대지 않고 "다른 사람이 저장함(보내기 대기 중)" 표시, 아니면 GET → 해시가 다르면 쓰기(자기 쓰기 표시라 감시자가 바깥 변경으로 보내지 않음) → 다른 사람이면 알림. 이름 변경·삭제도 반영. `project.*·environment.*·credential.*·suite.*·member.*` → 스냅샷 다시 읽기(역할 변경 포함). **`run.*` 은 C3 자리 — 지금은 반영할 것이 없어 무시.**
- 작업마다 프로젝트별 직렬 체인 하나에서 돈다(피드 반영·보내기·충돌 해결이 섞이지 않음).
- 다른 프로젝트는 열 때 마지막 순번 이후를 받는다. 대기분은 재연결 시 **모든** 클라우드 프로젝트에서 보낸다.

### 7. 연결·로그인

- 상태: `none`(서버 없음) · `signed_out` · `online` · `offline`(재시도 중, 1초 → 최대 5초 간격으로 `GET /api/me`) · `login_required`(401). 시작 시 토큰이 있으면 `offline` 으로 두고 바로 확인. 서버 요청이 네트워크 오류면 어디서든 오프라인 전환 + SSE 중단, 재연결 시 대기분 전송 + SSE 재개.
- 장치 로그인: 코드 요청 → `verification_uri_complete` 를 시스템 브라우저로(http(s) 만, E2E 에서는 열지 않고 기록) → 화면에 사용자 코드 표시 → 서버 `interval`(최소 1초)로 폴링, `slow_down` 이면 +5초, 만료·거절은 메시지. 토큰을 받으면 `/api/me` 로 계정 확인 후 암호문 저장.
- 로그아웃: 서버 sign-out(최선) → 토큰 삭제. 작업 사본은 남고 열면 "로그인 필요" 화면. 대기분이 있으면 렌더러가 확인을 받는다. 작업 사본 지우기는 대기분이 있으면 막는다.
- 오프라인에서 읽기만: 환경·테스트 계정(클라우드)·스위트·구성원·프로젝트 설정(서버 필드) — 모든 서버 호출이 `call()` 한 곳에서 "오프라인 — 읽기만" 오류. 화면은 입력을 비활성화.

### 8. 이 PC 실행과 테스트 계정

- 클라우드 프로젝트의 이 PC 값 = 기존 vault(키 = 클라우드 id 기준 앱 id). 실행 조립은 로컬 프로젝트와 같은 코드.
- 화면: 이름 목록 = 클라우드 이름 ∪ 이 PC 이름, 이름마다 "클라우드: 등록됨/없음 · 이 PC: 등록됨/없음". 입력은 체크 두 개("이 PC" 기본 켬, "클라우드에도" 기본 끔·편집자 이상·온라인). 클라우드 값은 메인을 거쳐 서버 PUT 으로만 가고 어디에도 저장하지 않는다. 클라우드 프로젝트는 외부 secrets 파일을 지원하지 않는다(vault 만).

### 9. 로컬 프로젝트 올리기

- 순서: 프로젝트 만들기(이름·설명 500자·브라우저) → 환경(주소 없는 환경은 서버가 받지 않아 건너뛰고 알림, 기본 환경 유지) → 스크립트(현재 내용, `app`; **검증 오류인 스크립트는 버리지 않고 `external` 출처로 보관** — 서버가 "검증 오류" 로 표시) → 스위트(경로 → 받은 스크립트 id) → 작업 사본 등록 → `chats/`·`recordings/` 복사 → **이 PC 의 vault 값을 새 클라우드 키로 복사**(이 PC 안에서만, 같은 사람이 같은 PC 에서 바로 실행할 수 있게) → 로컬 프로젝트에 `uploadedTo` 표시. 결과 화면에 클라우드에 입력할 테스트 계정 이름 안내.

### 10. 권한 표시

- 서버의 `myRole`·`can` 을 `state.json` 에 두고 화면에 쓴다(판정은 서버). 보기 역할 = 스크립트 만들기·가져오기·녹화·편집·실행·이름 변경·삭제·되돌리기·AI 요청 버튼 숨김, 상단 "보기 전용", `writeScript` 거부.
- 구성원 화면은 목록·역할 변경·내보내기. 초대는 이메일로 받되 서버에 일반 구성원용 사용자 검색이 없어 **관리자일 때만** `GET /api/admin/users` 로 찾는다(서버 공백, 아래 한계).

## 고려한 대안

| 대안 | 제외 이유 |
|---|---|
| 온라인이면 서버 먼저 저장(실패 시 파일 안 씀), 오프라인만 대기열 | 경로가 둘이 되고 "오프라인 대기분도 같은 규칙"과 충돌 처리가 갈림. 대기열 하나 + 결과 대기로 같은 효과 |
| 대기 항목마다 고정 기준 버전으로 전송 | 같은 스크립트를 오프라인에서 두 번 저장하면 두 번째가 항상 충돌. 앞 건 성공 버전을 이어받는 쪽이 맞음 |
| `EventSource` 폴리필 | Bearer 헤더 불가 또는 의존성 추가. 파서 70줄로 충분 |
| 모든 클라우드 프로젝트에 SSE 상시 연결 | 연결 수만 늘고 SPEC 은 "연 동안". 열 때 순번 이후 받기로 충분 |
| AI 충돌을 서버 409 에만 의존 | 피드가 먼저 오면 409 가 나지 않아 남의 변경이 지워짐(§5) |

## 결과

## 한계·후속

- **서버 공백 1** — 일반 구성원용 조직 사용자 검색 API 가 없다. 앱 초대는 관리자만 이메일로 가능(그 외는 웹 C4 또는 API). 서버에 `GET /api/users?q=`(활성 구성원 이름·이메일) 같은 경로가 필요.
- **서버 공백 2** — 웹의 장치 승인 화면(`/device`)이 아직 자리 페이지(C4)다. 실제 사용자는 브라우저에서 승인할 수 없다. 앱은 `verification_uri_complete` 를 열고 코드를 보여 주는 데까지 구현, E2E 는 API 로 승인.
- 서버에 "앱 AI 채팅" 출처가 없어 `ai_mcp` 로 보낸다(이력에 "AI").
- 이름 변경·삭제·되돌리기·삭제 복원은 온라인에서만(대기열에 넣지 않음). 앱 밖에서 지운 파일은 서버로 보내지 않는다(작업 로그에만).
- 외부 편집기가 피드로 이미 받은 남의 저장 위에 옛 내용을 덮어쓰면 그 바깥 변경이 이긴다(로컬 프로젝트의 바깥 변경과 같은 규칙). 앱 편집기·AI 는 §4·§5 로 막는다.
- 이력 목록의 요약은 메모·검증 상태만(버전마다 원문을 받지 않음). 비교 화면은 단계 문장 요약.
- 클라우드 작업 로그는 작업 로그 탭 아래에 최근 100건 목록만(필터 없음).
- 작업 사본 지우기는 이 PC 만. 서버 프로젝트 삭제·복원은 웹.
- C3 확장 지점: `ProjectSync.applyChange` 의 `run.*`, 작업 사본의 `cloud-runs/`(아직 만들지 않음), 예약 탭·실행 위치 선택·앱 알림(`/api/me/events`)은 미구현. → **C3 에서 구현(2026-10-21, [ADR-026](ADR_026_앱-클라우드-실행-위임-구현.md))**: `run.*`·`schedule.*` 는 `SyncHost.runEvent` 로, 초대는 `GET /api/users?q=` 우선(404 면 위 관리자 대체).
