# PLAN - euta cloud (클라우드 웹 실행 시스템)

> 상태: **계획 초안** (2026-10-20) — 방향 확정, 세부 결정은 아래 "열린 결정" 을 사용자와 정한 뒤 C0(설계)부터 시작한다.
> 상위 계획: [PLAN_end-user-테스트툴-종합계획](PLAN_end-user-테스트툴-종합계획.md) — 제품 형태 결정(로컬 앱 + 클라우드 웹 이원화)의 상세가 이 문서다.

## 배경

- 지금의 euta 는 **로컬 앱**이다. 시연 녹화 + AI 정리로 스크립트를 편하게 만들고 그 자리에서 실행한다.
- 로컬 앱은 **PC 가 켜져 있어야** 돈다. 정기 실행·야간 실행을 하려면 누군가 대신 돌려 줘야 한다.
- 프로젝트가 각자의 PC 안에 있어서 **구성원이 같은 현황을 볼 수 없다.**
- 로컬 앱은 AI 채팅(본인 구독) 정책 때문에 다른 사용자에게 배포할 수 없다. **AI 를 품지 않은 클라우드 웹은 그 제약 밖**이라 팀 공유가 가능하다.

## 목표

- **실행 위임** — 로컬 앱에서 "클라우드에서 실행 / 클라우드에 예약" 하면 PC 가 꺼져 있어도 클라우드가 대신 돌리고, 결과는 로컬 앱 History 에 그대로 보인다.
- **프로젝트 공유** — 프로젝트를 클라우드에 두면 구성원 모두가 같은 설정·스크립트·실행 현황을 본다.
- 실행 결과(단계 타임라인·스크린샷·체감 지표·리포트)와 회차별 **추이**를 웹에서도 보고, 실패하면 **알림**을 받는다.
- 구성원이 **자기 Claude**(본인 구독)에 euta cloud 를 MCP 로 붙여(개인 토큰) AI 로 스크립트를 보고·고치고·돌린다.

## 위치 — 무엇을 하는 시스템인가

- **철저히 사용자 관점의 실사용 테스트.** 대상 서비스에 사용자와 같은 길(공개 URL · 브라우저)로만 접근한다. 내부 API 호출·서비스 토큰·엔드포인트 테스트는 하지 않는다.
- 시스템 검증·운영 점검(API 계약·상태 전이 확인)과는 **별개 트랙**이다. 코드·드라이버를 공유하지 않는다.
- **특정 플랫폼에 속하지 않는 독립 시스템.** 첫 실사용 대상 서비스는 테스트 대상일 뿐 아키텍처·규약과는 무관하다.

## 두 형태의 역할

| | 로컬 앱 (euta-app) | 클라우드 (euta cloud) |
|---|---|---|
| 역할 | **만들기** — 시연 녹화 · AI 정리 · 폼 편집 · 디버그 실행 | **돌리기·공유** — 실행 위임(PC 꺼져도) · 예약 · 공유 프로젝트 정본 · 이력·추이 · 알림 |
| 프로젝트 | 로컬 전용 프로젝트의 정본 · 클라우드 공유 프로젝트의 작업 사본 | 클라우드 공유 프로젝트의 정본 |
| AI | 앱 AI 채팅 — 본인 구독 (본인 PC 한정) | 서버 안 AI 없음. 구성원이 자기 Claude 에 **원격 MCP**(개인 토큰)로 연결 |
| 사용자 | 개인 | 팀 (구성원·권한) |
| 실행 | headed/headless, OS 입력 가능 | headless 브라우저 입력만 |
| 공통 | **euta-engine** — DSL · 실행 · 측정 4종 · 결과 폴더 · 리포트 | 같은 엔진을 서버 러너로 사용 · 같은 MCP 도구 핸들러 |

### 실행 위임 흐름

```
[로컬 앱] "클라우드에서 실행" / "클라우드에 예약"
   │ (공유 프로젝트면 스크립트·환경·예약은 이미 클라우드에 있음)
   ▼
[euta cloud] PC 가 꺼져 있어도 정해진 시각에 실행 (headless) → 결과 보관(엔진 결과 폴더 그대로)
   │ 실패하면 즉시 알림
   ▼
[로컬 앱] 켜질 때 결과를 가져와 History·리포트·재생을 지금 화면 그대로 ("클라우드" 표시)
```

### 클라우드 공유 프로젝트의 데이터 배치

| 클라우드 (공유 정본) | 로컬에만 (개인) |
|---|---|
| 프로젝트 설정 · 환경(주소·변수) · 구성원·권한 | 앱 AI 채팅 기록(본인 구독 대화) |
| 테스트 계정(입력만, 구성원도 값은 못 봄) | 시연 녹화 원본(정리된 스크립트만 올림) |
| 스크립트 + 변경 이력 · 스위트 · 예약 | 로컬 캐시(오프라인 작업용) |
| 실행 이력 — 클라우드 실행(자동) + 사용자가 올린 로컬 실행 · 작업 로그(행위자 = 구성원) | 올리지 않은 로컬 실행 |

## 범위

| 구분 | 내용 |
|---|---|
| 포함 (1차) | 실행 위임 · 예약 · 클라우드 공유 프로젝트(구성원·권한·동기화) · 실행 이력·리포트·추이 · 실패 알림 · 웹 보기·폼 편집(AI 없음) · 원격 MCP(개인 토큰, 사내망) |
| 후보 (2차) | 웹 안 AI 채팅(구성원 본인 API 키) · 로컬 앱 없는 녹화 경로 |
| 제외 | 서버가 구독 로그인을 받아 쓰는 AI(정책 금지) · 클라우드 `input: os` · 클라우드 시연 녹화 · 외부 고객용 SaaS(가입·과금·다중 조직) · 실시간 공동 편집 · 부하/성능 시험 |
| 첫 대상 | 첫 실사용 대상 서비스의 사용자 여정 |

|---|---|---|
| AI 로 작성하는 경로가 제한됨 | 앱 AI 채팅은 로컬 앱 보유자만(배포 금지) | 웹 폼 편집(AI 없음) + 원격 MCP(개인 토큰)로 구성원 누구나 본인 Claude 로 작성·수정. 녹화는 여전히 로컬 앱 보유자만 |
| 동기화 충돌·오프라인 | 같은 스크립트를 여럿이 고치면 덮어쓰기 위험 | 서버 버전 기준 충돌 검사(#3), 실시간 공동 편집은 범위 밖 |
| Linux 컨테이너와 macOS 의 렌더링 차이(폰트·안티앨리어싱) | 로컬 기준 이미지로 시각 비교 시 전부 실패 | 시각 비교 기준 이미지를 실행 위치별로 따로 두고, 클라우드 첫 실행에서 기준 생성 |
| headless 브라우저 봇 탐지 | 대상 서비스가 클라우드 실행을 차단 | 대상별 확인. 클라우드에선 OS 입력 전환 불가 — 막히는 대상은 위임 불가로 표시 |
| 회사망·VPN 안에서만 열리는 대상 | 로컬에선 되는데 클라우드에선 접속 불가 | 맡기기 전 검사로 알림. 위임 대상은 공개 URL 로 한정 |
| 실사용 부작용(데이터 생성·과금·외부 게시) | 대상 서비스 오염·비용 | 열린 결정 #9 테스트 규칙 · 전용 테스트 계정 |
| 테스트 계정 보관 | 클라우드 저장소 유출 시 계정 노출 | 암호화 저장 · 쓰기 전용 · 로그·리포트 마스킹 · 영상/trace 는 민감 계정이면 끔(ADR-006) |
| 자체 계정 운영 부담 | 비밀번호 보관·재설정·메일 발송을 직접 운영 | 검증된 인증 라이브러리 사용(구현 세부는 ADR), 비밀번호는 해시만 저장. 정식화 시 Entra 로 전환해 계정 관리를 사내 IdP 에 넘김 |
| 개인 토큰 유출 | 토큰을 가진 사람이 그 계정 권한으로 접근 | 해시만 보관 · 만료 필수 · 폐기 · 마지막 사용 시각 표시 · 사내망 전용 · 계정 비활성화 시 모든 토큰 무효 · 접두사(`euta_`)로 유출 탐지 쉽게 |
| 러너 위치에 따른 체감 지표 편차 | 실제 사용자 체감과 다를 수 있음 | 리포트에 실행 위치 기록, 추이는 같은 위치끼리만 비교 |
| 브라우저 동시 실행 자원(메모리) | 예약이 몰리면 지연·실패 | 러너당 상한 · 대기열 · 러너 수 증설 |
| 수 시간짜리 실행 | 러너 자리를 오래 차지 · 배포 시 끊김 · 대상 서비스 로그인 세션 만료 | 상한은 메모리 기준 설정값 · 배포 시 끝날 때까지 대기 · 세션 만료는 스크립트에서 다룸 · 예약 간격보다 긴 실행은 화면 경고 |
