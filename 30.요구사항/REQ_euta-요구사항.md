# REQ - euta 요구사항

> **사용자가 요구한 것의 목록.** 요구마다 언제 나왔고, 어느 결정·문서·단계로 반영됐고, 지금 어디까지 왔는지를 적는다. 결정의 이유·제외한 대안은 [PLAN 결정 사항](../20.프로젝트관리/PLAN_end-user-테스트툴-종합계획.md#결정-사항) · [PLAN_euta-cloud 결정 사항](../20.프로젝트관리/PLAN_euta-cloud.md#결정-사항)이 정본이다. 여기는 다시 쓰지 않는다.
> 원문은 남기지 않고 요지만 적는다. 일자는 요구가 나온 대화 날짜다.

상태 표기 — **구현** 구현·자동 검증 완료 · **계획** 계획에 반영, 구현 전 · **⏸** 뒤로 미룸 · **❓** 아직 정할 것 · **⚠️** 요구와 현재 구현 사이의 차이·미검증

## 아직 정할 것

요구에서 나왔지만 값이 정해지지 않은 항목이다. 결정 상태는 각 정본에서 관리한다.

- ❓ **정량 목표·성공 기준** — 대상 서비스 수, 스크립트 작성 시간 등. [PLAN 목표](../20.프로젝트관리/PLAN_end-user-테스트툴-종합계획.md#목표) `미결`.
- ❓ **AI 가 `${secrets.*}` 를 외부 URL 로 보내는 경로** — 실제 SaaS 대상 실행(R04 · R27) 전에 대책이 필요하다. [PLAN 리스크](../20.프로젝트관리/PLAN_end-user-테스트툴-종합계획.md#리스크).
- ❓ **euta cloud 열린 결정 10건** — [PLAN_euta-cloud 열린 결정](../20.프로젝트관리/PLAN_euta-cloud.md#열린-결정-c0-전에-정한다).
